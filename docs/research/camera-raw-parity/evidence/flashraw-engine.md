# RAWMaster 的 RAW 图像引擎

新建 RAW 作品时，应用先验证实际文件能否由 FlashRaw 0.3.1 读取。检查内容包括文件方向、按方向旋转后的宽高、Metal 设备和一个真实传感器区域的 16 位浮点解码。通过后，版本化解码标识写入作品配方。应用重新打开作品、撤销、重做、复位和导出时会读取同一标识。历史配方沿用其既有系统解码器，未通过准入的文件使用系统 RAW 路径。已指定 FlashRaw 的作品在对应库不可用时会返回可诊断的错误。

## 从文件到画布

| 环节 | 实现 |
| --- | --- |
| 解码 | 由固定版本的 Rust `flashraw-capi` 读取传感器数据并请求 GPU 双线性去马赛克。容器分析和熵解码的具体执行端取决于格式。 |
| 原生输入 | C ABI 返回相机平衡下的线性 sRGB 三通道 F16，应用将其上传到 Metal。全尺寸输入使用 GPU 私有的 RGBA16F 纹理，整数坐标变换处理全部 8 种 EXIF 方向。纹理只读并由租约管理。同一作品的并发冷启动共享一次填充，关闭或收到内存压力时回收。 |
| 交互 | Metal 生成最长边 2400 像素的线性 RGBA32F 代理。白平衡、曝光、降噪和颜色等操作复用缓存的线性图像，避免每次拖动重复解码。效果颗粒按原图坐标采样，裁切和旋转位于其后。 |
| 定稿与导出 | Core Image 在 Metal 上组织 full-resolution 调整。FlashRaw 配方的预览、缩略图和导出从相同的线性底图及源调整出发。只在检测过的同一不可变图像对象上复用有限值检查。 |
| 引擎接口 | `RAWMasterImaging.ImageEngines` 提供编辑、浏览、分析、资源统计和成片导出的接口。设置页、性能监控和退出程序观察同一个预览服务。每个编辑控制器各自持有显影和导出实例，每次批量导出也独立创建实例。引擎可在 XCTest 中无界面运行。 |

Release 下的 31 项接口与生命周期测试全部通过，覆盖浏览并发、取消、缩略图最后一个引用的释放、离线成片导出、批量导出和退出时的资源统计顺序。[逐项测试、可执行文件摘要及耗时](engine-composition.json)

固定 Rust 提交为 `2994e8c550bec70ab78a938ab28a74d7762124f4`。打包脚本使用 Cargo 锁文件并随应用分发动态库和许可证。当前 ABI 在输出端提供主机可读像素，上传和原生纹理分配均计入引擎观测范围。[FlashRaw C ABI 与统计实现](https://github.com/ybouane/flashraw/blob/2994e8c550bec70ab78a938ab28a74d7762124f4/crates/flashraw-capi/src/frame.rs)

## 性能记录

应用菜单「诊断 → 图像性能监控」显示调度器的等待数、工作线程报告的运行数、完成时长和 MP/s。可以暂停采样显示、清空历史或导出 JSON。运行中任务在清空后继续计数。图构建、Graph + 校验、GPU 完成、API 返回和 AppKit 画布绘制分别计时。画布绘制返回的时间位于 WindowServer 扫描出屏之前。

白盒复核可以在启动进程时设置 `RAWMASTER_INTERACTIVE_TIMING=1`，日志会给出输入查找、预算预留、引导图命中或填充、算子提交以及屏幕缓冲区生成时间。在同一二进制中，将 `RAWMASTER_PROXY_LIGHT_GUIDE_CACHE`、`RAWMASTER_PROXY_DETAIL_GUIDES`、`RAWMASTER_PROXY_JOIN_POST_CROP` 或 `RAWMASTER_PROXY_KEEP_SHARPEN_CONTEXT` 分别设为 `0`，即可单独关闭对应优化进行对照。批量发版流程会读取实拍文件并记录测试包摘要。[发版性能脚本](../../../../scripts/test-image-performance.sh)

每次 FlashRaw 解码附带原生 ABI 的实际解码后端、后处理后端、线程数、输入输出字节数及分阶段耗时。原生总时长含容器解析。部分阶段的计时范围重叠，整次耗时取自原生墙钟。诊断 JSON 完整保留 11 个阶段，包括本次未产生用时的阶段。

同一张 9504 × 6336 像素 Sony ARW 上，三次独立、交错的 Release 对照测得，定稿预览的中位数由 473 降至 242 ms，局部纹理与清晰度由 3619 降至 1892 ms，局部细节由 1705 降至 1054 ms。两个局部定稿效果的所有像素字节一致，中性定稿的最大通道差为 1/255。[逐轮耗时、缓存及像素校验](engine-optimization.json)

整图交互预览从已完成写入的浮点纹理直接检查所有像素。检查和显示转换可以同时进行。两者均完成后才返回图像。六项操作各取得每个方案 40 个热样本，曝光中位数从 13.14 降至 7.32 ms，亮度降噪从 15.83 降至 8.83 ms。中性与曝光加颜色两种配方的预览和定稿输出逐字节相同。[并行校验对照及原始时间](interactive-validation.json)

在 Sony ILCE-1M2、Sony ILCE-7RM5、DJI FC9313 和 Leica Q3 43 的六份 RAW 上验证了实际解码、横竖尺寸、代理与定稿。两个竖向文件使用 EXIF 8。FlashRaw 为六份样本均报告 NEON 解码与 Metal 后处理。在 384 像素视图中，代理与定稿的 RGB 通道绝对误差第 99 百分位为 4–20/255。[文件摘要、尺寸、方向及逐阶段计时](flashraw-camera-matrix.json)

彩色颗粒的强度、大小和粗糙度均在处理后的图像上产生可重复差异。FlashRaw 作品的亮度和颜色降噪在同一线性源上运行，更改细节保留量也无需重新去马赛克。三个降噪滑块的真实交互中位数从 344–673 ms 降至 12–14 ms，随后整图并行验证进一步缩短部分操作。[颜色、蒙版和降噪的首次修复样本](engine-control-fixes.json)

交互高光与阴影依赖同一张对数亮度高斯图。对于 FlashRaw 输入，编辑器按源文件、解码方式、图像网格、白平衡、曝光、降噪和模糊半径缓存 R32F 引导图。2400 × 1600 的引导图占 15.36 MB，计入已有的纹理预算。在 Sony ILCE-7RM5 实拍 ARW 上，两轮独立进程各输入 20 个新滑块值，高光的两次中位数为 4.83、5.08 ms，阴影为 4.62、5.25 ms。关闭缓存后，高光为 7.88、8.05 ms，阴影为 8.28、9.23 ms。两轮启用缓存的中位数和 p95 均达到同尺寸 LightFlow 的项目门限。两个控件各取三个强度，六帧完整 RGBA8 输出与关闭缓存时逐字节相同。[交替测试、LightFlow 对照和整帧 SHA-256](interactive-light-guide.json)

默认配置的正式测试包 `127a7d8a` 又进行了三轮跨进程复测。同一控件每种工作负载共 60 个样本，曝光、对比度等 8 项的中位数均在门限内。同时考核 p95 时，交替两态为 2/8，连续新值为 5/8。逐帧跟踪显示，高光与阴影的 40 个新值都命中了引导图，命中耗时中位数均约 0.065 ms，首次构建为 6.93 ms。三个进程的原始样本与计时跟踪分别保留。[共同读回的跨进程重复与白盒数据](interactive-readback-repeatability.json)

无裁切和旋转时，裁切后暗角现在将实际最终画布写入 F32 表面，再一次完成整图有限值检查及显示转换。十帧 2400 × 1600 对照全部保持单通道误差不超过 1/255、p99 为零，透明度逐像素相同。暗角中点、圆度和羽化的热中位数由约 8.1 ms 降至 5.5–5.6 ms，强度约由 5.2 降至 3.7 ms。早期稀疏网格未能分辨暗角高光的两态；完整图像可分辨这处变化。[同包 A/B、完整帧质量和开关](interactive-postcrop-performance.json)

单独调整纹理、清晰度或锐化时，引擎可以复用已验证输入上实际测得的局部亮度响应。纹理和清晰度使用两种尺度的同一加权对数亮度高斯滤波，锐化使用选定半径的亮度均值。12 张完整显示图与逐次重新滤波的输出逐字节相同。两轮热交互中，纹理和清晰度的中位数从 6.4–6.9 ms 降至 3.3–3.5 ms，锐化半径、细节和蒙版从约 9–10 ms 降至约 6.7–7.2 ms。此轮锐化仍高于 LightFlow 对照。定稿和导出的原有细节着色器源代码保留原字节。[强度、半径、逐帧像素及三种输入边界的验证](interactive-detail-performance.json)
