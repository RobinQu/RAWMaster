# RAWMaster 项目原则草案

状态：规划方向与主线已确认 / 规格细化中；版本：0.3；更新日期：2026-10-21。

这是未来 Constitution 的候选内容；2026-10-21 用户已确认相关产品边界及首版保留策略，尚未逐条批准全部原则或写入 `.specify/`。原则约束产品行为和后续技术选择；具体引擎、数据库和语言放在技术计划中决定。

## P01 原片完整性与可恢复操作

原片作为不可变输入。系统不在导入、分析、显影和同步中原地改写原片。相机卡格式化、原片物理删除及保留期清理与普通筛选分离；不得从模型建议直接推导这些操作。

“复制成功”须有目标完整副本及内容校验结果。“已同步”与“已有独立备份”分别显示。缓存清理只回收明确可再生成、可重取的内容；用户标记离线保留的唯一原片不能作为普通缓存释放。

验收关注：导入前后源文件 hash 不变；中断不造成半成品被登记为完整副本；误排除可撤销；恢复流程能取回经过验证的备份。

## P02 离线是完整工作模式

在已有完整本地原片和所需引擎的项目中，用户断网后可以继续选片、整理，以及该阶段已交付的编辑和导出。只缓存缩略图时，明确可做的操作和缺少的数据。

离线期间的人工决定持久保存，重连后不会因服务器旧状态而消失。每个里程碑按自身已交付能力验收离线模式，不把未来的完整显影能力当作首版已有功能。

## P03 拍摄用途与序列完整性优先

同一张照片可同时属于多个用途的组。保留拍摄顺序、源时间和校正信息；分组允许人工修正。连拍推荐不能直接用于延时或叠栈淘汰。

“独立照片入选”“某次序列处理的成员/权重”“长期原片保留”分别记录。序列中排除一帧时提示时间、曝光、焦点或覆盖缺口；不自动补帧或把缺口悄悄隐藏。

暗场、偏置场、平场、有意欠曝/过曝和长曝光等特殊输入不能因通用评分被误删。即使高级合成延期，序列身份与保护规则也从首版建立。

## P04 建议有证据，人工决定有稳定性

质量分析保存对象、方法/版本、输入版本、置信信息及可查看证据。评分与旗标属于用户；机器建议独立保存。没有足够数据时显示未知、低置信或技术错误，不给出确定坏片结论。

服务器新结果不得覆盖人工决定、强制重排当前审阅界面或让已确认保留项消失。建议阈值可按拍摄类型配置；先做可解释的技术质量和组内比较，再考虑审美模型。

首版默认建议与批量确认，不默认自动排除。2026-10-21 用户明确要求后续版本迭代自动化排除废片：该能力列为 F003 后续增量，按项目显式启用，并定义适用场景、可撤销范围和误排除预算。自动排除不覆盖人工已确认保留项，不直接物理删除原片。

## P05 资产身份独立于路径和存储位置

路径可变，逻辑资产及其来源关系稳定。内容 hash 用于校验与内容复用，逻辑资产 ID 用于组织和同步；两者不能混为一谈。

相同字节可共享底层内容，但保留不同导入来源、资料库归属、编辑版本和序列位置。RAW+JPEG、虚拟副本、派生输出和备份副本分别建模，不以相似画面代替字节一致性。

## P06 同步操作与文件，明确处理冲突

本地数据库由本机持有，通过受控接口同步业务变化和文件，不把运行中的数据库文件放入网络目录供多端共写。

对重复提交、断线重试和乱序到达给出明确结果；一项逻辑操作重复送达不产生重复资产或重复决定。离线并发编辑保留双方版本或显式冲突，不能仅依到达时间覆盖。不同字段的合并规则由正式规格列出。

## P07 分析与渲染结果可追溯

每个分析结果、编辑版本与序列任务记录输入内容、配方及处理依赖。输出关联原片、成员顺序、引擎/模型版本、profile 和色彩信息；依赖升级不静默改写既有版本。

Mac 与服务器结果一致性通过固定样本和容差验证，不默认不同硬件能逐像素一致。旧版输出是否能重现，应记录“可执行重现”与“仅留渲染档案”的区别。

## P08 前台响应与渐进完成

首批可用素材到达即显示，不等待整卡完成。当前查看、放大和比较优先于后台分析；复制、校验、解码、上传分别控制并发和资源，避免重复解码和内存失控。

扫描、暂存、复核、上传、备份是不同进度。性能指标须在注明硬件、RAW 模式、样本规模和缓存状态的基线上测量，不能仅报告平均值或暖缓存效果。

## P09 历史迁移如实保留语义与缺口

Lightroom 迁移分别报告文件完整性、组织关系、历史外观、可编辑性四个维度。未转换的编辑配方和依赖可以封存，但不能标成新引擎可编辑。

迁移使用一致副本，原库与原片保持只读；尽早盘点关联编辑数据、预览和虚拟副本。新引擎编辑创建新版本，旧作品不因打开而变色。具体版本和字段覆盖以实际样本验证为准。

## P10 本地与自托管边界清楚

核心导入、选片、索引和归档不依赖第三方云服务。外部云能力若以后引入，需单独说明上传内容和目的。客户端、服务器各自有明确的数据和任务责任；先用可维护的简单队列，再根据测量决定是否引入复杂调度。

远端访问需经过认证；日志不泄露凭据。首版已确认单用户多设备，团队权限与多租户留作后续明确特性。

## P11 规格驱动、按风险验证

每个交付行为能追溯到规格要求及验收场景；方案和任务不得擅自扩大特性范围。原片完整性、恢复、同步、迁移与序列保护安排集成和故障测试；视觉交互进行真实照片操作验收。

不把大量实现镜像式单元测试当作完成证据。检查清单的审阅通过、实现完成、验收通过分别记录。
