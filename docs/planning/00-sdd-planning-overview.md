## 1. 项目目标与本轮边界

为大量 RAW 拍摄建立连续工作流：导入时即可浏览和筛选，按连拍、延时、星空等用途组织素材；Mac 可独立离线工作，联网后与自托管服务器协同完成分析、归档和备份；逐步接入历史 Lightroom 库，最后补足显影和专业序列计算。

优先减少两类成本：每次数万张拍摄的人工审阅成本，以及跨设备、跨历史资料库查找和保管素材的成本。

最初的规划轮次只整理文档。当前用户已授权在项目目录实现 M1 客户端并读取/复制指定 RAW 样本；实现仍不涉及服务器部署、发布、提交或推送。原规划中的后续里程碑不因本次客户端实施而自动完成。

## 4. 在 RAWMaster 中采用 SDD 的方式

当前补充：001–003 已有实现与验收记录，004 A+B1 已交付、B2 保留未通过质量门的隔离诊断；005 规格、技术计划、数据设计与任务已获用户确认，当前进入 A。以下实施状态须区分 A 研发与 B/C 集成；不抹去此前完成工作。本轮未运行 Spec Kit 命令。

官方核心顺序为：项目原则 → 特性规格 → 技术计划 → 任务 → 实现 → 收敛检查。澄清、需求质量清单和跨文档一致性分析是可增加的质量环节。本项目因涉及原片保管、离线冲突与异构处理，建议每个正式特性都使用这些环节。

| 阶段 | RAWMaster 产物 | 本轮状态 |
|---|---|---|
| Constitution | 项目原则及变更规则 | 仅起草，见 01 |
| Specify | 用户故事、功能要求、实体、边界和可测量结果 | 001–004 有正式记录，005 为本轮已批准规格 |
| Clarify | 将关键歧义及用户答复写回规格 | 004 默认值/图标边界已确认；005 推荐堆叠体验和路径已确认 |
| Plan | 技术方案、研究记录、数据模型与必要接口契约 | 005 设计已批准，A 证据与检测研发开始 |
| Checklist | 规格是否清楚、完整、一致的审阅清单 | 005 规划审查与用户确认完成；实现验收单列 |
| Tasks | 按用户故事组织、有依赖顺序的实施任务 | 005 按 A → B → C 执行，质量门前不进 B/C |
| Analyze | 检查规格、计划、任务之间的覆盖与冲突 | 本轮仅人工文档一致性检查，未运行 Spec Kit 命令 |
| Implement / Converge | 实现、验证并补齐差距 | 001–004 交付与限制见 validation；005 A 研发中，质量与集成未完成 |

命令名称在官方资料中常写作 `/speckit.*`；Codex 等集成可能使用 `$speckit-*`。本包使用阶段名称描述流程，不假定工具已经安装或命令可调用。
