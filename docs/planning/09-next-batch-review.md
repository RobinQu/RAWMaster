日期：2026-10-23。状态：**用户已确认 A → B、默认跟随系统及图标系统边界，开始分阶段实现。** 以下保留方案评审记录；实际验收另行记录。

已确认的新要求：界面与图标均提供浅色、深色、跟随系统三档，由用户主动选择。“跟随系统”指 macOS 当前外观，包括系统自己的自动日夜切换；不增加 RAWMaster 独立时间表。用户已确认首次默认跟随系统、A → B 顺序及系统图标边界。

## 3. 用户会得到什么

### A：外观与素材可用性

“RAWMaster → 设置…（⌘,）→ 外观”提供三个互斥选项：**浅色 / 深色 / 跟随系统**，建议首次默认跟随系统；设置立即生效、自动保存，所有应用窗口与应用自有弹窗一致。系统文件选择器跟随应用外观的实际行为纳入验证，不以应用自绘模拟替代系统选择器。

浅色：中性浅灰图像画布、浅色面板、深色文字、C2 图标。深色：中性深灰画布、深色面板、浅色文字、C1 图标。图像本身的渲染、色彩与解码缓存不随主题改变。选中、保留、排除、星级和错误同时依靠图形/文字区分。换主题时保留焦点、所选、缩放、比较布局及任务进度，不重新载入整库。

外置盘离线时仍显示已缓存图片和原有决定，信息栏提供“查找原片…”；会话可提供“重新定位来源…”。选择新目录后先出核验报告，分为匹配、未找到、内容不同、歧义及无法读取。用户确认后仅提交通过核验的匹配，失败项保留原状态；不自动重新导入或复制原片。

### B：更少手工整理，更可靠地按组审阅

工具栏菜单增加“识别拍摄组…”，只处理当前项目/会话或显式选择的范围。用户主动启动；不默认导入时全库分析。第一版只提出**普通连拍 / 相似画面组候选**。基于时间和预览相似提出候选，解释依据；没有完整相似证据时标成“时间邻近候选”，不能称为确认连拍。

候选单独出现在“待确认分组”面板，不改变现有组。用户可查看成员、拆分、合并、纠正用途、忽略，确认后才进入普通组列表。确认与人工修改后的组默认锁定；重新分析只产出新候选，不改回用户结果。快捷键 P/X/U 等继续用于照片决定，不复用于接受分组。

延时、HDR、星空等用途本批提供人工类型与保护；不自动判断曝光覆盖、间隔缺帧或校准关系。不知道用途就保留未知。排除一张独立照片不等于移出其序列；本批增加的缺口提示只描述“用户移出了哪些成员”，不声称已验证序列技术完整性。

## 4. 图标手动切换的系统边界

| 位置 | 跟随系统 | 用户在应用中固定浅色 / 深色 |
|---|---|---|
| 应用界面、设置与关于窗口中的图标 | 与当前解析后的主题一致 | 与用户选择一致 |
| 应用运行时 Dock | 按 macOS 系统图标外观处理 | 拟用公开 AppKit 能力呈现对应 C2 / C1；需在本机验证与系统染色模式的交互 |
| Finder、Spotlight、应用退出后的图标 | 原生图标资源由系统选取 | 仍由 macOS 图标外观偏好决定；不承诺被应用内部设置覆盖 |

Apple 的 `NSApplication.applicationIconImage` 文档明确其用途是临时改变 Dock 图标；它不是 Finder 全局图标覆盖 API。当前 SDK 的 `NSApplication` 没有 UIKit 的 alternate icon 接口。上述系统位置边界需要用户确认，不能在编码后才告知。

不修改全局系统外观、不写 Finder 自定义图标、不重写已签名应用包，也不启用常驻后台进程。若用户要求退出后及所有系统位置也必须按应用独立设置变化，需要先单独验证平台可行性并重新确认范围。

## 5. 实施顺序与退出条件（待批准）

| 顺序 | 可验收交付 | 退出条件 |
|---|---|---|
| A1 | 三档主题和图标联动 | 设置持久、三档与系统变化矩阵通过；图像及浏览状态不变；双主题窗口验收 |

| B1 | 完整组编辑和保护 | 拆分/合并/改类型/排序/锁定均可恢复，冲突不覆盖后续人工操作 |

A 可先单独交付，B 随后验收。A/B 为用户已确认的实施顺序；实现与质量验收分别记录，分组建议仍受 SC04/SC05 样本门约束。各步不承诺未知日期或只凭高配机代表全部 M4。
