# RAWMaster Server 1.0 功能规划

2026-11-26 · **规划，未开始实现。** 本文是 Server 版本的总览与决策入口，详细功能、数据、协议和任务见 [040 规格](../../specs/040-server/spec.md)。资料库前三阶段仍以 [033](../../specs/033-library-lifecycle/spec.md) 为准；Server 的产品验收沿用 [033 Server 规格](../../specs/033-library-lifecycle/server.md)。

## 1. 为什么现在做

本地资料库已经能导入、初筛、精编、编辑、导出，也已经有操作收据、封存不可变、逐文件归档资格、内容身份、备份包、资源对象和作业表。缺少的不是另一套照片管理，而是**长期保管与跨设备连续性**：

- 哪些原片真的在服务器上，哪些只有目录记录；
- 服务器副本之外，是否有独立备份，能不能恢复；
- 笔记本空间不足时，冷照片能否代理浏览、按需取回；
- 两台设备离线修改后，决定是否会丢；
- 长任务能否交给服务器，断线后是否只登记一份结果。

Server 1.0 先回答前四个问题，远程计算作为 1.1。桌面客户端仍是完整离线主工作区；服务器不是打开应用的前置条件。

## 2. 一句话范围

> **Server 1.0 = 归档 + 独立备份 + 异机恢复 + 冷热数据 + 多设备同步。**
> 远程 AI／批处理在 1.1；100 TB／200 万文件容量验收另立专项。

## 3. 功能地图

| 能力 | 用户结果 | 关键边界 |
| --- | --- | --- |
| 连接与设备 | 一台 Mac 安全连接自托管服务器，可撤销设备 | TLS 指纹、一次性登记码、按设备令牌；默认局域网 |
| 资料库绑定 | 一个服务器保管多个库，客户端知道哪些已同步 | 不共享活动 SQLite；不改写 `libraryID` |
| 归档 | 每个有资格原件有明确状态：待传、服务器可用、待找回、缺失 | 只从封存会话有效纳入与显式恢复取资格；排除项零引用 |
| 独立备份 | 同代目录＋对象＋资源＋成片，可校验、可恢复 | 独立故障域；同池快照不算备份；逐对象校验 |
| 异机恢复 | 新机器恢复目录、关系、决定、编辑依赖和成片 | 先目录后对象；部分成功不标完整；新设备重新登记 |
| 冷热数据 | 冷片用代理浏览，需要时取回完整 RAW | 代理可重建、不冒充原件；取回断点＋哈希 |
| 离线固定／释放 | 按照片／组／项目固定；释放有明确检查表 | 未固定、服务器可回取、独立备份覆盖、无未同步编辑，缺一不可 |
| 多设备同步 | 离线操作排队，重连合并或显式保留冲突 | 字段级合并，不做通用 CRDT；组／配方保留分支 |
| 远程作业（1.1） | 冻结输入的作业可排队、查询、取消、重试 | 只开放已验证可移植引擎；缺能力禁用；结果只登记一次 |

## 4. 关键设计选择

1. **客户端离线优先。** 本地目录持续保存元数据、关系、决定和版本；服务器离线只影响归档、取回、同步和远程作业，不影响已有的本地工作。
2. **服务器保管内容，不接管客户端数据库。** 通过操作 ID、设备、基准修订和载荷版本交换业务变化；原件通过独立的断点内容传输。
3. **归档资格不扩张。** 服务端复核封存会话的逐文件处置；来源扫描、组关系、星级、备份扫描和远程作业都不能把最终排除项带入归档。
4. **主存、暂存、同池快照、独立备份分开显示。** 只有独立目标逐对象校验通过才算“独立备份已覆盖”。
5. **V1 先每库 SQLite。** 复用现有目录内核、归档视图、操作收据和备份包；单用户单节点写入量有限。并发或规模测量不足时再迁移 PostgreSQL，API 和业务身份不变。
6. **Rust 服务端单二进制。** 复用 `rawmaster-library`、`rawmaster-photo-export` 和可移植图像核；不强制 Kubernetes 或外部数据库。
7. **远程计算按能力开放。** Mac 专用 Metal 链路默认本地执行；服务端只运行已验证的 Linux 引擎、模型和许可组合。
8. **冲突可见，不静默覆盖。** 不同字段合并；同一人工决定保留双方来源；组顺序和配方保留分支；删除不触发物理删除。

## 5. 交付阶段

| 阶段 | 交付 | 发布门 |
| --- | --- | --- |
| S0 · 契约 | 身份、操作信封、归档资格、备份代次、作业描述、UI 状态 | 评审通过；无未决 P0 语义 |
| S1 · 连接与目录 | 服务端骨架、TLS、登记、设备、库绑定、操作日志 | 错误指纹／过期码／撤销设备被拒；离线不影响本地 |
| S2 · 归档与备份 | 计划、断点上传、对象校验、去重、独立备份、异机恢复 | 五文件样本精确；恢复逐对象哈希一致；排除项零引用 |
| S3 · 冷热与同步 | 代理、固定、取回、释放、outbox、冲突、双设备 | 冷片可切换；断网修改不丢；释放门槛正确 |
| S4 · 远程作业（1.1） | 能力、输入、队列、取消、重试、结果登记 | 断线重试单结果；缺能力禁用；旧结果不覆盖 |
| S5 · 容量与运维 | 百万级／100 TB 参照、监控、保留、升级、演练 | 容量报告与恢复演练通过；未测规模不标完成 |

**Server 1.0 = S1 + S2 + S3。** S2 是首个可发布增量；S4 不阻塞 1.0，但作业身份和输入描述从 S1 起兼容。

## 6. 用户可见入口

- **设置 → Server**：地址、证书指纹、登记码、设备名、资料库绑定、归档策略、备份目标、诊断。
- **资料库工具 → Server**：归档覆盖率、独立备份、冷热与固定、冲突、作业、恢复。
- **标题栏／状态区**：在线／离线、待上传、待同步、冲突、运行作业的简短状态。
- **照片／组／项目上下文**：查看归档状态、固定离线、取回原件、释放本地副本。
- **导入完成摘要**：本次纳入／排除／仅序列／失败、可归档数量与字节、开始归档。

现有可操作预演：[资料库工具 → Server](../ui/prototype/index.html#tools/server)。本轮不改原生界面；原生实现前按 [AGENTS](../../AGENTS.md) 更新同一工作台并走查连接、归档、备份、冷热、冲突、作业和恢复场景。

## 7. 验收主线

1. **五文件样本。** A.RAW 排除、A.JPG 纳入、B.RAW 仅序列、C.RAW 必要帧但排除、D.RAW 失败；归档与独立备份恰有 A.JPG、B.RAW；恢复 A.RAW 只增一份引用。
2. **断点与去重。** 大文件中断后续传；重复请求不产生第二个对象；哈希／长度不符不登记完整。
3. **独立备份门槛。** 主存完成但备份未验证时禁止释放；完成后释放成功；固定原件和引用盘不被释放。
4. **冷片取回。** 代理切完整 RAW，中断继续，最终哈希一致；离线时如实显示可用级别。
5. **双设备合并。** 不同字段合并；同一评分冲突保留双方；组顺序和配方保留分支。
6. **作业重连。** 断网、改组、重试原请求只产生一个绑定原输入的结果；旧结果不自动采用。
7. **异机恢复。** 主存损坏后用独立备份恢复到新机，逐对象核对原件、关系、决定、编辑依赖和成片。

## 8. 待决问题

| 编号 | 问题 | 当前建议 |
| --- | --- | --- |
| D-SRV-01 | 服务端目录引擎 | V1 每库 SQLite；测量后决定是否迁移 PostgreSQL |
| D-SRV-02 | 独立备份实现 | 产品契约固定；原生代次复制／restic／ZFS send 在 S2 选择 |
| D-SRV-03 | 代理规格 | 长边 2048／2560、sRGB JPEG；用真实冷片测后冻结 |
| D-SRV-04 | 认证 | TLS＋一次性登记码＋按设备令牌＋指纹；mTLS 可选 |
| D-SRV-05 | 冲突矩阵 | 按 040 规格第 6.6 节冻结，不做通用 CRDT |
| D-SRV-06 | 远程作业类型 | 只开放 Linux 已验证引擎；Mac 专用链路本地执行 |
| D-SRV-07 | 保留与回收 | V1 默认不自动删除；保留代次和期限需用户确认 |
| D-SRV-08 | 管理界面 | V1 配置文件＋CLI＋原生设置；Web 管理台后置 |
| D-SRV-09 | 静态加密 | V1 依赖磁盘／卷加密；应用层加密另立专项 |
| D-SRV-10 | 多服务器 | V1 先支持一个服务器多个库；多服务器连接与跨服务器统一检索后置 |
