## F001 渐进导入与可恢复接入

**目标与独立验收**：用户从存储卡或目录导入一批照片，在整批完成前看到首批可用预览；中断后继续，不丢失已记录状态。

**用户故事**：US1（P1）选择源、项目及原地接入/复制导入方式，立即开始浏览；US2（P1）拔盘或退出后继续导入；US3（P2）识别重复接入及 RAW+JPEG 关系；服务端直存接入放在 F006 联动增量。

**功能要求**：

- F001.R01：建立持久导入会话，记录源、接入方式、复制模式的目的地、项目、逐文件进度与失败原因；逐批扫描和显示。
- F001.R02：区分“源上可见”“复制中”“受管副本已校验”；临时文件不能被当作完整受管副本。
- F001.R03：源文件只读；记录内容校验与副本位置；同名文件不得静默覆盖。
- F001.R04：记录稳定资产 ID、来源、拍摄顺序、原始时间/时区不确定性、关联文件；重复字节可复用存储，来源归属不丢失。
- F001.R05：支持暂停、继续、取消未完成部分及容量不足后的恢复。已完成部分与未完成部分分别报告。
- F001.R06：允许手动标记组及用途；延时、叠栈等组在首次人工筛选前已有保护标记。
- F001.R07（2026-10-21 确认）：同时支持原地接入与复制导入，由用户选择；原地模式不新增副本，必须区分引用可用和受管副本已校验。
- F001.R08（原地接入契约）：源掉线后保留资产、决定与来源关系，重新定位后核验内容身份；外部内容变化不能仅依相同路径继承旧决定。

**验收场景**：

1. Given 一批可读 RAW，When 开始导入，Then 首批预览在全批复制完成前可见，且来源/副本状态准确。
2. Given 正在复制，When 拔盘后重新连接并继续，Then 已校验项不重复产生资产，未完成项继续或明确重试。
3. Given 不同目录含同名不同内容文件，When 同批导入，Then 两份内容保留且来源可追溯；相同内容重导入不丢失新归属。

**边界与成功标准**：源消失、磁盘满、权限不足、损坏与不支持的 RAW 都单列。源字节零改写；恢复后逻辑资产和完整副本无重复/丢失。首图时间按 03 的硬件基线测量。延期：相机联机拍摄、视频转码、自动格式化卡。

## F002 本地组选片工作台

**目标与独立验收**：即使没有 AI 和服务器，用户也能完成一批拍摄的比较、保留/排除、评分及恢复。

**用户故事**：US1（P1）用键盘逐组审阅并同步放大主体；US2（P1）批量决定并撤销；US3（P2）集中处理待复核项。分组起初可手动，自动分组由 F004 接入。

**功能要求**：

- F002.R01：提供照片组、待复核、全部素材视图；键盘操作、并排比较、同步缩放与导航。
- F002.R02：分别保存未决定/保留/排除、星级/旗标、序列成员决定及长期归档决定；后两项允许尚未决定。
- F002.R03：批量决定支持撤销；已排除项折叠且可恢复，首版不默认物理删除或到期清理。
- F002.R04：序列组中排除成员须显示该用途的缺口提示；不能把“非独立入选”自动转为“移出序列”。
- F002.R05：当前查看优先获取细节；明确标识内嵌预览、RAW 复核与原片不可用，不能把预览质量冒充最终质量。
- F002.R06：后台新建议不覆盖人工决定，不强制改变当前审阅位置；离线或重启后决定持久存在。
- F002.R07（2026-10-21 确认）：M1 先显示内嵌预览，放大时按需解码 RAW 原始分辨率细节供人工判断；显示数据来源和未就绪状态。此能力不等于 M2 自动锐度/曝光分析或完整显影。
- F002.R08（2026-10-21 确认）：支持将用户选择的精选原片复制到新目的地，源只读、输出内容校验；取消、缺片或失败可恢复并明确报告，不能静默覆盖不同内容。
- F002.R09（2026-10-21 确认）：支持导出选择清单，记录身份、决定、来源及输出结果，序列范围和扫描覆盖明确；具体格式与字段契约另定。

**验收场景**：

1. Given 本地原片和手动分组，When 断网审阅、批量排除并撤销，Then 决定准确恢复，原片保留，重新启动后状态一致。
2. Given 某帧不适合独立展示但参与叠栈，When 将独立入选设为排除，Then 叠栈成员关系不变。
3. Given 当前组已确认保留，When 后台分析回传低质量建议，Then 用户决定不变，可主动查看新证据。
4. Given 当前显示内嵌预览，When 用户放大，Then 优先读取该 RAW 细节，未完成时不把低清预览称为原始细节。
5. Given 选片完成，When 复制精选并导出清单后中断重试，Then 源不变、完整输出可校验、缺失及失败逐项可查，清单与决定对应。

**成功标准**：决定、撤销及重启恢复结果完全一致；人工审阅耗时相对自身基线比较。100% 细节等待需区分真实像素来源与缓存状态。延期：复杂调色、审美自动裁决、无确认删除。

## F003 RAW 技术复核、质量建议与后续自动排除

**目标与独立验收**：针对用户正在筛选的组，展示主体锐度和 RAW 曝光等证据，帮助决定，避免只靠小 JPEG 淘汰照片。

**用户故事**：US1（P1）复核疑似失焦/曝光异常的帧；US2（P1）查看组内比较理由及不确定性；US3（P2）将耗时分析交给服务器，结果仍可与本地决定协同；US4（后续版本）按用户启用的策略自动排除明确废片，并查看记录、批量撤销和恢复。US4 为 2026-10-21 用户明确要求，不进入 M1/M2 首次人工确认版本。

**功能要求**：

- F003.R01：将 EXIF/内嵌预览初筛与 RAW 复核分开，标识分析层级和数据来源。
- F003.R02：提供主体/用户指定区域的锐度比较、RAW 通道饱和及相关曝光统计；曝光异常结合拍摄用途，不能仅凭直方图暗亮淘汰。
- F003.R03：每项建议记录证据区域、比较对象、算法/模型版本、置信或适用性；无法判断可输出未知。
- F003.R04：预览相似用于分组建议；完全重复依据完整内容校验。二者使用不同结果类型。
- F003.R05：优先处理当前帧/组；本地可完成基础复核，服务器原片到达后可增强分析；旧输入结果不覆盖新输入。
- F003.R06：技术错误、不支持解码及校准帧等不能归入坏片；未分类序列采用保守规则，需人工确认组用途。
- F003.R07（后续自动排除）：用户可按项目启用、暂停自动排除，明确适用拍摄类型及规则；默认关闭，规则与阈值版本可追溯。
- F003.R08（后续自动排除）：仅对已支持且达到启用判据的技术失败项自动设置排除；未知、解码错误、用途未确定、受保护序列/校准帧及人工已确认保留项不自动处理；相似度不得单独触发排除。
- F003.R09（后续自动排除）：记录被处理资产、触发原因、证据、规则/模型版本及原决定；用户可逐项/批量撤销，重启或重连后记录与恢复结果一致；仅改变独立入选决定，不改变序列成员和原片保留。
- F003.R10（后续自动排除）：先运行只记建议的影子评估，再按拍摄类型验收误排除率、检出率、覆盖率和人工复核成本；启用前冻结阈值、评估样本和停止条件，未达标保留建议模式。自动排除不触发原片物理删除或到期清理。


**验收场景**：

1. Given JPEG 显示高光白块但 RAW 仍有余量，When 完成 RAW 复核，Then 初筛可被修正，证据及来源可见。
2. Given 包围曝光或暗场组，When 运行普通曝光检测，Then 不因有意偏暗/偏亮产生确定淘汰决定。
3. Given 某机型 RAW 无法解码，When 分析失败，Then 显示格式/技术问题，资产与人工决定不变。
4. Given 用户启用已通过验收的自动排除规则，When 处理符合规则的技术失败项，Then 独立入选转为可恢复的排除，记录原因和先前状态，原片及序列成员不变。
5. Given 人工确认保留项、用途未知帧或必要序列/校准帧，When 自动规则运行，Then 不自动排除；暂停策略后不再启动新的自动排除操作。
6. Given 一批已自动排除项，When 用户批量撤销并重启或重连，Then 原决定恢复且操作不被重复应用。


**成功标准**：按拍摄类型和机型报告有效分析覆盖率、未知比例、失焦建议精度及优秀片误排除指标，见 03；不以一个统一质量分替代证据。自动排除另验收已冻结的误排除预算、检出/覆盖指标与全部撤销场景，不用建议模式结果冒充自动处理结果。后续自动排除依赖 F002 的恢复、F003 的有效分析及 F004 的用途/序列保护；远端执行还依赖相应归档与同步契约。延期：通用审美评分、复杂全主体识别、自动物理删除。

## F004 拍摄组识别与序列保护增强

**目标与独立验收**：用户把混合拍摄拆成正确用途的组，识别缺口并纠正算法分组。

**用户故事**：US1（P1）识别普通连拍、延时、包围曝光并批量修正；US2（P1）检查排除影响；US3（P2）管理星空、星轨、全景和焦点堆栈，以及校准帧关系。

**功能要求**：

- F004.R01：结合拍摄时间、曝光周期及画面关系提出分组，给出未分类与不确定状态。
- F004.R02：支持拆分、合并、类型纠正、成员排序、组锁定；人工修改不被重新分析覆盖。
- F004.R03：允许同一资产参加不同用途的组；序列成员决定属于具体组/处理版本，不能由资产级旗标代替。
- F004.R04：针对延时检查间隔，针对 HDR 检查曝光覆盖，针对全景/焦点堆栈提示覆盖问题；只对已支持的规则给出判断，其他明确标成未评估。
- F004.R05：关联暗场、偏置场、平场等校准输入，保留原始顺序和用户纠正记录。

**验收场景**：

1. Given 一张卡混有连拍和延时，When 自动分组后用户纠正并锁定，Then 以后分析不擅自改回。
2. Given 完整包围曝光组，When 排除其中一档用于 HDR，Then 显示覆盖变化，保留其原片与原组关系。
3. Given 相机时钟回拨或多机位，When 排序依据不确定，Then 可查看原时间并手动纠正，不静默重排成确定时间线。

**成功标准**：人工组关系修改可完全恢复；已支持规则的构造缺口全部被报告；算法分组正确率与人工纠正耗时单独报告。延期：自动补帧、全自动复杂场景推断。

## F005 多资料库目录与统一检索

**目标与独立验收**：用户选择一个、多个或全部资料库检索，不需切换独立目录文件。

**用户故事**：US1（P1）按时间、机型、评分、关键词和项目跨库查图；US2（P1）原片离线时仍浏览已缓存范围；US3（P2）语义与相似搜索。

**功能要求**：

- F005.R01：资料库、项目、集合与存储位置分离；移动路径或增加副本不改变资产身份。
- F005.R02：跨库过滤、排序与集合管理，支持一原片多编辑版本及来源关系；缓存范围和全库查询范围明确。
- F005.R03：显示离线结果及原片位置，区分本机已索引和服务器全局结果；无法访问服务器时不能暗示已搜索全库。
- F005.R04：同一内容跨库出现时可汇总浏览，但不同来源组织和编辑版本不被去重删除。
- F005.R05：语义索引为可选增量，不阻塞基础目录和元数据检索。

**验收场景**：

1. Given 两个库含相同原片和不同编辑版本，When 全库查询，Then 可找到全部来源与版本，物理存储复用不影响关系。
2. Given 只有部分项目已缓存，When 断网搜索，Then 返回本地可搜结果并说明范围，不能将未缓存解释为不存在。

**成功标准**：精确过滤结果与基准清单一致；搬盘后资产 ID 和关系不变；检索延迟分冷/热缓存测量。延期：团队共享空间、复杂权限、网络实时协同编辑。

## F006 服务端归档与备份闭环

**目标与独立验收**：原片可从工作盘归档服务器，内容校验明确，并能从独立备份恢复。

**用户故事**：US1（P1）优先归档保留项与完整必要序列；US2（P1）上传中断后继续；US3（P1）区分服务器副本和独立备份并演练恢复。

**功能要求**：

- F006.R01：服务端暂存、完成校验、正式归档分别记录；支持断点传输、重复请求和校验失败重试。
- F006.R02：支持保留项、待复核项、排除项及序列不同策略；未决定项不得因导入结束自动删除。
- F006.R03：序列上传依据其处理输入，不能只上传独立精选帧；本地空间不足时支持分批和服务端暂存目的地。
- F006.R04：客户端可以查看各位置完整副本和独立备份状态；同一存储池快照不能冒充独立备份完成。
- F006.R05：归档后可回取验证；恢复流程包含元数据/关系与原片，定期完整性检查报告问题。
- F006.R06：远端接入有认证和传输保护；服务端仅接收已声明的项目操作，凭据不进入一般日志。

**验收场景**：

1. Given 大文件正在上传，When 断网后重试，Then 不产生额外逻辑资产或误报完成，最终内容校验一致。
2. Given 服务器已有但独立备份尚未完成，When 查看状态，Then 只能看到服务器副本完成。
3. Given 原服务器工作副本不可用，When 从独立备份恢复一项目，Then 文件、组关系与决定可核对恢复。

**成功标准**：校验错误不会被登记为完整副本；中断/重试无丢失；恢复抽样通过。备份目标、频率和覆盖范围待确认。延期：多站点主动复制、企业存储编排。

## F007 离线项目与多设备同步

**目标与独立验收**：用户把项目设为离线可用，断网修改后重连，两台设备的决定可合并或显式保留冲突。

**用户故事**：US1（P1）选择元数据/预览/完整原片离线级别；US2（P1）离线选片后同步；US3（P1）并发修改不静默丢失；US4（P2）迁移已具备输入的后台任务。

**功能要求**：

- F007.R01：显示所选离线级别的准备进度和实际可用能力；未下载完成不显示完整离线就绪。
- F007.R02：同步业务变化和内容副本，不共享活动数据库文件；变更可重试且去重。
- F007.R03：逐字段规定合并规则；评分/旗标同字段冲突可供选择，编辑配方保留分支，组成员冲突不得破坏序列。
- F007.R04：设备离线期间的删除/排除恢复规则、撤销与重放明确；文件删除不因普通同步冲突自动触发。
- F007.R05：离线固定内容不被缓存回收；释放本地受管原片前验证可回取副本，并尊重用户离线设定。
- F007.R06：任务在本地/服务器上执行取决于完整输入和依赖；取消、重试和过期结果有确定行为。

**验收场景**：

1. Given 完整离线项目，When 网络中断后继续选片并重启，Then 本地决定保留，重连后一次有效同步。
2. Given 两台离线设备修改同一评分和不同配方，When 重连，Then 可识别评分冲突并保留配方分支，双方操作可追踪。
3. Given 项目仍缺两份原片，When 用户查看离线就绪，Then 显示未完成及受限能力，不能显示完整就绪。

**成功标准**：故障矩阵中无静默丢操作；重复/乱序同步结果满足已定规则。延期：多人同时编辑、通用 CRDT 平台、复杂分布式调度。

## F008 Lightroom 历史库接入

**目标与独立验收**：逐库导入可核对的组织与版本关系，搜索历史作品并保留已编辑外观。

**用户故事**：US1（P1）从一致副本盘点和迁移常用元数据；US2（P1）保留虚拟副本、集合及历史预览；US3（P2）扩大到特殊关系、规则和可归档的私有信息。

**功能要求**：

- F008.R01：以副本接入，记录源 catalog、版本、原片与相关编辑数据的可用性；不升级或修改唯一原库。
- F008.R02：导入经过验证的字段、集合、堆栈和虚拟副本关系；不能仅依每张原片旁的 XMP 推断全部结构。
- F008.R03：把原始配方、封存依赖、Adobe 渲染外观和新系统可编辑配方分开；缺少渲染时明确提示。
- F008.R04：每个库输出数量与关系对账，列明成功、仅封存、不支持、缺失；重复迁移不会反复复制对象。
- F008.R05：智能集合保存规则和成员快照；不能等价执行的规则明确报告。首阶段采用单向接入。

**验收场景**：

1. Given 同一 RAW 有两个虚拟副本，When 接入，Then 原片内容可复用，两套编辑身份及各自历史外观分别保留。
2. Given 原片缺失、编辑依赖不全或未知字段，When 生成报告，Then 逐项列明，不能把“已导入元数据”概括为“迁移无损”。
3. Given 历史外观已保留，When 用户开始新引擎编辑，Then 新建编辑版本，历史显示不被替换。

**成功标准**：源库/原片零改写；数量、来源和已支持关系可逐项核对；未支持项目无静默丢弃。延期：Adobe 全参数原生执行、完整 History 转换、发布/书籍/打印布局、与 Lightroom 双向同步。

## F009 非破坏显影与一致导出

**目标与独立验收**：以选定且验证过的引擎创建可追溯编辑版本；在本地独立编辑，服务端可按同一依赖导出。

**用户故事**：US1（P1）在本地调整基础曝光、白平衡、色调并导出；US2（P1）保留多版本与依赖；US3（P2）在服务端批量生成一致输出；局部编辑与高级降噪另划增量。

**功能要求**：

- F009.R01：原片只读，配方单独保存；预览、缩放、色彩显示与导出有明确语义。
- F009.R02：配方绑定引擎、版本、profile、模型与色彩空间；升级不默默重算旧版本。
- F009.R03：交互更新有取消与渐进结果，旧请求结果不能覆盖当前配方；具体常驻处理边界由技术验证决定。
- F009.R04：输出关联输入和配方版本，错误可重试；支持明确的输出色彩/位深选项。
- F009.R05：跨端处理先验证同依赖可用性和容差；不能在两端悄悄换引擎后仍宣称外观一致。

**验收场景**：

1. Given 已保存版本，When 引擎升级，Then 旧版依赖和外观状态仍可识别；缺依赖时不伪装为原版重现。
2. Given 同一原片与配方及固定依赖，When Mac/服务器分别导出，Then 在预定色彩与像素容差内比较，差异被报告。

**成功标准**：真实机型画质样本审阅通过；交互延迟、内存与跨端容差有测量记录。延期：完整 Adobe 参数/蒙版兼容、第一版即替代所有 Lightroom 编辑功能。

## F010 专业序列计算

**目标与独立验收**：对有明确用途和输入清单的序列执行可恢复、可追溯的专业处理。

**用户故事**：US1（P1，建议首先）延时关键帧、参数过渡、亮度分析和去闪烁；US2（P2）深空校准/配准/叠加；US3（P2）地景星空的天空/地面分别处理；具体先后由用户拍摄占比确认。

**功能要求**：

- F010.R01：冻结每次任务的成员、顺序、权重、校准输入、配方和版本；修改组后创建新任务版本。
- F010.R02：支持进度、取消、重试、断点/阶段恢复与失败输入定位；恢复边界按具体引擎验证。
- F010.R03：延时保留时间关系，明确缺帧和亮度异常；去闪烁不等于删除有意变化。
- F010.R04：深空、地景星空、星轨采用不同任务类型；天空配准不能直接代替地景合成。
- F010.R05：处理结果关联输入及参数；完整输入本地可用时可离线运行，服务端可承接长任务。

**验收场景**：

1. Given 昼夜延时，When 调整关键帧并去闪烁，Then 输出帧序和时间映射可核对，前后亮度可比较。
2. Given 长任务中断，When 从已支持的阶段恢复，Then 不重复覆盖正确结果，最终输出可追溯。
3. Given 地景星空序列，When 选择处理类型，Then 天空和地面处理边界明确，不把普通深空叠加描述为完整地景方案。

**成功标准**：每类专项样本独立验收；输入/输出/参数关系完整；恢复结果满足同任务的预定容差。延期：首版同时覆盖所有专业摄影门类。

## 共享领域概念与责任

这些是需要约定的业务实体，不是数据库表或 API 设计：

| 概念 | 作用 | 首次建立 |
|---|---|---|
| Library / Project / ImportSession | 组织范围、拍摄项目、接入过程 | 项目/会话 F001；完整资料库 F005 |
| Asset / Content / Replica | 逻辑身份、原始字节、各位置副本 | F001 |
| CaptureGroup / Membership | 拍摄用途、成员顺序及参与决定 | F001 最小标记；F002 操作；F004 增强 |
| UserDecision / AnalysisResult | 人工决定与机器证据 | F002 / F003 |
| EditVersion / RenderArtifact | 编辑分支、渲染档案 | F008 可先封存；F009 可执行配方 |
| Operation / Conflict | 离线变更与合并冲突 | F001/F002 留稳定身份；F007 正式协议 |
| Job / ProcessingRun | 资源、输入快照、执行结果 | 各特性最小任务；F010 专业处理 |
| ArchivePolicy / BackupRecord | 长期保留规则、独立备份证据 | F006 |

同一照片需分别记录：筛选决定、分析层级、各位置原片可用性、备份覆盖。序列参与和长期保留还是另外的决定。界面可按当前任务简化，底层不能合成一个含义不清的“完成”。

## 后续追踪约定

正式规格延续 `Fxxx.Rxx` 要求 ID，并分配独立故事与验收 ID；技术计划、实施任务和验证记录引用这些 ID。需求完整性审阅与实现测试分别记录。此包尚未将所有建议转为可执行任务，也没有测试结果。
