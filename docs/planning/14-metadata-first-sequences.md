# 元数据优先：拍摄事件与序列分组

2026-10-24。用户授权：只读审计原始 RAW，补齐 RAW/JPEG 拍摄事件关联，再完善连拍、间隔拍摄规则并回归。暂不引入预训练模型；保留人工标注、dev4 和空间 CV 实验基线；质量达标前不接自动导入。

## 起点与范围

当前 dev4 在 Sony 已标相邻边上 TP799、FP1、FN1、TN6，精确恢复五个已标组中的四个；A1M2 连拍四段恢复三段，A7R5 间隔拍摄一段完整恢复。DJI 双格式样本仍是 376 个文件，未恢复 373 条正相邻边。详细旧结果见[空间 CV 实验](13-spatial-cv-experiment.md)，本轮不覆盖这些结果。

现有 JPEG 代理没有保留 MakerNotes，原 ImageIO 读取也不等于完整厂商元数据审计。本轮固定读取已有六个清单的 1,265 个原始文件：889 个 Sony ARW、188 个 DJI DNG、188 个 DJI JPG，约 65.85 GiB。目录日期和文件修改时间不充当拍摄时间，不扩展到未列出的邻片或其他目录。

## 三层身份

- **文件**：每个原 assetID、ordinal、内容哈希保留，不去重、不隐藏、不删除。
- **拍摄事件**：只有经过验证的关联证据才把一次曝光的 RAW/JPEG 视作同一事件；缺证据、冲突或一对多时保持独立文件，并说明原因。
- **序列与选片组**：相机序列计数、模式和时间节奏描述物理拍摄过程；用户根据主体位置标出的边界描述选片意图。两种证据分别报告，原标签仍用于严格质量评价。

DJI 0188 的归属继续未知，不构造负边或完整终点。机型一致不能单独证明同一台机身；用户来源声明与可核验原生设备身份分开记录。

## 实施顺序

1. **只读审计。** 使用固定版本、仅研究用途的本地 ExifTool，提取明确字段白名单：原始拍摄时间与精度、曝光、设备候选标识、厂商拍摄模式及序列计数等。确认字段实际存在、可解码、是否冲突、在哪些机型/格式可用；不从字段名称推断语义。对全部原片做前后 SHA256 和文件属性校验，审计事实封存后再叠加人工标签诊断。
2. **事件关联。** 根据审计结果冻结关联规则；同秒、同名、同机型或相似图像都不单独作为同次曝光证明。每个文件恰属于一个事件，映射完整且不重排。已证同事件的重复时间可共用事件时钟，其他时间歧义和来源屏障继续保留。
3. **规则增量。** 依据实际可用的模式、计数变化及周期证据设计通用规则，先验证合成反例，再封存并运行全部已见样本。保留现有严格计量和完整组要求，不针对文件名、样本编号或标签写分支。
4. **回归与交接。** 对比 dev4 与新研究路径的文件/事件覆盖、误并、漏连、完整组和类型；分别记录物理序列证据与选片标签评价。默认配置、旧 fixtures、标签及 golden 保持不变，审计与新规则另有版本和身份。

## 实现边界

本轮在隔离工作区实现序列算法、离线工具及测试，不修改正在开发的导入初筛 Core、存储和应用界面。新的关联结果通过独立交接文档供后续适配，不能被视为已经接入资料库或自动导入。

厂商身份原值只在本地临时内存内处理，持久化使用私有本地密钥的 HMAC；不发布原始序列号、GPS 或完整 MakerNotes。审计没有写入元数据、转码或完整 RAW 显影操作。工具输出、运行时间、内存及取消均有界，失败报告不得冒充完整可用审计。

## 原片审计结果

固定 ExifTool 13.59（提交 `2200871d9cef988051d2a99d67df3bda6cbb30a8`），43 个数据字段及两项诊断字段。归一化版本 `qualified-parser-facts-v1.1`。第二次完整审计耗时约 136.55 秒，1,265 个原片全部通过前后 SHA256、文件属性及既有来源哈希校验；封存事实哈希为 `ba663312eec6cfd0aabfcc2837bd39e75fa45f64d4585c63a60c20c4497c3f17`。

| 事实 | 观察 |
| --- | --- |
| Sony 主序列字段 | 全部 889 个 ARW 都返回 `SequenceNumber`、`SequenceImageNumber`、`ReleaseMode`；文件计数与图像计数不能互换 |
| A1M2 连拍模式 | 438 行为连续拍摄模式，主序列计数与图像计数一致；计数在用户标注的同一组内也会重置 |
| A7R5 间隔拍摄 | 439 行均为主序列计数 0、图像计数 1、普通释放模式，仍可依时间节奏形成间隔序列 |
| Sony 时间 | 889 行都有三位亚秒和 `+08:00` 原片偏移；该偏移不同于既有 ImageIO/JPEG 观察，不回填旧数据 |
| DJI 身份 | 376 行的同字段设备/传感器候选标识一致；本轮白名单中的四个图像/捕获唯一 ID 字段均未返回可用值 |
| DJI 时间与设置 | 188 个秒级时间桶各有一份 DNG、一份 JPEG，曝光、ISO、光圈、焦距及曝光程序逐对一致；这些支持配对建议，不构成原生曝光唯一 ID |

原片审计也解释了规则限制：已标组内 DSC00411/DSC00412 相隔 0.451 秒、计数从 45 降至 1；已标组外 DSC00560/DSC00561 相隔 4.506 秒、计数从 11 降至 3。两处都仍为连续拍摄模式，因此不能直接用计数重置当作用户选片边界。实际规则和原人工标签需要分别计量。

首次审计在 DJI JPEG 的 `APP7:DJI:SensorID` 容器匹配处停止，保留为 `analysisReady:false` 的部分报告。修复仅增加已请求 SensorID 字段的 APP7 返回形式，没有扩大字段或样本范围；第二次重新校验整个批次。原始警告只做 HMAC 保留，本轮有 564 条 DJI 解析诊断，未在未审阅原文的情况下推断具体原因或宣布其无影响。

审计完整性与事实已独立复核。完整产物在忽略目录 `output/validation/008-original-metadata/audit-02/`；首次部分结果也保留。事件关联、规则增量和离线运行器已实现；30 项候选质量对照已完成，整体质量未通过，自动导入未启用。


## 已实现的研究路径

新增历史元数据补充集 `SequenceGroupingMetadata/v2`，完整绑定 1,265 个旧 JPEG 资产及其原片哈希。既有 v1 图像、时间观察、标注和 golden 不变。原片时间、设备候选与拍摄设置是独立证据；原片的时区偏移不会被填入 JPEG 的当前读取结果。

RAW/JPEG 关联先对完整相机作用域建立时间桶。只有桶中恰好两份相邻文件、一 RAW 一 JPEG、时间及精度相容、五项原始拍摄设置精确相等、至少一项共同设备候选且无冲突，才形成建议。缺少原生曝光唯一 ID，当前建议不会自动变成已确认配对。严格路径仅折叠调用方明确确认且绑定完整身份与版本的配对；实验路径可以显式假设建议成立，但此时只报告条件分组指标，顶层质量始终不通过，配对准确率留空。

连拍增量只在原有局部直方图门失败、其他局部指标和全局锚点仍满足时尝试救援。双方必须是主释放模式 2、主序列与图像计数一致；A 只接受计数严格递增 1，B 额外接受旧有 0.6 秒密集时间窗内的计数下降。计数跳增、相等、缺失、冲突不触发救援。暂停桥接与间隔规则保持原有约束，没有为单个样本增加阈值。救援统计表示局部门通过次数，后续全局锚点仍可能拒绝，不能把它直接解释为最终恢复的相邻边。

固定对照为 dev4、严格关联+A、严格关联+B、假设关联+A、假设关联+B，共六组素材 × 五种策略 = 30 个质量单元，另有六个配置准备进程。本轮不重复上轮 264 个性能单元；耗时和进程峰值只作这次执行的资源记录。

最新完整 release 回归通过 298 项测试，7 项按可选条件跳过，零失败；包含六组默认 golden、上轮 12 组空间 CV 原生结果哈希、完整补充集绑定及配对歧义、精度、版本过期、保护/读取失败等反例。工具回归 33 项通过，包含本地固定 ExifTool 对生成 TIFF 的真实调用；CI 未配置该本地工具时相应可选项跳过。

### 结论与后续

本轮授权的审计、事件关联、规则增量和实样对照已完成，**生产质量门仍未通过**。继续保留元数据优先路线和显式研究开关，不引入预训练模型，不启用空间 CV 强制复核，不接自动导入。
