# 导入初筛 → 项目精筛：工作流与下一轮范围

日期：2026-10-24。状态：用户已确认工作流并授权更新SDD和开始实现。正式范围、任务和实际验证见[006规格](../../specs/006-import-triage-workflow/spec.md)、[任务](../../specs/006-import-triage-workflow/tasks.md)和[验收](../../specs/006-import-triage-workflow/validation.md)；以下保留设计理由，不把批准当作已完成。

## 1. 本轮需求与现状

用户要求导入会话承担自动分组和低质量图片过滤；粗筛完成后关闭会话，仅留下常规项目，项目承接精筛（评分、标签）、图片处理和导出。上一轮要求的 JPEG+RAW 组合处理继续纳入。

当前 AppModel 的 project/session 都只是 AssetRecord 的范围过滤，共用 WorkbenchView 的决定、评分、比较和交付工具。ImportSession.status 表示文件任务状态，不能同时代表初筛是否完成。AssetRecord 要求 projectID，说明现有实现从登记起就归属项目；改变工作流必须增加明确的项目纳入边界，不能仅更改侧栏标题。

已完成主题、原片重新定位、人工组编辑、序列检测基础、六组 JPEG 回归数据及首次 GitHub 提交。005 空间 CV 实验正在另一对话执行；自动序列检测质量未通过，生产堆叠、历史重跑和导入整合仍未交付。这些不重复计为新增成果。本提案不改变另一对话的执行范围。

## 2. 两个工作区的职责

| 工作区 | 核心问题 | 主操作 | 完成后 |
|---|---|---|---|
| 导入会话（界面可称“导入与初筛”） | 本批哪些素材进入后续制作？序列和双格式关系是否正确？ | 接入核验、JPEG+RAW 关联、连拍/间隔堆叠、技术质量建议、批量通过/排除、异常复核 | 点击“完成初筛并纳入项目”，关闭日常工作区 |
| 常规项目 | 哪些作品值得使用，如何整理、处理和交付？ | 精筛、星级、基础标签、比较、已有/后续图片处理、交付 | 长期保留，可继续追加其他会话 |

初筛保留放大、RAW 复核和比较能力，但主操作不再以星级和导出为中心。项目显示可用的精筛和交付能力；完整显影仍属后续阶段，不能把新的项目工作区表述为已经交付显影引擎。

一个会话首版对应一个目标项目，可创建新项目或追加到已有项目；一个项目可累计多次会话。首版不增加一次会话分发到多个项目的分拣流程。

## 3. 用户路径

1. **接入素材。** 选择来源、原地引用/复制方式及目标项目意向。新项目名称可提前填写，正式常规项目在首次纳入时建立；已有项目不受未完成批次污染。
2. **边接入边初筛。** 首批可用素材立即浏览；复制/核验、双格式关联、序列检测和质量分析分别显示进度及覆盖。分组只发布完整、有效的结果，不因后台更新移动当前焦点。
3. **复核建议与异常。** 主视图为“全部 / 建议排除 / 人工排除 / 需复核 / 序列”。用户可批量应用受支持规则的建议、纠正关联及堆叠、恢复排除。需复核不等于坏片。
4. **完成初筛。** 展示进入项目的拍摄数/文件数、排除数、必要序列素材、文件异常及未分析范围。默认除明确排除外均纳入，不要求逐张按通过；有未决异常时明确选择保留待复核、重试或本批不纳入。不能静默遗漏。
5. **纳入项目并关闭。** 一次提交有效成员、双格式关系、组结构与来源记录，成功后跳转项目。会话从活动列表移入“导入历史”，项目继续精筛。后台排队不是已完成，不因最后一个文件复制完毕自动关闭。

这一步是逻辑纳入，不额外搬运或复制照片。原地引用仍依赖原盘，关闭不表示已归档或已备份。

## 4. 生命周期和一致性

会话业务阶段：接入中 → 初筛中 → 待完成 → 已关闭。暂停、取消、等待原盘、任务失败属于任务/阻塞状态，不能揉成单个业务阶段。文件任务结束只表示接入已结束，不表示用户已完成初筛。

完成前需要扫描范围封存，且纳入素材的接入结果可核对；正在更改输入/关系的任务须完成或安全停止。分析未达到质量门或用户主动跳过时，可明确选择人工初筛并记录未运行/未完成的部分，不伪报自动分析成功。

纳入与关闭在一个持久事务中完成；输入或人工关系版本过期则要求刷新摘要。重复点击、崩溃和重试不得重复建立项目成员，不得出现会话已关而成员丢失。全批排除允许关闭，报告零纳入，不强制创建空项目。

已经关闭的会话仍保存来源、清单、初筛决定、排除原因及分析版本。项目的“来源与导入历史”可查看和恢复未纳入素材；恢复只追加所选对象和必要关系，不重放旧批次覆盖项目新评分、标签或编辑。

实施细化：原身份恢复适用于已成功接入并有核验身份的文件。从未核验的接入失败项没有可验证的旧字节，完成摘要明确说明关闭后需新会话重新接入，旧来源/失败记录保留；不能在恢复时虚构旧内容身份。

项目里再次分析是显式维护动作，先看变化再应用，不自动重开原会话、不重置精筛结果。新来源追加始终建立新会话。

## 5. 三类决定分开

| 记录 | 含义 | 默认与边界 |
|---|---|---|
| 初筛处置 | 待审 / 通过 / 排除 | 未明确排除的正常素材默认可纳入；通过不等于精选，不自动赋星级或精筛保留旗标 |
| 项目精筛 | 未决定 / 入选 / 排除，另有星级与基础标签 | 新纳入默认未决定、无星级；用户已有人工元数据不清空 |
| 序列参与 | 是否用于某个序列任务及顺序 | 不由单张粗筛或精筛决定自动移除 |

人工已确认通过和必要序列/校准帧受保护。单张被排除但仍是必要序列输入时，显示冲突，允许以“仅序列用途”纳入项目；不自动破坏序列，也不暗中把它混入独立精选。规则未支持该用途时明确未评估。

## 6. JPEG+RAW 贯穿各阶段

领域关系：文件资产 → 同次拍摄的双格式组合 → 多次拍摄的连拍/间隔堆叠 → 项目成员。它们是不同关系；原文件身份、哈希和可用性分别保留。

- 接入时识别同目录/明确来源范围内的候选，结合文件名和可用拍摄元数据。仅同名或同秒不能证明配对；多候选、矛盾或跨目录情况进入人工确认。支持后到伴随文件及人工解除，保留纠正记忆。
- 初筛默认一张卡代表一次拍摄，显示 RAW+JPEG，可展开核对两个文件；同时报告拍摄数与文件数。快速预览优先相机 JPEG，显式切换 RAW 渲染/细节，回退时标明实际来源。
- 质量分析按来源记录证据。JPEG 过曝/模糊不直接证明 RAW 同样不可用；文件故障不等于整次拍摄低质量。整对排除须有适用证据或用户明确决定。
- 确认配对后，一次拍摄作为一个时序事件参与检测，两个文件均保留并映射结果。不再把 DNG/JPG 精确重复时间当作两次快门；未确认配对的重复时间仍保留歧义。
- 初筛纳入和组合卡上的项目精筛默认作用于组合，展开后的单文件例外必须明确显示实际范围。历史决定冲突先展示，不能用自动关联覆盖。
- 项目导出提供 RAW+JPEG、仅 RAW、仅 JPEG，复制原有文件；格式不存在时显示缺失，不暗中生成 JPEG、替换格式或误报完整。

现有回归代理图与真实相机 JPEG 的来源需要区分；不能因测试资源都编码为 JPEG 就错误重建文件配对。新增事件级标注与计量另起版本，保留逐文件旧基线及已知失败；同次拍摄及代理始终在同一数据划分内。

## 7. 低质量过滤提前进入下一轮

它由原计划的后续质量辅助提升为本轮初筛核心能力。首版包含：分析状态、可解释的疑似技术缺陷、组内/区域清晰度比较、疑似曝光异常、批量应用建议和持久恢复。

先以有预算的预览做候选筛查，在需要时对当前疑似项做 RAW 复核。没有 RAW 传感器统计证据时，不把普通渲染直方图称为 RAW 通道饱和；不承诺仅凭预览判定不可挽救曝光或主体失焦。

默认自动分析、人工批量确认排除；已达到独立验收的规则可提供用户显式开启的自动过滤，未达标保持建议模式。未知、低纹理、用途不明、损坏、不支持、离线等各有状态，不能统一作为废片。连拍相似不等于应淘汰，间隔/HDR/星空/校准素材不使用通用坏片规则自动删减。

为排除规则建立独立真值和影子评价，按类型报告好片误排、检出、覆盖、恢复及人工成本。现有序列标签与 1024px JPEG 集能支撑工程回归，但不足以直接证明 RAW 质量过滤有效。验收口径及支持范围在实施前冻结，不编造准确率。

旧资料库不能按文件任务 completed 推断用户已经粗筛。现有常规项目、决定、星级、组、文件身份全部保留；原会话默认收纳为“旧版导入记录，初筛状态未知”，仅真正未完成的接入任务继续显示待处理。需要重做初筛时由用户显式发起，并保护已有项目决定。

完整显影引擎、专业合成、服务器归档同步、自动清理/物理删除继续沿既有里程碑推进，不因本轮改造默认增加实现范围。

## 9. 待确认的产品选择

1. 会话是临时初筛工作区，完成后退入历史；一个会话纳入一个目标项目，允许多会话累计。
2. 明确排除之外默认纳入，项目初始无精筛决定；初筛不要求逐张打星。
3. 默认自动分析、批量确认排除；自动过滤仅对已验证且用户显式启用的规则执行。
4. JPEG+RAW 默认合并显示、整对初筛/精筛、优先 JPEG 快速预览，可查看单文件例外。
5. 按 WF01–07 组织下一轮，质量过滤不再整体延期；完整图片处理按原显影里程碑交付。
