# RAWMaster 界面设计与研发

[打开摄影工作台](prototype/index.html) · [按功能找原型与规格](coverage.md) · [单独打开导出面板](../../specs/032-export-workspace/prototype.html)

在仓库中双击 `docs/ui/prototype/index.html` 即可开始。默认打开「河谷拍摄」，包含 12 次拍摄和 14 个文件。点击照片聚焦，⌘/Ctrl 点选、⇧ 连选或使用「多选」。顶部的资料库、编辑和导出沿用同一组照片。浏览器会在本机保存示例数据，设置 → 通用 → 恢复初始样本可以重置工作台。导出预设由 Spec 032 的预设库管理。

如需分享同机走查地址，可在**仓库根目录**运行以下命令。页面、脚本和授权样片均从仓库加载。

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

打开 [本机摄影工作台](http://127.0.0.1:8765/docs/ui/prototype/index.html)。文件方式与 HTTP 方式各自保存示例状态。

## 一次 UI 变更怎样交付

| 阶段 | 在哪里做 | 完成时能回答的问题 |
| --- | --- | --- |
| 定义行为 | 对应特性的 `spec.md` 或 `ux.md` | 谁在什么范围执行什么动作？默认选中什么？成功、取消或出错后回到哪里？哪些状态属于照片、项目、版本或批次？ |
| 更新 HTML | 从覆盖表进入现有页面，复用相同选片、草稿、任务和交付组件 | 能否用正常入口做完一件事？新状态是否能和原有功能接续？长名称、多选、离线输入和空结果能否操作？ |
| 走查与决策 | 在特性目录记录入口、样片、动作和观察结果。布局与视觉改动附代表截图 | 主操作、键盘顺序、选择范围和错误恢复是否清楚？在哪个窗口宽度、哪种外观下走查？评审采纳了哪种方案，哪些问题仍开放？ |
| 原生实现与验收 | SwiftUI / AppKit、对应测试与特性验证记录 | 相同动作在应用中的版式、状态、可访问性和恢复行为是否符合原型？引擎、持久化、导出文件和性能分别有什么实测证据？ |

更新菜单文字、快捷键、按钮禁用条件、后台反馈或已有页面的布局，都从对应 HTML 入口开始。已有原型覆盖本次需求时直接引用并复验该场景。纯内部重构沿用现有回归。评审可以写在现有 spec 或 PR 中，给出原型路径、受影响范围、复现步骤和决定即可。若原生实现发现新的平台约束，先在原型与规格中记清最后采用的处理，并更新对应走查记录。

## 三项可复用的设计决定

- **位置表达作用域。** 顶栏切换资料库、编辑、导出。资料库底栏明确显示操作张数。编辑标题显示当前文件与草稿状态。导出把预设放在预览上方，目标目录放在提交按钮旁边，更换样式后目录仍可核对。
- **把照片放在判读中心。** 网格以照片、文件名、拍摄参数和审阅标记为主。需要时再展开搜索和筛选。暗房左栏垂直排列预设、快照和历史，胶片模拟在本张滤镜预览中试看。右栏沿左缘用图标切换面板，默认显示智能预设，「交互式创作」进入本张的 Agent 对话。翻片、缩放、裁切、对比和背景集中在画布底部浮动工具条。「Prompt」把原浮条展开为本张的单次编辑输入。[快速 Prompt 规格](../../specs/034-quick-prompt-editing/spec.md)颜色与文字或图标共同表达离线、选中、保留等状态。
- **区分预览、提交和采用。** 初筛封存前核对整批。筛选列表后仍能看到实际交付数。生成或保存版本后由摄影师明确采用。新建水印只修改弹窗内草案，应用后回到当前照片。范围、版本和原片可用性都随选片进入导出。

## 怎样验证

在仓库根目录执行浏览器走查。脚本使用 Python 3 和 `agent-browser`，启动独立会话与临时本机 HTTP 端口。浏览原型本身只需要浏览器。可用 `RAWMASTER_UI_CHROME` 指向本机已有的 Chrome/Chromium 可执行文件。

```sh
python3 scripts/check-ui-prototype.py
```

手工复查时，把窗口从桌面三栏收窄到信息栏变为抽屉。用 Tab 逐项到达操作，用 Escape 收起弹窗，在搜索框内输入 P/X 和数字。逐项核对选中状态、主操作可用性、空结果和返回位置。用设置切换主题，查看画布、选中描边、次要文字与键盘焦点。真实应用中的 VoiceOver、窗口菜单、RAW 像素、GPU 呈现与文件结果由对应原生验收覆盖。[操作场景与验证记录](coverage.md) · [编辑暗房专项走查](../../specs/025-editing-workspace/prototype-review.md)

## 文件归属

工作台由普通 HTML、CSS 和相对路径的经典脚本组成。共享照片身份、浏览范围、版本与决定在 `prototype/model.js`。样片映射在 `photos.js`，导出范围、版本交接和交付回执在 `delivery.js`。资料库、初筛/拍摄组、编辑、管理面板分别在 `library.js`、`sessions.js`、`editor.js`（暗房画布和浮动条见 `editor-canvas.js`，快速 Prompt 面板见 `quick-prompt.js` 和 `quick-prompt.css`）、`tools.js`。设置、任务与顶栏在 `app.js`。导出选片、版式、预设交换、预检及逐文件结果继续由 Spec 032 的原型维护。归档或分享完整工作台时一并包含该目录及仓库样片。[导出专项](../../specs/032-export-workspace/spec.md) · [样片说明](../fixtures/offline-regression.md)
