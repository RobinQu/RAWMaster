# 006 · 实施计划

2026-10-24，已授权。产品依据[工作流13](../../docs/planning/13-import-cull-project-workflow-review.md)。

1. 冻结状态/成员/配对/恢复合同，经独立代码审查后实现。增加独立工作流存储，复用既有SQLite事务、WAL备份、文件安全和图像管线。
2. 为兼容必填AssetRecord.projectID，新项目可用隐藏暂存目标；已有项目以纳入关系分离待初筛素材。UI常规范围和导出必须统一应用该边界，不能仅侧栏隐藏项目。
3. Core负责独立粗筛、配对、版本化完成摘要及原子关闭/历史恢复、标签与交付范围。新关系与既有CaptureGroup分开，旧JSON向后解码并保留业务字段。
4. App负责初筛/项目/历史导航、组合卡与操作范围、完成确认、异常处理、标签及格式交付。新文件任务使用初筛入口；旧底层导入接口可为旧调用保留兼容，但不可让应用默认绕过初筛。
5. Imaging新增独立有预算的预览风险分析，不修改Sequence*。ImageIO最多提取有限预览，不批量完整解码RAW；结果只做人工复核建议，取消和旧内容不能产生部分误应用。
6. 005检测与空间CV实验保持独立，应用明确显示未达质量门未启用。配对事件合同准备好后由005适配并另起评价版本；本轮不以改旧baseline关闭质量门。
7. 每阶段定向正确性/故障验证及源码复审，再进行普通测试、发布构建、签名/图标检查及隔离资料库窗口验证。除必要兼容断言外不重写现有测试含义。

代码所有权：Core worker维护Core/相关Core测试，App worker维护应用/相关UI测试，Quality worker只加独立Imaging风险分析及测试；root负责SDD/协调/集成，oracle只读审查。共享类型先冻结再消费，禁止两个worker同时编辑同一文件。

本轮不自动运行用户真实资料库迁移、不自动推送GitHub、不修改原片；交付应用构建和隔离验证，实际迁移在用户启动更新版本时按既有备份流程执行。
