# 034 · 快速 Prompt 实施方案

**目标平台** macOS 15+，Apple Silicon，SwiftUI／AppKit 暗房，Swift 编辑与归档服务，FlashRaw／Core Image／Metal。macOS 26+ 使用系统 Liquid Glass。交付以现有 027／031 成像构建为基础。[产品规格](spec.md) · [研发任务](tasks.md) · [技术证据](research.md) · [请求与归档契约](contracts/quick-prompt.md)

## P1 的纵向切片

| 边界 | 复用与增量 |
| --- | --- |
| 暗房状态 | 在 EditingImageCanvas 现有底栏上增加 Prompt 编辑状态。复用原浮条的位置、画布变换和可访问性材质策略。Prompt 会话保存前一个工具、对比、焦点和视口。将圈选走同一画布的点击／拖动路由。裁切、原片按住、颜色取样、局部画笔及 Prompt 只由当前激活工具接收事件 |
| 当前照片与已确认范围 | 使用 EditingInteractionContext、源内容身份、EditingDevelopmentSession 的当前草稿和原生裁切／几何。复用 027 的冻结蒙版材料。把作者坐标映射为当前已定向、已裁画幅的 top-left 规范像素，记录正逆变换、离散栅格、mask 摘要与采样版本 |
| 请求与任务 | 扩展现有 AIEditRequest／ProcessingJob，增加类型化的 Prompt 输入和版本化元数据，旧作业按原解码路径加载。重用提交意图、commandID、attemptID、runID、回执和 EditingArchive 的核验发布。工作台关注任务 ID，界面状态销毁不影响已经接受的作业 |
| 模型路由 | FLUX.3 Image Klein 接成一个固定的本地配置，优先验证既有 030 的 MLX Q8 与受管进程通路。验证兼容的本机 Prompt 扩写与量化。保留当前 LocalComfyProvider 的 Qwen 图入口，另接一个 Klein 适配，而后共用取消、回收、产物和回执。Seedream 5.5 扩展现有 CloudImageProvider 的单图路径并按版本校验能力，使用现有 Keychain 存储和固定北京端点 |
| 图像输入 | 提交前用同一源、色彩配置和几何生成已完成的 SDR 构图。用明确带 sRGB 的无元数据图像作为模型输入。冻结裁片的像素边界、实际 padding、缩放、可逆补边与编码字节摘要。模型输入是受限分辨率的渲染图，后续贴回只允许通过已登记的映射 |
| 图像输出 | P1 将结果作为独立 .ai 创作版本归档。局部生成在最终几何的同尺寸基底上做线性光合成，贴回后以 TIFF16 或等价的已验证高位深成片归档。保留 M=0 的原始样本，按 tile 流式写出。整张归档采用经验证的实际尺寸与所含色彩信息。兼容现有作品版本、采用和导出。该工作保留现有 029 修复算子的阶段顺序。跨 RAW 滑杆变化的可重算生成图层交给 029／030 的后续实现 |
| 应用 | 已生成候选绑定冻结的父版本／编辑修订。确认时以作品当前状态做比较更新，一次记录版本切换及撤销令牌。已有草稿可继续使用。当前成片若已成为创作版本，再发 Prompt 以该版本已归档产物为输入，并记为新子版本 |

## 从输入到归档

1. **采样。** 确认当前草稿、source binding 和 canonical 预览一致。记录原生尺寸、正反几何和色域。整张使用当前可见构图，矩形与复用蒙版都落到这个坐标空间。相交面积为零、来源或姿态失配、精度退化或超预算时显示原因。对以 mask 为源的范围，将投影、采样与羽化都固定在本机。当前源与版式变化要求重新确认范围。
2. **计算请求。** 局部用实际覆盖包围盒加可计算并可预览的上下文。为 1 MP 首轮实验统一预算，Seedream 显式尺寸须满足最新已验证能力表。不同模型输入比例有约束时对同一裁片按确定规则缩放、补边与裁回。记录完整映射及按各厂商能力选择的目标尺寸。宽高或方向返回不满足已冻结映射时，候选停在失败或待核对，用户可在任务详情定位原因。
3. **执行。** 预览、编辑提示词和试用模板只执行本机准备。仅云端明确确认后持久化提交意图并发送。实际尝试保留区分「排队、准备、提交、生成、整理」。本地进行取消并等待任务释放。云端传输断开后用原 Attempt 的核对入口，优先恢复已经收到的本机文件。能否查到远端结果由适配器能力决定。
4. **验证与贴回。** 校验候选数量、完整解码、方向、通道、色域、尺寸、alpha、预算与相应回执。没有可信 ICC 的这类候选按固定 sRGB 解释并打标。候选几何不一致时不能直接非等比拉伸。固定输入到原生画幅的映射后，以同一线性工作色彩空间计算 B + M × (C − B)。对 M=0 的导出像素走冻结基准的相同写出路径，以同参数下最终 TIFF16 码值验保护区。贴回后显示成片而非服务的全裁片。全图在采用前标出输出尺寸和潜在构图漂移。
5. **发布与恢复。** 兼容现有 staged write、校验和原子发布。工作条撤除期间只更新原任务与候选，当前窗口无换片。允许用户在来源版本下看候选并回到当前暗房。提交、失败、收起、过期与审阅均不修改 RAW 配方。重开、同步备份和导出读取归档及处理记录，无模型参与。透明、HDR 或超出已验证预算的源，首批从实测通过的 SDR 图域切入。

## 交付边界与放行

- **产品准入。** P1 的标准交互、单图输入、单图输出两边一致。垂直切片优先让 Seedream 的测试传输和本机模拟适配完成首个可走通构建，并行接通真实 Klein。生产资格按模型与范围登记。当地模型可用性以设备和许可验证为准，技术方案不承诺全量分发模型。所有模型可单独配置与解释不可用原因。
- **质量评测。** 预先冻结 24 张用例，局部与整张各 12 张。跨人像、风光、街拍，横竖、细字、发丝、边缘、强透视、裁切和 EXIF 定向覆盖。两边用同一意图、同一输入预算。分别记录短中文与模板展开、首图可接受、拒绝原因、局部误改与全图偏移。建议 Beta 线为每种模型、每范围至少 9/12 可用，经独立双人盲评后在 D0 确立。面部、文字、边缘失败的任务按实际经验关闭或标为需复核。
- **性能。** 单独测工具条和圈选到画布稳定、准备与编码、上传前后、推理、归档和首屏对照。大 RAW 进行前后台交错（交互时最终 AppKit p95、缓存变化、模型内存、模型取消 join）。030 PoC 是测量起点，新的固定生产构建、目标设备和测量边界决定上线读数。
- **工程界面。** 032 交付仍可导出已采用版本。027 蒙版范围先在同一张使用，031 用户配方与 XMP 路径不承载 Prompt 候选。为旧库提供可解码的增量版本。阶段与作用域验收独立于 031 SC-02 预设速度。
