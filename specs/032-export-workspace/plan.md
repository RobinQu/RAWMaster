# 032 · 导出研发与验收

2026-11-22。导出在独立检出开发和验收，基线为 `210af4c1`。资料库及编辑器的并行改动由各自会话集成。导出只通过有序照片 ID、显影快照、归档文件和已有应用入口接收输入。[产品规格](spec.md) · [样式研究](reframe-styles.md) · [容量依据](batch-limits.md)

## 实施顺序

1. 在 `Modules/PhotoExport` 完成独立 Rust crate。先用 `cargo test --locked` 验证批量约束、跨平台预设、画布坐标、实际 JPEG/PNG/TIFF 编码、ICC、透明度和文件发布。Server 可通过 Rust API 直接使用，桌面使用版本化 C ABI。
2. 将 SwiftUI 的正常交付入口接入 Rust。先接选片与预设，再接现有完整显影、题注预览和最终文件。对原件沿用可核验的逐字节复制与清单，新增工作台的准入用相同 200 张限制。工作台测试由标题栏、文件菜单和对话框进行，覆盖本机目录独立、样式卡、取消以及实际产物。
3. 在同一主机对齐 RAWMaster、AlcedoStudio、LightFlow 的实测条件。先测共同可处理的输入，再用真实输出文件校验尺寸、色彩和交付成功。性能门槛须同时检查首件和整批。

## Rust 与宿主的责任

| 责任 | Rust | SwiftUI / Server 宿主 |
| --- | --- | --- |
| 批量准入 | 判定唯一输入、超限与范围错误。1 至 200 个照片 ID，共用计数规则 | 冻结当前可见候选中的有序勾选项。缺失的照片保留其计划位置 |
| 预设 | v2 校验与规范表示，v1 迁移，Logo 校验。统一命名模板 | 管理个人预设、上次设置和各设备的目录权限 |
| 成片 | 画布与裁切几何、可移植栅格合成、8 位 JPEG / 16 位 PNG、TIFF、sRGB ICC、同目录排他发布 | 供应按版本显影、定向、裁切后的像素、已验证来源的 EXIF、文字栅格及 Logo。macOS 可用 Core Image 加速合成并把最终像素交给 Rust 编码 |
| 任务 | 检查文件名与计划、保护提交目标、冲突使用排他发布 | 负责资料库身份、原件校验、任务进度、错误与设备访问。原件服务按字节复制并生成报告 |

Server 宿主需要提供照片显影、字体排版和元数据读取。底层的输入是显影后的 sRGB 像素与明确的版式几何。交付设定、画布、编码和发布不依赖 AppKit、SwiftUI、图库数据库或 macOS。JPEG 透明区域合成白底，PNG/TIFF 保留直通 alpha。归档与原片的身份校验位于宿主，EXIF 白名单由桌面适配器在编码后以无损方式应用。

## 首版性能验收

- 首先选 JPEG 8 位、长边 2048 px、质量 90、sRGB ICC、净图、关闭描述性元数据。使用相同本地字节，分 1 张、20 张及适用的 200 张测试。单独记录 RAW 和 JPEG，不拿浏览器内部编码耗时与应用整批写盘比较。
- 每轮记录第一份可读取输出和整批可用的用时、实际成功数、每秒张数、文件总字节和能取得的 RSS。以单工具串行和新目的地反复运行，记录中位数、原始样本、硬件、构建及预热状态。分开说明浏览器 ZIP、应用沙箱、色彩默认值及进程统计口径。
- 首版目标为共同场景下整批中位耗时不超过两款参照中较快者的 1.25 倍，首件中位耗时不超过 1.5 倍。以端到端写盘为发布判据。不能等价执行的输入或格式单列，沿用可复现的成功项作回归基线。[性能基线](performance.md)

## 功能验收

| 场景 | 通过条件 |
| --- | --- |
| 199 / 200 / 201 张 | 199、200 可开始。201 保留勾选，执行与仅清单入口均在写盘前拒绝。筛选/滚动 1,200 候选时仍可按范围减选。CSV 和 JSON 各保留所需记录 |
| 文件同名、失败和取消 | 文件名带点号、Unicode 和序号时保持模板语义。目标文件被别的进程占用时按设置重命名或跳过。取消前已发布的文件可核验 |
| 预设 | 原件与成片参数、隐藏配置、Logo 和签名可来回。更换资料库和目标目录后，接收端继续使用自己的输入和目录。读取 v1，交流 v2 |
| 照片版本及题注 | 当前版本与历史归档按各自身份出图。不同照片的曝光、日期等来自对应源。缺字段则不绘制对应字符，去除文件 EXIF 不干预画面印字 |
| 图片合成与编码 | 8 位 JPEG sRGB、16 位 PNG 与 TIFF sRGB 实读，验证色彩描述、尺寸、alpha、无放大和大边长。水印工作室选图、取消、应用后从底栏写出 |
| 原件交付 | 复制原件逐字节相等。仅清单零图片。工作台 CSV 每张一行，整批 ID 保存在 JSON。旧 API 的默认 CSV 仍按现有契约输出 |

跨重启恢复、批次级持久化和多预设同时出图为后续阶段。
