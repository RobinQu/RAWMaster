# 图片交互性能验证 — 2026-10-22

环境：MacBook Pro / M4 Max、128 GB、macOS 27.0.1，发布配置。原片测试来源沿用用户授权目录；图像性能基准只读其中 15 张 Sony ILCE-1M2 ARW。原生窗口点击使用原资料库的独立 SQLite 备份，不改用户选片决定。

## 原因与修复

原网格叠加单击和双击的 SwiftUI 手势。5 次真实桌面改变选择的采样，在缩略图已加载时，NSEvent 按下 → 选中状态提交为 423–433 ms，提交 → NSView 更新仅 5–7 ms。系统双击时间窗为 500 ms；主要等待在手势识别阶段。原实现还在每次焦点变化后执行 150 ms 的居中滚动，增加点击后的移动感。

修复将卡片选择放到原生 mouseDown，同次调用提交；第二击打开单张。网格和胶片条共用输入处理器。手动点击保留视口，键盘导航单独请求显示当前照片。⌘/⇧ 多选、右键/Control-click、滚动和辅助功能操作都列入验证。

测试另发现保留同一个 URL 对象后，Foundation 的文件属性缓存可能使变更后的图片继续命中旧缓存。图像缓存键改用实时文件信息；此问题与单击等待分别记录，不归因为解码慢。

## 指标与门槛

| 指标 | 样本与计时边界 | 本机发布配置门槛 |
|---|---|---|
| 网格、胶片条选择 | 每表面至少 30 次，命中的原生接收器 → 焦点状态发布 | p95 ≤100 ms，最大 ≤150 ms |
| 选择的视图更新 | 同批事件 → NSViewRepresentable 更新 | p95 ≤150 ms，最大 ≤250 ms |
| 应用冷缓存预览 | 30 次请求 → 解码结果 | p95 ≤100 ms |
| 原始 RAW | 30 次请求 → 原始尺寸位图 | p95 ≤1500 ms |
| 预览 / RAW 缓存命中 | 100 / 50 次请求 → 缓存对象 | p95 ≤5 ms |
| 比较 2 / 3 / 4 张 | 各 3 次全部 RAW 返回，解码器串行 | p95 ≤每张 1500 ms；小样本冒烟指标 |
| 缩放、平移、1 / 2 / 4 画布 | 各 30 次状态更新 → 完成离屏位图绘制 | p95 ≤33.33 ms，最大 ≤100 ms |
| 快速切换取消 | 24 项取消压力批次 | 批次完成 ≤1000 ms；单批冒烟指标 |

除画布外，最大值门槛为 p95 门槛的 2.5 倍。所有阈值在修复前按基线和本机使用目标声明；不是对其他硬件的性能保证。

同机同系统、同一构建配置与样本的报告可继续比较。允许 p95 增长 50%，并留出抖动下限：输入状态 5 ms、输入视图 20 ms；冷预览 50 ms、RAW 1000 ms、缓存命中 1 ms、比较每张 750 ms、画布 8 ms、取消批次 100 ms。绝对门槛始终保留。

## 回归入口与证据

`swift test --jobs 4`：默认的正确性、资源限制和即时输入断言。发布前运行 `scripts/test-image-performance.sh --source RAW_DIRECTORY --output REPORT_DIRECTORY`。在可复现的后续运行中增加 `--baseline-dir PREVIOUS_REPORT_DIRECTORY`。报告保存原始样本、最近秩 p50/p95/max、配置、计时边界和失败记录；必需报告、样本或回调缺失即失败。

真实桌面还可使用 `--interaction-trace /absolute/path/trace.jsonl` 启动应用，操作后运行：

```sh
python3 scripts/analyze-interaction-trace.py /absolute/path/trace.jsonl --output output/native-summary.json
```

默认要求至少 30 次改变选择的完整原生事件记录。本次前后各 5 次真实输入是与自动化基准分开的复核，显式用 `--minimum-samples 5`；不将这 5 次的 p95 作为稳定统计结论。修改前记录在固定预算下会明确失败。

XCTest 未能可靠地在非活动窗口向原始 SwiftUI 手势派发事件，失败诊断已保留；没有伪造修改前的 30 次结果。修复后的接收器基准不包含操作系统事件递送，另由真实 CUA 输入复核。NSView 更新和离屏绘制都不等同 WindowServer 已呈现一帧，不宣称端到端屏幕延迟。

原始构建、仅加计时的原始构建、原生输入记录和独立测试库位于忽略的 `output/validation/performance-2026-10-22/`；图像基线为 `output/performance/image-baseline.json`。完整照片与原始路径不加入版本控制。

## 最终结果

统一入口已完成一次新目录的发布配置回归，并与同配置通过的参考报告比较，全部通过。最终结果位于 `output/performance/regression-2026-10-22/`，参考位于 `output/performance/reference-2026-10-22/`。

| 修复后项目 | p95 |
|---|---:|
| 网格接收器 → 选中 / NSView 更新，30 次 | 1.39 / 5.20 ms |
| 胶片条接收器 → 选中 / NSView 更新，30 次 | 0.94 / 3.97 ms |
| 冷预览 / 完整 RAW，各 30 次 | 30.77 / 690.60 ms |
| 2 / 3 / 4 张完整 RAW 比较，各 3 次 | 1245 / 1840 / 2393 ms |
| 单画布缩放平移，30 次 | 19.15 ms |

另做真实鼠标输入前后各 5 次复核，使用同样的原生事件和应用内计时边界：修复前按下到选择为 423–433 ms，修复后为约 1–2.54 ms；修复后按下到 NSView 更新最多 10.41 ms。严格核对 5 次提交和 5 次完成，没有将丢失点击忽略。原生记录为 `baseline-native.jsonl` 和 `after-native-timed.jsonl`，统计为各自 `*-native-summary.json`。

真实窗口另外验证右键菜单、指定照片双击打开、⌘ 多选、比较和 RAW 放大均正常。卡片辅助功能子元素折叠为单个带标签和操作的节点；该收尾修改另运行交互门槛，网格 / 胶片条选中 p95 为 0.81 / 0.74 ms，视图更新 p95 为 3.31 / 3.09 ms，记录 `ui-final-ax.json`。最终应用实际辅助功能树每张卡片只有一个节点，节点点击可选中对应照片。

普通回归测试 49 项通过；3 项按默认配置跳过（两套显式性能基准及既有离屏布局诊断），其中两套性能基准已由上述发布配置入口实际执行并通过。新增 20 项图像正确性/资源与门槛检查、6 项交互检查，覆盖立即处理、修饰键/双击、菜单和滚动路由、手动视口与键盘跟随、忽略取消的旧预览隔离、普通网格无 RAW 解码、缓存失效、并发上限、合并请求、取消与缓存预算。

工具反向验证通过：原实现的真实点击记录触发时延门槛失败；旧报告目录、缺少画布项目、未启用门槛的当前报告被拒绝；超时进程被终止并生成失败摘要；显式测量基线可供后续严格回归比较。15 张 RAW 的内容、尺寸和修改时间在最终回归前后全部一致。发布配置构建和临时签名检查通过，未创建 Git 提交或推送。

尚未测试 30,000 张图库、低配 M4、其他相机 RAW 模式或显示器实际呈现时间。
