# 005 · 自动序列堆叠交互设计

2026-10-24 · **Approved，用户已确认推荐体验；尚未接入应用。**

用户已要求导入时自动识别连拍和间隔序列，以可展开堆叠展示，并能重跑历史素材。以下为已确认的推荐默认值与研发路径；样本和技术路径见 [plan](plan.md)。

## 1. 保留现有工作台，增加一种列表组织方式

保持项目/会话栏、中央照片工作区、检查器、底部决定栏和胶片条。Light/Dark/System 继续复用现有语义配色；不更换页面、不新增自动评分或自动排除入口。

- **展示堆叠与用途组分开。** 堆叠用于整理一次导入会话中的照片列表；现有 CaptureGroup 继续表达可重叠的连拍/HDR/延时/校准等用途与序列参与。自动生成堆叠不创建用途组、不修改其保护状态，也不把“参与序列”当作显示/隐藏依据。
- 首版每张照片在其导入会话中最多属于一个展示堆叠；不嵌套，不跨会话/项目。没有足够证据的照片保留为散片，不能为了显得“已完成”而硬归类。
- 自动堆叠只允许覆盖**整个会话基础顺序中的连续区间**。保持当前“会话 + 自然相对文件路径”的稳定顺序；不是仅在某个来源分区内连续后，把其他来源的夹杂照片搬走。未知/失败/交错来源是屏障。照片顺序改变必须是另一个明确设计，不能偷偷发生在自动分组时。
- 全部素材、项目、会话视图可展示会话内堆叠。现有手动用途组视图保持逐张平铺和组内人工顺序，不套一层可能不完整的自动堆叠；检查器仍可说明照片所属堆叠并提供“在原会话中查看堆叠”。

## 2. 默认展开，收起是明确的用户动作

推荐首版所有新自动堆叠默认展开。刚发生过“文件实际都已导入，但用户误以为照片消失”的问题，不应再用自动折叠降低默认可见照片数。

### Grid

在原自适应照片网格中增加轻量分段标题/中性边界，照片卡片尺寸、照片选择高亮与单击响应保持。标题示例：

```text
▾ 连拍 · 123 张                         ⋯
  [照片1] [照片2] [照片3] ... [照片123]
```

收起后是同尺寸的一张实际照片卡片，加轻微叠层和独立展开按钮；例如 `▸ 连拍 · 123 张 · 收起 122 张`。不可把“123 张”写成“已选 123 张”，不能用整个堆的选中背景冒充单张照片已选。

堆叠标题/展开按钮与照片点击区分开：点击箭头只展开/收起，不改照片焦点、决定或星级；点击照片才选择该张。标题双击不触发单张查看。保留现有原生即时 mouseDown 接收器，不能重新引入等待双击判定的单击延迟；展开按钮不得被覆盖层吞掉，右键菜单和滚轮继续传递。

### Filmstrip

沿用现有单张宽度与水平滚动。展开堆用中性分隔和短标签 `连拍 123 ▾` 包围连续缩略图，收起后显示一张代表图和独立 `▸123` 控件。可将标签置于缩略图现有卡片角部/边界，不增加第二条导航栏。

同一堆在 Grid 与 Filmstrip 共用展开意图，避免一处显示全部、另一处无提示隐藏。展开/收起属于本地浏览偏好，不创建领域命令，不自动给堆叠加保护。

### 当前焦点与已选照片不能被收起动作悄悄丢掉

- **确定推荐：普通单焦点可直接收起，临时显示该 focus 照片；如果会隐藏其他已选照片则保持展开。没有逐次确认弹窗。** 当前焦点在堆内且仍匹配筛选时，该照片成为本次收起卡实际显示的 assetID，focusedID、选择和持久封面均不改。只有一个已选成员而焦点在堆外时，也可临时显示该已选成员，不转移焦点。
- 若堆内有多个显式已选成员，一张代表图无法使它们都可见，禁用收起并说明“堆内有 N 张已选照片，清除多选后可收起”；单焦点/单选不受此限制。该限制只影响收起，不清空多选，不把不可见多选留给 P/X。单击已收起卡始终以卡上实际显示的 assetID 重设单选。
- 已有持久封面、当前显示代表图和照片选择是三个概念。检查器/帮助文字明确区分，不为便于收起而修改资产身份或永久封面。

## 3. 数量始终按照片计，并解释所有隐藏来源

定义：

| 指标 | 含义 |
| --- | --- |
| T | 当前范围内全部照片数，含被筛选排除和被堆叠收起的照片 |
| M | 当前筛选匹配的照片数，收起不会减少此数 |
| V | 列表实际显示的照片卡片数；每个收起堆只贡献一张代表照片 |
| H | 因收起隐藏的匹配照片数，`H = M - V` |
| T − M | 因筛选不匹配而隐藏的照片数，与 H 分开 |
| S | 堆叠数；单独标“堆”，绝不替代照片数 |

中央标题下在有堆叠/筛选时用最多两行的短摘要，例如：

```text
共 1103 张 · 当前筛选匹配 132 张
显示 28 张 · 收起隐藏 104 张 · 保留 12 张
```

窄中央区域也应完整表达关键数字，不能重现标签挤成竖排；无堆叠时维持原摘要密度。侧栏会话数继续是登记照片数。状态/筛选结果不得把收起的成员称为未导入、缺失或未找到。

每个堆显示全量 N 与当前筛选匹配 K。收起示例：`共 123 张 · 匹配 12 张 · 显示 1 张 / 收起 11 张`；其余 111 张是筛选不匹配，不混入“收起 11”。展开则显示 K 张匹配照片。

## 4. 封面没有质量含义，筛选不能把匹配成员藏没

推荐自动封面为堆内基础显示顺序第一张，不使用“最佳”“最清晰”“推荐精选”等词，不以曝光、对焦或算法评分选封面。允许用户从某张实际照片明确“设为堆叠封面”，该领域修改可撤销并默认保护该堆；失败预览显示占位图及文件名，不能为遮掩读取失败偷偷换成所谓更好照片。

筛选规则：

1. 先逐照片计算匹配集合，再投影堆叠；`K = 0` 才移出当前筛选结果。不能仅测试持久封面是否匹配。
2. 已展开堆显示所有 K 张匹配照片，标题仍写原始 N 张。
3. 收起时的代表图优先级明确为：符合筛选的当前焦点成员 → 符合筛选的唯一已选成员 → 符合筛选的持久封面 → 基础顺序第一张匹配成员。最后一种标为“筛选代表图”，前两种可标“当前图/已选图”；都是临时表示，不回写封面。若出现多个已选成员则展开，而非用此优先级把其余多选藏起来。本次收起期间锁定实际显示的 assetID，焦点移走不自动换图；只在展开后重新收起、筛选使代表图不匹配或成员失效时重新投影。卡片事件绑定当时显示的照片，回调不得动态重取封面。
4. 堆菜单提供“清除筛选并展开此堆”，是明确操作；不会后台清除全局筛选，也不提供名称含糊的“显示全部”按钮。
5. 用户切换筛选，或决定/撤销导致匹配变化后，显式选择立即与当前匹配 assetIDs 取交集，不自动选其他照片。当前照片出筛选时可保留 focusedID 作单张回看/下一张定位锚点，标“当前照片不符合筛选”，但不再是 P/X/星级操作对象；没有匹配选择时禁用这些写入动作，撤销仍可用。一次批量决定先作用于操作前明确选择，再规整；自动前进根据操作前单选和位置计算，不能用规整后的空集合跳回第一张。这是对当前仅筛选视图、不裁剪选择实现的新增要求。
6. 任意主动跳转到收起的非代表成员都先展开再定位；不因焦点恢复或后台刷新静默把卡换成另一张。收起投影不能隐式选中其他照片替代刚操作的资产。

## 5. 选择与快捷键仍以实际照片为单位

“单击堆叠”不能成为隐含全堆选择。默认只选择所见代表照片的一张 assetID，P/X/U/0–5 星级也只影响该照片；双击代表照片进入现有单张查看，不展开后批量选择全堆。

保留现有**显式** ⌘/Shift 多选和底部“已选 N 张”的批量操作契约，不把本次功能变成取消多选功能的改版：当用户主动选了多张实际照片，决定/星级仍作用于明确选择集合；堆叠本身从不隐式追加隐藏成员。

| 输入 | 推荐结果 |
| --- | --- |
| 单击实际照片或收起堆的代表图 | 只选择该照片；保持原生即时响应 |
| 双击实际照片或代表图 / E | 打开该照片；不推断整堆操作 |
| 单击展开箭头 / 键盘聚焦箭头后 Space | 只改展开状态 |
| ⌘ 点击 | 只增减被点击的照片 |
| Shift 范围选择 | 以基础照片顺序计算显式范围，先展开涉及的堆使被选照片可见，再选择；不能暗选不可见成员 |
| 左/右箭头、决定后自动前进 | 沿现有筛选后基础照片序列逐张前进，目标在收起堆内则先展开再定位；折叠不改变逐张选片顺序 |
| C | 沿用 2–4 张实际照片的比较；单选时仍用相邻照片补足，并先展开所涉及堆；不把一个堆当一张照片或默认把全堆送去解码 |
| G / E / Tab / Z | 保持现有网格、单张、检查器与按需细节行为；不新增整堆 RAW 解码 |

“选择当前筛选内全部 K 张”是明确的整堆范围动作，执行时先展开、展示所有被选成员并更新已选数量。“选择整堆全部 N 张并清除筛选”需用完整按钮文字；不能让一个未说明的封面点击触发此效果。首版无需另加“整堆排除”快捷键；明确选择成员后复用现有决定栏即可。

AX 元素仍是一张实际照片一个选择元素，另有展开按钮，避免曾修复过的重复 button 树。展开控件朗读“连拍堆叠，共 123 张，匹配 12 张，已展开/已收起”；选中数量和保护/错误不靠颜色表达。

## 6. 人工纠正与保护是明确的堆叠动作

堆菜单可复用已交付的 preview→apply 模式，最小范围为：组成堆叠、设置封面、改连拍/间隔类型、边界拆分、相邻范围合并、解除堆叠（保留全部照片）、保护/允许重算。人工修改默认保护，不能把改照片星级或收起列表当作保护命令。

为保持首版连续区间约束：

- 拆分按明确边界切开连续区间，不支持从中间抽出零散照片后让剩余堆跨过它们；不足两张的一侧作为散片，预览说明，不制造一张照片的堆或删除照片。
- “组成堆叠…”允许同会话完整基础顺序中至少两张明确选择的连续照片，既可全为散片，也可包含完整相邻旧堆与散片。先预览全部受影响旧堆、散片、顺序、类型、数量与保护变化，用户一次应用，形成一条默认保护且可精确撤销的人工命令。没有显式指定封面时取顺序首张；不改变用途组。
- 连续性按完整会话顺序校验，不因筛选隐藏夹杂照片就偷偷把它们补进选择。只选旧堆部分成员时明确提示先显式拆分，不自动拆取。原相邻堆合并复用这一路径，不提供任意零散成员编辑器。
- 解除自动堆叠要持久记录人工意图并保护对应范围，重跑不能立即原样重建；具体 tombstone/人工范围由 Core 合同落实。
- 用途组已有成员顺序/参与冲突处理保留；展示堆叠没有“参与序列”开关，不借用用途组的 includedAssetIDs。

自动导入后台生成的每个堆不能不断压入 ⌘Z 栈，抢走用户刚做的 P/X/星级撤销。自动导入与异步历史重跑均只写持久运行记录和冲突安全恢复，不压入普通 ⌘Z。仅显式人工修改与用户点击“撤销这次分组”的恢复命令按实际顺序进入统一运行期撤销栈；不用全照片历史快照恢复。

## 7. 导入中的到达与发布不抢工作台

保留“用户开始导入时进入该新会话”的既有一次性导航；之后照片/堆叠到达不再切 scope、改 focusedID、替换选择、退出比较或重置 RAW 缩放。

- 原片登记后先按稳定基础顺序平铺可浏览，不等待整批分组或全部预览解码。
- **导入中增量补读/分析证据，照片继续平铺；本会话素材尾部完整后一次原子发布有效堆叠。** 之前只显示“分组中”，不把未封闭尾部的暂态猜测变成会反复拆并的正式堆叠。发现顺序不等于文件顺序，不能依赖文件系统枚举先后来判定闭合。整体任务终态必须等尾部判定与发布完成，不把“已排队”叫作“已分组完成”。
- 一次发布的默认展开堆只增加组织边界，成员数量不减少。用 assetID + 相对屏幕偏移锚定可见照片，插入标题或补齐前面文件时保持当前照片位置；不靠旧行号恢复滚动。
- 对已有导入的续传/补片也先保留已生效视图，尾部完整后原子更新受影响范围。未变堆保留身份与浏览偏好；成员或边界变化的堆明确标“新增/变化 N 张”并默认展开，不无提示把新照片吞进旧的折叠数字。人工保护在提交前重验。
- 状态至少区分“发现 / 原片登记或复制 / 自动分组覆盖”。原片接入完成而分组未完成时显示“原片接入完成，分组处理中”，不能写成全任务成功。终态报告同时列已覆盖照片、未完成/证据不足/失败范围与重试入口。
- 自动过程不改保留/排除/星级、用途组或序列参与，不为所有隐藏成员解码 RAW。展开仍懒加载内嵌预览，只有现有明确放大才请求 RAW 细节。

暂停导入应暂停其待处理分组，已登记照片和先前已生效的堆保留；本次未完成分析不发布半套结构，并明确剩余覆盖。若未来允许“只暂停分组、接入继续”，按钮必须明确写明对象；首版不用一个泛称“取消”同时承诺两种不同结果。

## 8. 历史重跑：先算变化，保护人工结果，再明确应用

推荐会话菜单“重新分析连拍与间隔序列…”。首版以完整会话为单位，项目级入口先列会话复选范围，绝不默认重跑整个资料库，也不在启动应用时改历史内容。

推荐历史流程与导入的区别：**新导入自动发布，历史重跑先生成差异预览，再由一次明确“应用未保护堆叠的变化”提交**。这不是逐候选手工确认，只是让用户先看到会改变哪些既有列表结构。

1. 范围页显示会话/照片总数、原自动堆数量、人工/保护范围数量；连拍与间隔均默认纳入。不上未经验证的阈值滑块或准确率。
2. “分析并预览变化”后台运行；工作台可继续选片，不跳到结果、不折叠旧堆。检查器可查看本次进度，关闭面板不等于取消。
3. 差异报告区分新增/改边界或类型/解除旧自动堆/无变化/保护跳过/证据不足/失败，照片总数始终守恒；展示选定项旧新成员顺序和封面，说明变化理由及证据限制。
4. 保护的人为修改、保护堆、解除堆叠的人工范围及现有用途组不被覆盖。用户想纳入需另行明确允许重算，再更新预览；不能默认提供一个“一并覆盖所有人工结果”的复选项。
5. 应用前重新检查输入与保护状态；用户在计算后新增保护或改边界时，不能覆盖旧快照，报告过期/跳过并要求重新预览相关范围。
6. 分析/预览阶段取消，不改变当前堆叠。应用阶段按会话原子提交；跨会话可在事务边界停止，并明确列出已应用与未应用会话，不能声称已全部回滚。恢复/撤销也需遵守后来人工修改的冲突检查。
7. 原照片始终保留。分析取消不改结构；暂时不可读/未完成范围保留整个相交旧堆叠并提供精确重试。完整检查但不足以继续成组，可在差异预览列出“解除旧自动堆叠”，经用户明确应用后成为散片；不能把这种变化伪称为读取失败，也不笼统承诺所有 partial 保留全批旧结构。跨会话应用取消保留已提交会话，列明未应用部分。证据不足不标为废片。

## 9. 实施前需要验证的交互矩阵

| 场景 | 可观察验收 |
| --- | --- |
| 1103 张照片首次自动分堆 | 默认仍显示所有匹配照片；T/M/V/H 算式与实际卡片数相符，无身份丢失或重复 |

## 10. 无法核验设备身份时的来源确认

导入页提供未默认勾选的“本批素材来自同一台相机”，说明仅用于在缺少可靠设备标识时分析序列。先接受用户意图，扫描封存后绑定本批实际资产清单；发现明确多设备证据时不能用声明覆盖。未选择也可照常接入、浏览和选片，报告“相机来源未确认，部分照片未自动分组”，提供补充来源确认后重跑入口。

历史会话没有足够设备证据时，在范围页提供同样的明确确认；已有声明与清单仍有效则不重复询问。同目录新增资产不默默继承；用户可撤销声明，使相关分析失效并待重算。不要将目录或机型作为已确认来源的默认值。
