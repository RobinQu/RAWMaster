# 005 · 连拍与间隔序列自动堆叠

日期：2026-10-24。状态：**Approved / 用户于 2026-10-24 确认推荐体验与 A → B → C 实施路径，已授权实施；质量验收仍待实测。**

用户要求：导入时自动识别连拍、间隔拍摄的文件序列；在照片列表以可展开的 stack 表达；导入后可重新发起分组，覆盖历史资料。此要求取代 004 SG01“不随导入自动启动”和 SG02“逐组确认后才建组”的目标流程，不改动其已经交付的功能与历史验收记录。

## 用户故事

### US1：导入完成时已有可辨认的序列（P0）

- AS01：导入流程包含自动分组。先登记并可浏览照片，已核验素材逐步补读证据；文件处理完毕后，完成尾部边界判定与分组提交才显示“接入与分组完成”。
- AS02：复制/核验和分组分阶段计数。素材导入成功、分组取消或失败时必须分别显示，不将分组失败当作照片未导入，也不把任务排队当作已经完成。
- AS03：导入中增量保存分析证据，照片先平铺浏览；扫描清单封存、尾部分析完整后，才一次原子发布正式堆叠。首版不发布暂态堆叠。后台更新不自动折叠、不移动当前焦点或改变选择。
- AS04：连拍与间隔序列采用不同证据规则。不能把“间隔短”一律叫连拍，也不能把“拍得久”一律叫延时。类型不明确时保留未知/散片及理由。

### US2：在网格和胶片条中识别并浏览堆叠（P0）

- VS01：库、项目、导入会话的网格与胶片条都显示堆叠边界、类型与成员数量；展开后每张照片仍是可选的独立条目。
- VS02：建议新生成堆叠默认展开；收起显示明确的叠层卡与“共 N 张 / 折叠 M 张”，展开/收起不是照片删除或排除。侧栏数量始终按照片计。
- VS03：范围总张数、筛选匹配数和折叠数分别表达。所有匹配照片必须且只能出现一次：作为散片、展开成员，或归属于收起卡的明确计数。
- VS04：单击照片仍选择该张；单独的展开按钮负责堆叠展开/收起。双击照片仍打开单张，既有多选、比较与原始像素查看保留。
- VS05：P/X/U、星级和默认交付均针对明确选中的资产，不能因收起堆叠就暗中作用于全部成员。“选择整组”等范围扩展必须是显式动作并显示实际张数。
- VS06：首版不自动挑最佳片。默认代表图使用确定性顺序首张，用户可更换；代表图不等同保留决定或质量评分。
- VS07：筛选匹配的是成员照片，不能只检查固定代表图。代表图不匹配但成员匹配时，堆叠仍出现，并说明匹配数；临时展示的匹配成员不改用户保存的代表图。
- VS08：人工用途组内沿用已保存成员顺序，首版不加入嵌套堆叠层级；折叠不会改变该组的序列参与。
- VS09：方向键、决定后自动前进沿筛选后的照片顺序逐张移动，目标在收起堆内时先展开。收起不改变焦点或永久封面；若会隐藏其他已选成员则保持展开并解释，不能留下不可见的批量操作对象。
- VS10：筛选匹配变化后，明确选择与匹配资产取交集，不扩选；出筛选焦点仅作回看/导航锚点，不接受决定/星级写入，无匹配选择则禁用这些动作但保留撤销。一次批量动作先作用原明确集合、再规整。收起期间锁定代表图的实际身份，点击不能操作悄悄换过的封面。
- VS11：连续散片或完整相邻旧堆与散片可经一次预览组成堆叠，默认保护、可撤销；按完整会话顺序验证，不能补入筛选隐藏的未选成员，也不能从旧堆中暗中抽取部分成员，须先显式拆分。

### US3：为历史素材或新规则重新分组（P0）

- RS01：“重新分析连拍与间隔序列…”支持明确选择的项目/会话；首版分析单位为完整会话，照片选择不会默默变为运行范围。全库运行需用户显式选择。
- RS02：历史重跑先计算整批差异预览，用户一次明确应用后，按会话原子替换仍由算法管理的旧结果；期间原堆叠可用。取消分析不改变旧结构；跨会话提交可在会话边界停止，报告已应用与未应用，不宣称全批回滚。
- RS03：人工创建、拆分、合并、改类型/代表图/成员等修正默认受保护；重跑不覆盖，不因为用户解锁就直接取得覆盖权限。
- RS04：用户“解除堆叠”或否定边界后保留对应记忆，输入及规则未变时不在下一次重跑自动复建。允许用户显式清除此记忆。
- RS05：任务保存算法、参数、作用域和输入版本。照片增减、内容身份变化、人工结构修改会使过期结果拒绝提交；评分与决定变化不无故使纯图像分析过期。
- RS06：同输入同规则重跑幂等，保留未变堆叠身份及用户浏览偏好。重新分组有可审阅的结果摘要和可恢复记录，不与既有组/选片撤销抢占顺序。
- RS07：不可读、未完成、来源/时钟/内容/特征未验证等范围保留整个相交旧堆叠；只有完整有效观察且唯一不足为无序列支持的照片，才算“检查后不成组”。此时仅对明确允许算法管理的旧堆在差异中列出解除，经明确应用后成为散片；不凭创建来源或解除保护取得重算权限。不得把未知与已检查单张混为全批保留或全批清空。

## 共同约束

- GC01：自动堆叠只组织与呈现，不删除、移动源文件，不写 RAW，不自动决定保留/排除，不改变人工序列参与。
- GC02：资产在同一展示作用域至多属于一个主要堆叠；多用途 CaptureGroup 仍可重叠。二者不可为省代码而混为同一关系。
- GC03：默认不跨项目、会话或未经核验的相机来源自动拼组。机型名称、文件名连续和目录相同均不能被伪称为已证明同一设备。
- GC04：保留原 EXIF 字符串、亚秒和偏移；无偏移只比较相应来源的本地拍摄时间，不伪造 UTC，不用目录名或文件修改时间代替。
- GC05：缩略图方向归一，默认使用有预算的内嵌预览特征，不为自动分组批量解码完整 RAW。链式相似必须有跨组漂移与长暂停边界约束。
- GC06：损坏、不支持、缺证据、不可读、时钟回拨、相机来源不明保持可见，逐项说明不分组原因，不能当废片丢弃。
- GC07：重用本地 SwiftUI/AppKit、SQLite 和图像框架；主题、原片重新定位、人工组与现有交付保持兼容。不包含自动排除、完整显影、序列合成或网络同步。
- GC08：自动堆叠是完整会话基础顺序中的连续区间，不通过过滤掉坏片、未知或其他相机行制造连续性，不重排照片。人工拆分/相邻合并也遵循此约束；非连续组织继续用用途组。
- GC09：无法验证设备身份时，可由用户明确确认“本批来自同一台相机”，绑定封存资产清单；不默认勾选，不自动覆盖同目录未来新增照片。无设备证据仍可导入选片，并报告分组覆盖不足。

## 验收门

1. 导入与历史重跑：同一作用域、输入和规则产生等价有效堆叠；中断、续传、缺片和取消均不丢素材或旧决定。
2. 可见性恒等式：匹配资产总数 = 散片数 + 展开堆叠成员数 + 收起堆叠匹配成员数；空筛选、混合状态及重启往返均成立。
3. 原片 SHA256/大小/修改时间、资产身份、决定、评分及人工组关系的非授权变化数为 0。
4. 连拍与间隔分别用整段标注开发集和独立评估片段验收。拟议最低门：正负相邻边 precision ≥95%、recall ≥95%；已确认禁止合并边界误并为 0；本轮指定的完整正例组逐组精确恢复，不以高相邻边 recall 掩盖拆组；新留出按类别至少 80% 的正例照片形成类型正确堆叠，未知计入覆盖损失。报告误并/拆分、类型混淆、未知及纠正耗时。以上是本轮采用的工程验收门，规则/样本角色冻结前可评审支持范围，看到留出结果后不能调低门槛。零预测 precision 为 null，不能通过全部保持未知达标；缺负例不能计算完整 precision，也不能宣布该类别通过；任一明确负边界证据不可判定也阻止通过，不能仅从分母排除。未确认来源的条件实验单独报告，不能关闭 A 质量门。
5. 已看过的 123 张与独立 16 张诊断数据是当前已知回归，不再作为新算法未见过的留出集。用户已提供间隔整组 `/Volumes/SM9100-8T/RAW Dumps/2026-10-06-a/DCIM/100MSDCF/DSC05994.ARW–DSC06420.ARW`，对应 427 个编号，文件存在/齐全、节奏与暂停尚未核验；用户随后确认邻片组外，但文件名核验发现06421不存在。首次验证采用新连拍72输入及间隔439输入的预注册上下文；间隔只验真实起始负边界与EOF，不声称结束后边界已验证。详情见 [验证记录](validation.md)。规则冻结后首次整段验证，未有实测证据不能宣称通过。
6. 无后台、导入+自动分组、历史重跑三种负载下复测点击、预览、RAW、比较与绘制；保持既有绝对和同机相对门槛。新增测量 stack 展开/收起、批量提交与重启恢复，明确应用更新和屏幕呈现边界。
