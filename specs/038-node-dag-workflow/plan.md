# Implementation Plan: 038 · Node DAG 工作流与暗房界面

**Date**: 2026-11-26 · **Spec**: [功能规格](spec.md) · **Prototype**: [摄影工作台](../../docs/ui/prototype/index.html) · **Evidence**: [验证记录](validation.md)

## Summary

先稳定现有显影配方、照片预览、不可变版本及导出契约，再分阶段把图结构和交互接入原生暗房。首个可发布切片是「打开旧片 → 一个 Corrector → 调整／撤销 → 查看终稿 → 保存候选 → 导出」。默认视角 100% 可读居中，图与主图独立；多节点编辑和中间输出须通过 T04 的预览与交付隔离验收后才开放。HTML 已用于交互评审，本文是原生研发计划，不是原生实现或像素验收。未初始化或执行仓库中不存在的 Spec Kit CLI。当前研发授权已包含原生开发与验收，不包含提交或发布。与 [037 计划](../037-color-film-hdr/plan.md#调度与判定)统一顺序：先开发固定阶段和旧配方只读投影，再接暗房、冻结最终输出与多节点；并行推进各自独立的输入、模型和 HDR 文件测试。原生默认行为和发布状态仍须凭独立验收证据放行。

## 2026-11-27 · 实施确认

保留 T01～T05、FR 和 SC 的原口径，不以首个切片缩减规格。先让已经验证等价的旧显影拥有一个可在原生窗口打开的**只读兼容视图**；在后续编译、持久化和像素验收前，不打开任意拓扑、忽略或监看。评审从资料库进入暗房，打开、收起和关闭 Graph；现有调整、撤销、保存和 032 仍走原链。本阶段通过独立评审开关进入，不改变默认行为。下一阶段先交付有界、可验证的执行计划，再逐项接入节点写命令和预览目标，最后才接入工具和批量。

- 开放门槛：先复跑[只读兼容走查](spec.md#只读兼容视图评审入口)，再用真实原片和独立资料库断言同一动作不变更显影、历史、视口或交付。旧规格的 20／200 张和完整可访问性仍须分别验收。
- 037 与 038 共享场景前级和最终输出语义，但不互相代签：旧 SDR 地图不能作为 HDR 母版；场景组件能导出并不意味着暗房已经能编辑该工作流。

### 场景图工程门槛（先于实测）

关联合约：[037 T03/T04/T11](../037-color-film-hdr/plan.md) 与 038 T02/T04。先以独立配方模式接入目录草稿、不可变版本和固定交付票据，旧引擎明确拒绝该模式。Metal 图使用 AP1 预乘 F32 与 R32F 覆盖，允许负值和超白；核对串行、Parallel 的线性增量、Layer 顺序及 13 个模式、独立 Group、Outside、遮罩循环及范围、全源坐标 ROI。代码测试使用 独立 CPU 参考，混合 F32 通道绝对误差 ≤ 8×10⁻⁷（固定向量），alpha 相同，选中 ROI 与全幅对应像素逐像素相等。禁止以浏览器代理作为像素参考。

第一道**组件性能**门槛：Apple M2、常驻 960×640 F32 输入，双曝光分支、一条线性覆盖及两次混合；两轮各预热 5 次、采 30 次，含调度、纹理分配、提交和 GPU 完成，p95 每轮 ≤20 ms。明确不包含 RAW、成像输出、视口运输或主线程，该门槛不是 036 的手势/定稿 p95。再验收真实 24 MP 冻结版写盘和独立回读，但不能冒作批次或实时视口性能。最终仍须按 T03～T05 用原生同动作重验。</n
原生浮窗阶段增加监看门槛：在相同雪景 F32 输入、浮窗打开、1200×640 工作窗口内，组内首节点与最终图交错切换，各预热 5 次、采 30 次，以命令至相应 SDR 浮点 drawable 完成计时。p50 ≤25.92 ms、p95 ≤210.23 ms。该门槛覆盖监看状态的末端呈现，不含 HID、RAW 冷读、跨屏、复杂 Node 并发和批量，也不是 T05 整体验收。

批量候选先过数据库门槛：Apple M2，20 个冻结目标全部创建并撤销；200 个在第 23 项后取消、重开、重试，保持离线/修订冲突和撤销校验。每项仍从磁盘核验完整 SHA（同字节只可复用校准），候选阶段不包含渲染或导出编码。门槛 20 项提交 ≤15 秒、200 项提交/取消/重开/重试 ≤120 秒。独立像素交付沿 032/T05 另测，不用库操作速度代替出口吞吐。

## Constitution Check

- 遵循仓库原型优先、真实浏览器走查、同输入原生复验的顺序。覆盖表、规格和原生行为同改；模拟与真实证据严格分开。
- 单一配方权威。图查看状态不得成为配方或导出输入；未确认的新交互、未支持的底稿或素材保持禁用与明确原因，不降级成错误像素。
- 不增加第三方前端框架或改变旧预设交换语义。Rust / Swift 跨界复用现有请求和取消契约；只在相应阶段验证后开放新命令。

## Project Structure

本次交互交付位于 `docs/ui/prototype`、`scripts/check-ui-prototype.py` 和本特性目录。未来原生 UI 与会话测试留在现有 RAWMaster Swift 目标及其测试目标；图执行和像素夹具留在 ImageEdit Rust 测试边界。优先增量修改上表所有者，仅为图的持久化、图形交互或渲染接线增加必要单元。不要建立另一套暗房、预设数据库或导出任务入口。

## 验证与发布边界

- **自动检查**：保留 [浏览器用例](../../scripts/check-ui-prototype.py) 和旧兼容导入流程；原生阶段将图结构/序列化、适配、会话/焦点、预览身份、保存/交付与像素一致性分别加入项目现有 Swift／Rust 测试及 CI。运行仓库既定的测试命令，不以脚本通过代替视觉或像素验收。
- **交叉测试**：单节点、长串行、分支、多选、组内路径；桌面和最低窗口、浅/深色、四种照片背景、减少透明，检查节点字高、标题可达、图可平移、状态对比和 VoiceOver。最终、节点临时输出、失败保留、用户返回四种画布状态必须可辨。
- **放行**：每个阶段都要有命令退出码、真实数据/截图和可复现动作；遇到未支持图配方、旧数据不对等或错误导出，保持该能力关闭，旧单照片链仍可工作。原生开发和数据迁移纳入实施；发布不在当前授权内。
