# 数据变化提案

状态：2026-10-23 范围获批，开始实现；下面记录模型设计，数据库实际迁移以验证记录为准。

## 本机偏好

`appearance.preference = system | light | dark` 保存用户意图；`resolvedAppearance` 为运行时结果，不永久覆盖意图。偏好版本和未知值回退规则明确。本机偏好不进入 SQLite 业务同步日志、原片清单或组数据。

## 文件身份和位置

现有 Asset ID 和 `contentHash` 继续标识已登记内容；历史 `sourcePath` 保留。位置角色为原始来源引用或受管副本，当前位置及可用性独立维护。会话增加当前源根和当前受管根，历史源/目标与有效继续位置不能混用。

迁移时当前路径先按旧 ImportMode 标成当前角色，不重新哈希全库。缺哈希、失败接入保留未知，不伪造完整资产。一次重定位只更新确认范围，未匹配资产仍引用旧位置。

`RelocationSession`：ID、scope、根目录角色、选定目录、输入版本、扫描进度、状态。

`RelocationCandidate`：资产 ID、候选路径、候选内容哈希、文件状态指纹、匹配依据、歧义/失败原因、用户选择；扫描证据与最终提交结果分开。临时证据不进入选片清单。

状态：扫描中 → 待审阅 → 提交中 → 完成 / 部分完成；取消/中断可保留可复用进度。没有用户确认不会修改有效位置。

## 可信拍摄元数据

按资产保存：原始 DateTimeOriginal、亚秒原文、偏移原文、解析结果、时间精度/可靠程度、机型、已可确认的相机来源、原始文件顺序及元数据提取版本。可确认来源不默认保存相机硬件序列号；同机型多机位未知由用户限定处理范围。

旧 `capturedAt` 不被当作可信精确时间。新字段缺省为空/未知，后台可按需补读；原字段可暂用于兼容显示。拒绝用文件修改时间自动补拍摄时间。`sourceFingerprint` 随输入内容变化，人工星级不改变图像分析输入版本。

## 正式组和人工操作

CaptureGroup 增加：来源 manual / acceptedSuggestion、用途、locked、groupRevision。成员保持独立 position / included，照片入选决定不搬进组。已有组迁移 manual + locked，不变成员顺序与参与状态。

GroupCommand：稳定 operation ID、类型、影响组/成员、预期与结果版本、最小 before/after、来源、时间、补偿关系。沿用事务 `operations` 并增加足以恢复的版本化 payload，不仅保存最终快照。

组恢复只修改组域；后续成员操作冲突可见，后来照片评分不回滚。拆分/合并的新旧 ID、成员位置、参与选择全部可追溯，跨项目合并拒绝。具体重复成员参与冲突不得再静默 OR。

## 候选，与正式组分开

SuggestionRun：ID、作用域与扫描覆盖、输入版本、参数/算法版本、状态、进度。

GroupSuggestion：ID、run ID、有序成员、候选用途（含 unknown）、时间/相似证据、证据层级、涉及既有组及其版本、pending / accepted / ignored / stale。

输入/算法指纹用于相同候选去重与忽略记忆；重算不能删除已确认的正式组。确认事务创建组/更新候选状态并记录同一组命令，重复确认幂等。输入变动使相关候选 stale；评分变化不使纯图像候选无故过期。

候选恢复不等于继续未保存的任意计算栈；重启仅重排未完成工作。已完成、输入未变的候选和忽略状态保留。

## 版本与输出

A 的重定位采用 v1→v2，B1 采用 v2→v3，v1 可在一次有一致备份的迁移事务中顺序升级到 v3；每次版本变更原子提交、失败回滚、有一致备份、拒绝未知较高版本。JSON 模型新增字段使用明确缺省解码，不靠新增非可选字段导致旧库打不开。

精选清单继续输出原身份、决定及组关系；若增加当前位置/组类型等字段，升级 manifest 版本并保留旧字段语义。不把预览相似度、主题偏好或候选状态伪装为用户决定。新的位置与组操作记录未来可供 M3 映射，不在本批承诺同步。

精确接口、按域最小补偿、aggregate 逻辑摘要、幂等及 tombstone 规则见 [group-commands.md](group-commands.md)。B1 仅增加组命令与组域表；上文“可信拍摄元数据”和“候选”是后续目标，当前无正式数据库字段或候选表。
