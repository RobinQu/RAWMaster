# 004 · M2a 客户端外观与可恢复的拍摄组选片

日期：2026-10-23。状态：**Approved / 用户确认 A → B、默认跟随系统与图标系统边界，授权实施。** 质量指标仍须真实开发/留出样本验证，不因批准而视为已经达标。

决策入口：[下一批审阅](../../docs/planning/09-next-batch-review.md)。既有能力以 001–003 验收为准；本规格只定义增量。跟随 macOS 外观及其自动日夜切换已获用户明确确认。

## US1 · 用户控制界面与图标外观（P0，NB01）

作为选片用户，我可在设置中选择浅色、深色或跟随系统，舒适地浏览同一张照片，应用图标与运行时外观匹配。

- TH01：通过“设置… / ⌘,”进入“外观”，三个互斥选项，建议首次默认跟随系统；立即保存，无需重启。
- TH02：跟随系统读取 macOS 有效外观，包括自动日夜变化；不独立计算日出日落、不申请定位、不另设时刻。手动浅/深模式不被系统变化覆盖。
- TH03：全部应用窗口、网格、单张、比较、胶片条、侧栏、表单、错误、空状态及应用自有弹窗支持两套语义色。
- TH04：照片像素、RAW 渲染参数和缓存键不因外观变化而改变；焦点、所选、作用域、滚动、缩放及任务不重置。
- TH05：浅色使用 C2，深色使用 C1；应用内图标按解析主题联动。手动浅/深档联动运行中 Dock；system 档回到原生系统图标策略，尊重 macOS 独立图标外观偏好。Finder / Spotlight / 退出后图标由系统原生图标偏好决定；该边界已获用户接受。
- TH06：偏好是本机设置，不写进项目清单或未来共享业务状态；不增加图标与界面各自独立的配置。
- TH07：操作文字和图标能独立表达选择/保留/排除等状态；不能只靠主题下的色差传达含义。

验收：在系统浅/深两种状态下分别测试三档设置；重启、打开其他窗口、睡眠唤醒、设置恢复、比较及导入中切换均正确。照片解码调用计数不因切换增加；所有浏览状态不变。系统图标固定/自动/染色分别记录实际表现，不将预览切换等同桌面全局实测。

## US2 · 找回掉线或移动后的同一原片（P1，NB02）

作为原地接入或移动工作盘的用户，我能重新找到同一份内容，恢复 RAW 细节和交付能力，保留已有选片结果。

- RL01：缺片的信息栏与导入会话提供明确恢复入口；盘重新挂到原路径时可通过现有核验恢复，无需强制重定位。
- RL02：重定位先选目录、只读扫描并展示预览报告；候选匹配限定在当前资产/会话范围，不能跨项目静默匹配。
- RL03：完整 SHA256 与已登记内容身份匹配才可更新位置；同名、同尺寸、相似画面均不能代替哈希。不具备旧哈希的记录不能自动继承身份。
- RL04：多个相同内容候选需用户选择位置；不同内容、无法读取、缺失保持原状态。若先前不可用的旧路径已恢复，提交前重新检查并发变化。
- RL05：资产 ID、决定、星级、组和顺序不变，原始导入来源保留；新增“当前位置”。复制模式的原始卡路径与受管副本位置分别处理。
- RL06：来源根重定位和受管根重定位分别明确影响。更新会话默认根之前核验资产映射及相对路径；源根变了不自动改变复制目的地，受管根变了不伪造原来源。
- RL07：用户确认后原子提交匹配项及审计记录；部分成功需明确数量，不把整批显示为全部就绪。中断重扫可复用已核验证据，但提交前重新检查文件状态。
- RL08：取消仅取消本次查找，不删除原记录或已存在副本；更换素材内容需另行接入为新内容，不套用旧决定。

验收：同字节换盘、同名不同内容、重复候选、零匹配、部分匹配、源外部变化、读权限失败、取消/退出恢复、受管副本存在而原卡缺失、来源与受管根分别移动；逐项核对决定、关系、源字节及导出目标。符号链接解析后不得越出用户选择根目录。

## US3 · 人工纠正并保护组结构（P1，NB03 基础）

- GR01：复用已有组，新增拆分与类型纠正；保留现有创建、改名、合并、排序、参与调整入口。一个资产仍可属于多个用途组。
- GR02：已有组迁移为人工来源、默认锁定。人工确认/修改的组默认锁定；锁定保护自动改写，不阻止用户主动调整。解锁仅允许用户显式操作，不表示允许自动覆盖。
- GR03：组类型包含未知、连拍、延时、HDR、星空及其他手动用途；系统不依据单个时间阈值断言特殊用途。
- GR04：照片独立入选与组内参与仍分离。合并/拆分必须预览各组成员及参与状态变化；出现相同资产的参与状态不一致时明确列出并由用户确认，不用默认 OR 隐藏冲突。
- GR05：新增组操作使用统一的撤销顺序，与既有选片撤销不互相抢占；组操作有持久 before/after 补偿，可在重启后通过最近组操作入口恢复。不得跨越后续冲突操作静默回滚。
- GR06：恢复只影响本次操作实际修改的实体，不能整组历史快照覆盖后来评分/决定；版本变化时提示冲突并提供人工复核。
- GR07：移出受保护组输入前显示影响范围；本批只提示显式移出的成员，不判断 HDR 覆盖、延时间隔或天文校准充分性。

验收：拆分/合并后往返恢复、重复资产参与冲突、不同用途重叠、跨项目阻止、锁定状态重启保留、最新操作撤销及后续变更冲突检查。任何步骤不改原片。

## US4 · 审阅普通连拍分组候选（P1，NB03 建议）

- SG01：按当前项目/会话或显式选择范围启动；默认不分析全库、不随导入自动启动，扫描尚未完成的会话须提示范围不完整。
- SG02：候选与正式组分离；只有“确认分组”才写正式组。忽略的相同候选不在输入未变时反复提示。
- SG03：保留原始 EXIF 时间字符串、亚秒、偏移、相机来源和顺序依据；缺少亚秒/偏移或多机位来源不明时降为未知或时间邻近候选，不静默用文件修改时间当拍摄时间。
- SG04：先用保守时间窗口提出相邻候选，再按方向归一的低分辨率预览比较画面；完全重复仍由完整内容哈希判断，相似不等于重复。
- SG05：默认同项目、同会话、同可确认相机来源内识别；不跨会话自动拼组。只有机型名称不足以证明同一台相机，多机位不明时须用户指定范围。
- SG06：候选保存输入版本、成员、理由、参数和算法版本；没有预览或分析失败显示证据不足，不归为废片。没有校准依据的相似度分数不显示成置信概率。
- SG07：用户可预览并纠正成员、类型，拆分/合并候选或忽略；确认后默认锁定，原有人工组不被替换。重叠资产的影响必须显式展示。
- SG08：后台结果不移动当前照片、不改变决定、评分或序列参与。输入改变时旧结果过期；取消后不得再提交旧候选。
- SG09：后台任务可取消、可重试，重启保留已提交候选与确认状态；未完成计算不伪装为已完整识别。

验收：明确连拍边界、同秒独立画面、长暂停、缺时间、乱序/时钟回拨、多机位不明、方向混合、坏预览、范围增减、重复运行、取消后晚回调、人工纠正后重算、与已有组重叠。真实样本只承诺通过的机型/模式，未知范围保持保守。

## 不包含与后续出口

本批不交付：清晰度/曝光自动裁决、传感器 RAW 饱和判断、自动排除、RAW+JPEG 自动成套交付、完整跨次运行历史、独立备份管理、服务器/同步、Lightroom 或显影。

M2b 输入：本批得到可纠正的组、可信元数据、受保护用途及性能底座。后续质量证据必须记录像素来源和算法版本、建立分层留出样本；自动排除仍需单独影子评估与批准。

## 成功标准与批准门

- SC01：三档主题验收矩阵中没有状态重置或图片重解码；正常窗口/弹窗的两套视觉检查通过。
- SC02：恢复测试中错内容成功匹配数为 0；所有成功匹配的身份和人工决定不变；失败逐项可见。
- SC03：组修改/补偿场景无静默覆盖；候选计算产生的照片决定变化数为 0。
- SC04：真实连拍标注试评估报告相邻帧同组 precision / recall、未知覆盖和纠正耗时；初始建议目标为 precision ≥95%，需在开发集确定规则并冻结后用独立留出集评估。不能靠全部输出未知达到目标；同时报告覆盖量、样本量及误并组。
- SC05：若现有样本不能组成开发/留出两部分，或达不到 SC04，B2 只能提交人工组功能与失败评估，不能宣称分组建议验收完成；与用户确认补样本或收窄范围。
- SC06：沿用 002 的现有性能门槛并增加后台运行组合；本机高配不代表低配验收。新主题应用状态提交拟定 p95 ≤100 ms，不等同屏幕呈现时间，批准后先测基线。

SC04 计量口径：对留出拍摄片段中已人工标注的相邻帧对，统计“系统建议同组”的 precision 和“真实同组边界被识别”的 recall；未知/证据不足另报占全部范围的比例，不能通过不产出任何候选算作通过。同时逐组列出误并事件、样本数量和纠正耗时；小样本结果不推断所有相机/场景。开发集与留出集按整组或拍摄片段划分，避免相邻帧泄漏。

用户确认范围、默认设置和图标系统边界后，才可将状态改为 Approved 并启动技术验证或实现。
