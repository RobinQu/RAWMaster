# 一个照片的多种修法

本轮把日常调整、回滚与旧结果查看分开。打开编辑后直接调整当前照片，Quick Prompt 处理 AI 编辑。「快照」标题的更多菜单提供「已有编辑结果…」，可找回原图、旧候选与归档成片。切换色彩外观只修改当前编辑。虚拟副本是下一阶段的资料库设计。

## 历史、快照与已保存结果各自解决什么问题

| 摄影师要完成的操作 | 合适的入口和身份 |
| --- | --- |
| 撤销刚才的调整，沿同一次编辑前后走 | 历史。它属于当前照片的这条编辑分支，有容量限制。 |
| 为一个可恢复的修图状态命名，之后从这里继续 | 快照。恢复快照写入一条普通历史记录。现有命名快照按来源和分支存在会话内存中，重启后的长期保留需要目录存储。 |
| 找回以前已保存的候选、已采用的 AI 成片或外部软件的编辑结果 | 已有编辑结果。旧配方、归档像素和来源关系分别保存。生成结果可能含独立像素，单靠参数快照无法重建。 |
| 把同张原片的彩色、黑白两种修法并排选中、分别编辑和交付 | 建议新增资料库虚拟副本。每份副本有独立选片和编辑身份，指向同一物理源文件。 |
| 稳定运行队列作业并核对成片 | 提交时冻结来源、配方或归档像素、输出参数与摘要。编辑期间继续调整，不会改变已提交作业。 |

现有会话与存储边界可从 [编辑会话](../../Sources/RAWMaster/EditingDevelopmentSession.swift)、[撤销历史](../../Sources/RAWMaster/DevelopmentUndoHistory.swift)、[作品与已存结果](../../Sources/RAWMasterCore/LibraryStore+Editing.swift) 和 [工作台交付](../../Sources/RAWMaster/WorkbenchPhotoExport.swift) 核对。

## 资料库虚拟副本设计

Lightroom Classic 将虚拟副本的不同调整保存在目录中，网格和胶片条可单独选择每份副本。命名快照仍属于其所在照片的编辑过程。RAWMaster 的常见双交付场景可以沿用这个边界。[Adobe 虚拟副本说明](https://helpx.adobe.com/lightroom-classic/desktop/manage-catalogs-and-files/photos.html) · [Adobe 的快照与历史说明](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/develop-module-options.html)

- 在资料库选中一张照片，从菜单创建虚拟副本。副本从当时编辑状态开始，缩略图显示副本名，可与原照片并排比较。切换副本分别恢复其调整、快照与历史。一个副本的后续调整只影响本份呈现。
- 源文件沿用现有 asset 身份，另设独立的副本身份。当前资料库按导入会话和文件路径去重，导出选区按 asset ID 汇总；两处都需要让可选的呈现身份与物理源身份分别传递。仅复制一条相同路径的素材记录会与去重、堆栈、重连和队列选区冲突。
- 一次选择原片呈现和黑白副本，032 应收到两个输入。每项分别冻结副本 ID、当前修订、原片摘要或归档像素摘要。导出命名使用可读的副本名，并按已有重名策略处理；副本继续编辑后，已提交的两项仍能各自回放。
- 「移除副本」只移除它的资料库呈现。移动或找回一次源文件后，引用同一来源的副本一起恢复。AI 与外部编辑结果保留各自的归档字节，必要时可从指定结果显式建立副本。保留旧结果的原始 ID，使历史批次和已交付文件继续能追溯到当时的输入。

进入实现前，先让命名快照按编辑身份持久化并验证重开。再验收同源两份调整可独立选择、单独回滚、同时交付、源文件离线重连和移除单份副本。既有库采用显式建立副本，避免首次升级时把所有历史中间态铺满网格。
