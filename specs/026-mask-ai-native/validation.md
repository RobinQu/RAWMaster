# 026 · 原生验证结果与合并决策

## 判定

**独立原生验证通过（有限范围）；不建议直接合并当前实验包。** Camera Raw 的六类自动创建入口均有原生实现和真实模型执行证据，但 Snow、负点精修、复杂人物场景和资源管理仍存在明确限制。可以进入下一阶段的是“独立 Mask AI 服务＋按需模型加载＋已确认快照”的合并设计，而不是把当前全局 session 和全部模型直接接入主 App。

最终命令为 `/usr/bin/time -l env MASK_AI_MODEL_TESTS=1 swift test`。结果为 **13 项测试、0 失败**，其中 8 项离线单元测试和 5 组真实模型集成测试；共记录 **28 条模型输出**。完整套件约 35.9 秒，进程最大 RSS 为 2,951,708,672 字节（约 **2.75 GiB**）。该值是整套测试连续加载模型的高水位，不是单模型或 RAWMaster 当前内存占用。[结构化结果](../../experiments/MaskAI/Validation/results.json) [完整日志](../../experiments/MaskAI/Validation/full-suite.log)

## 缓存与性能证据

| 路径 | 首次／首次相关调用 | 后续复用 | 结论 |
| --- | ---: | ---: | --- |
| EfficientViT 场景分析 | Sky 约 1.04 秒 | 其他风景目标约 0.29–0.30 秒 | 同一山景的七类 ADE20K 目标只推理一次；缓存机制有效 |
| SlimSAM 点／框 | 点选约 1.60 秒，包含首次 encoder | 框选约 0.50 秒 | 同图 prompt 共用一次 encoder；decoder 次数符合预期 |
| 人物 All | 指定球员约 1.85 秒 | 15 个候选的 All 约 9.72 秒 | All 不是简单复制；多人物成本随实例数增长，需要批量调度与上限 |
| 整套验证 | 约 35.9 秒 | 最大 RSS 约 2.75 GiB | 不应让所有模型在 RAWMaster 中无限期常驻 |

这些耗时包含各自调用边界中的预处理、后处理和当前测试进程状态，不是纯模型 kernel 时间，也不是与 Camera Raw 的同口径性能比较。没有进行 Core ML EP 加速对比，不能据此承诺 Neural Engine 性能。

## 实际发现并修复的兼容问题

1. **SlimSAM FP16 原生图优化失败**：ORT 1.27.0 在 LayerNorm 融合初始化时报错。改用 Lightflow CPU 路径对应的 Q8 encoder／decoder 后正常执行。
2. **Q8 decoder 接口不同**：实际需要 `input_points`、`input_labels`、`image_embeddings` 和 `image_positional_embeddings`；点与标签使用带 prompt batch 维度的 rank 4／rank 3 输入。
3. **YuNet 输出结构不同**：原生模型输出 `bbox_*`、`cls_*`、`obj_*`，不是合并的 `loc_*`；解码器已按真实接口修正。
4. **纯框语义失败**：三个初始候选都未正确锁定汽车。框中心正点是实测驱动的补偿，不是可隐藏的内部细节。
5. **负点并非天然可靠修正**：当前样本产生局部掩码，需要候选 UI、更多 prompt 和后处理策略，而非强行接受最高 IoU 就宣称正确。

## 合并决策

### 可以进入合并设计的内容

- 独立 `RAWMasterMaskAI` 目标及明确的 provider／model adapter 边界。
- IS-Net 主体／背景作为 Vision 的可选 A/B 路径，而非未经验证直接替换 Vision。
- EfficientViT 一次场景分析派生多类目标，以及 SlimSAM encoder 按照片缓存。
- SlimSAM 点选与“框＋中心正点”的矩形工作流，保留三候选和人工修正入口。
- 人物检测、整人和基础部位的分层管线；五官使用独立 landmark 精度资格。
- 语义描述、模型哈希、源绑定和**已确认快照**，渲染／导出不得每次重推理。

### 当前不应合并的内容

- 不合并整套实验 session 生命周期、全局常驻模型或测试下载脚本作为生产实现。
- 不把 Snow 启发式标为 Camera Raw 等价 AI；不把未经补偿的纯框路径恢复为默认。
- 不把当前负点结果、闭嘴 Teeth 空结果或本次人物样本外推为普遍质量资格。
- 不在主渲染线程同步执行模型，也不在导出时隐式下载或重新推理。
- 不合并 fixture、实验 PNG 或验证构建产物到应用包。

## 合并前下一阶段门禁

1. 用真实 RAW 的中性、定向、显示参考显影输入验证主体、风景和人物；覆盖竖拍、裁切、多主体、发丝、树叶和低对比边缘。
2. 为每个模型测量独立冷加载、暖推理、峰值常驻和释放后内存；制定单模型／当前照片／后台预取预算。
3. 验证取消、切换照片、模型缺失、下载失败、设备／EP 失败和晚到结果隔离。
4. 进行 Core ML 转换或 Core ML EP 小规模 spike，并以当前 ONNX 输出做数值对照；不能假定转换后自动更快或更准。
5. 为负点、框中心补偿、Snow 和人物五官建立专门正负样本；失败时允许回退到画笔，不显示虚假成功。
6. 先提交合并设计 spec 和接口审查，再修改 RAWMaster 主 Package；保持本独立模块可重复验证。
