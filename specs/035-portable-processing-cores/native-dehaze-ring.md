# 原生正向去雾的环形行缓冲试验

在 9504×6336 和 8640×5760 的两张 RAW 上，冷态去雾会先用五级整数最小值构建引导图。先前的实现每次处理 64 行，重复计算相邻分带共有的边缘行。这次试验让每一级的中间行只计算一次，保留原有九个采样点、半浮点位模式、引导图及显示流程。[测量和原始回执](evidence/native-dehaze-ring.json)

## 调度和发布

每一级的输出覆盖原片，以及后续各级仍需读取的边缘。设一带为 64 行，下一层最大纵向偏移为 `d`。前一层保留 `64 + 2d` 行足以覆盖这带所有读取。四级中间纹理按绝对行号取模，最后一级写入完整纹理。只有读取原始像素时才将坐标夹到图边。两张 RAW 都从绝对行 −192 开始填充上边缘，每次实际读写前核对区间连续性和上一级仍保有的行。

同一条 Metal 命令队列每次最多编码四带，五级之间使用独立计算编码器和 Metal 跟踪的纹理。每一级为带内每个 16×16 工作组保留独立计数，末行和右边缘按真实像素数校验。第一层同时对原纹理的零偏移样本检查 RGB 范围和不透明度。所有提交完成、各级计数和末行齐全，并再次确认原件及任务有效后，引导图才能进入缓存。

启用 `RAWMASTER_QA_NATIVE_DEHAZE_RING_EROSION=1`，并同时开启已验证的 `RAWMASTER_QA_NATIVE_DEHAZE_HALF_EROSION=1` 与 `RAWMASTER_QA_NATIVE_DEHAZE_GROUPED_EROSION=1`。资格沿用 macOS 27.0.1、Apple M4 Max、现有两种尺寸、正向去雾、已验证的 FlashRaw031 私有不透明原始纹理及内存条件。新缓存身份以 `-ring64-v1` 结尾。首个提交前的资源不足可选择原有引导图路径；已经提交过的设备或写入失败会中止该请求。授权撤销始终中止。

## 两张实拍原片

| 指标 | 9504×6336 | 8640×5760 |
| --- | ---: | ---: |
| 五级实际写入的像素数 | 773,490,168 → 308,944,296 | 594,994,320 → 255,161,704 |
| 最小值阶段持有的字节数 | 518,340,608 → 520,486,912 | 430,080,000 → 429,686,784 |
| 提交并等待完成的命令数 | 25 → 26 | 23 → 24 |
| GPU 完成区间合计，中位数 | 33.97 → 17.90 ms | 27.73 → 16.08 ms |
| 含提交、等待、计数核验的循环，中位数 | 57.13 → 41.99 ms | 48.10 → 36.34 ms |
| 冷引导图获取加半幅显示读回，中位数 | 268.60 → 255.94 ms | 225.50 → 218.46 ms |

表中时钟来自两轮顺序相反的独立进程，每种实现对每张原片运行四次。主片旧实现的第一个进程额外花费约 97 ms 初始化运行时。次片第一次对照中，新方案的冷引导图获取较慢；第二次反序运行时两次都较快。只改变去雾强度的热态会复用原引导图。[逐次计时及素材指纹](evidence/native-dehaze-ring.json)

双方完整 RGBA16F 最小图各通道和逐带摘要相同。紧凑 R32F 引导图分别比较了 60,217,344 和 49,766,400 个值，差异为零。强度 15、45 的全幅线性 RGBAf、原 FIT 和现行半幅路径得到的 2400×1600 sRGB8 也全部一致。原始 256 行 Gaussian 渲染的几何、工作色域及采样方式沿用现有实现。[完整浮点和显示摘要](evidence/native-dehaze-ring.json)

独立探针分别漏写循环纹理的一行与最后一行，另在首次提交的 Metal 命令仍处于已提交状态时关闭真实请求，以及在第二次提交后取消。四次请求都排空已提交命令并拒绝发布；同进程随后重新处理同一原图，完成了全部 99 或 90 个最终分带。[故障与重试](evidence/native-dehaze-ring.json)

用生产调度和原版 Metal 源重复上述两图的完整数值核验，并额外注入首投递前撤销、首命令部分编码时失去编码器、已有提交后再失去编码器。七项故障对应已提交并等待的命令数为 0、0、1、1、1、2、24；每项随后均能重试。此轮与 Release 编译并行，只用于检验输出和生命周期。[生产调度的全部故障回执](evidence/native-dehaze-ring.json)


## 正常编辑服务

Batch30 封存程序在两张 RAW 上各按关、开、开、关重放完整的 37 个控件，每种开关和原片各有两个进程。全套 1,184 个互动及定稿画面摘要相同。四个开启试验的冷去雾状态均出现环形阶段，强度 45 的热态全部复用引导图。两张 RAW 的去雾配方均无局部编辑；同时切换的局部蒙版实验在这些去雾状态中没有执行。[正常入口原始读回和全套对照](evidence/native-dehaze-ring.json)

| 正常预览时钟，中位数 | 9504×6336 | 8640×5760 |
| --- | ---: | ---: |
| 去雾最小值阶段 | 65.06 → 53.28 ms | 58.49 → 43.07 ms |
| 冷态完整定稿 | 301.94 → 326.98 ms | 248.93 → 236.19 ms |
| 热态完整定稿 | 38.31 → 37.48 ms | 36.70 → 36.53 ms |

环形调度缩短了两张原片的最小值阶段。主片的两次冷态完整定稿分别为 351.30、302.66 ms，对照为 302.09、301.79 ms；本轮保留默认关闭。封存测试包中三项去雾资格、工作组回执和两尺寸布局测试全过。[逐轮数据和测试包指纹](evidence/native-dehaze-ring.json)

## 复核入口

`DevelopmentNativeDehazeErosionTests` 在支持的设备上逐段验证两种实际尺寸的行区间、四级环长度、总写入数、工作组回签到最后一行，以及资源预留。可从仓库根目录运行。

```sh
swift test -c release -Xswiftc -enable-testing --filter DevelopmentNativeDehazeErosionTests
```

实拍复核使用同一 Release 链接的 `scripts/performance/profile-settled-photo.swift`，传入原 ARW、含 `effects-dehaze` 配方及已知完整显示摘要的归档 JSON、输出 JSON 路径和 `effects-dehaze`。对同一源在新进程中只切换环形实验旗。第一档 `NativeDehazeHalfErosion` 事件可区分两种实现，第二档应复用完整引导图，两个定稿的完整摘要都应与归档相同。结构化证据记录了采集命令、运行时间、源文件和二进制指纹。[正常预览服务采集程序](../../scripts/performance/profile-settled-photo.swift) [结构化证据](evidence/native-dehaze-ring.json)
