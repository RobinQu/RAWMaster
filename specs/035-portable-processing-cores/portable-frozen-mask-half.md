# 冻结径向蒙版的定稿预览

编辑工作台中，用户调整单个径向蒙版的曝光、高光、阴影、白色、黑色、对比度、饱和度或色相，松开控件后产生一张精确定稿。实验开关 `RAWMASTER_QA_PORTABLE_MASK_HALF_FIT=1` 允许常规主画布将这一帧交给可移植 Rust 图执行。原始 RAW 和配方保持可重放，服务端使用同一个 `mask_tone_v3` 节点和具名覆盖契约。[节点定义](portable-local-mask-tone.md)

## 定稿的输入与所有权

宿主要求 FlashRaw 0.3.1 原尺寸、EXIF 方向 1、无额外 RAW 调整、普通画幅和单个有效径向层。该层须为零羽化、完全不透明、正向选择且仅一个上述控件非零。当前硬件资格为 Apple M4 Max、512 MiB 的 Core Image 上下文、实测的 9504×6336 或 8640×5760 原片，输出为 2400×1600。精细色相、多层或全局混合调整、交互拖动与比较画面沿现有显影路径执行。工作线程核对快照文件和原始不透明 RGBA16F 纹理的持有凭据。Core Image 的全图须符合已测的采样计划，且最后一层生成的对象与待物化对象相同。[宿主资格](../../Sources/RAWMasterImaging/PreviewNativeSource.swift) · [图像对象和输出计划](../../Sources/RAWMasterImaging/PreviewCanonicalHalfFIT.swift)

原生蒙版算子先将原尺寸覆盖写入单通道私有 R32Float 纹理。零羽化时，两张实测照片的覆盖仍分别有 366 和 363 个介于 0 和 1 之间的像素。宿主保留这些 Float32 值及其原坐标，为每次请求重新冻结覆盖。Rust 接收同一设备上的原始 RGBA16F、与图中名称一致的具名覆盖和独占 RGBA32F 半幅输出。每个原始像素都经过核验。零覆盖保留原像素，其余像素按原图顺序执行局部控件。每条 256 行带写完原生 Float32 后，用硬件线性采样形成半幅，最多四带共用一次提交。最后复用原 FIT 色彩和显示转换。[冻结覆盖](../../Sources/RAWMasterImaging/PreviewPortableMaskTone.swift) · [原生 ABI](../../Modules/ImageEdit/include/rawmaster_image_metal.h) · [Rust 实现](../../Modules/ImageEdit/src/gpu/metal_surface/native_half.rs)

宿主同时预留整个覆盖、半幅和带缓冲。主片上限共 533,692,416 字节，次片为 448,462,848 字节，并检查最终显示所需的设备余量。输出及覆盖初始化命令、Core Image 生成任务、Rust 已提交的命令均等待完成。撤销或文件失效会丢弃本次私有输出。加载旧运行库时，在提交覆盖任务之前回到原来的 Core Image 路径。能力开关默认关闭。[预留、撤销与回退](../../Sources/RAWMasterImaging/PreviewPortableHalfFIT.swift)

## 完整像素对照

两张原片各取八个控件的两个归档状态。独立诊断运行库保留 Rust 同一生产者写出的真实原生带，读出四通道 Float32，与原 Core Image 的完整原生结果逐位比较。再核对硬件采样后的整张半幅，以及原工作台实际归档的整张 sRGB8。32 个状态的三个检查层均逐位相同，合计覆盖 1,759,739,904 个原生像素与 439,934,976 个半幅像素。诊断中的临时全图和分段计时在独立进程完成。该次测量中，首次主片对照有一整带差异，改用独立原生对照上下文并显式初始化临时纹理后，两张原片所有位置通过。原报告保存在复现包内。[逐片位数、SHA-256 和失败对照](evidence/portable-frozen-mask-half.json) · [完整源码及原始回执](evidence/portable-frozen-mask-half-sources.tar.gz)

公开 C 接口以错误返回拒绝覆盖名不匹配、误将彩色源作为覆盖、未写入的 NaN 覆盖，以及首组提交后撤销的请求。相同程序在新请求中重试，两档曝光均复现归档。正式宿主另有原位撤销、重试、丢弃原图凭据和配方资格的回归。[原生回归](../../Tests/RAWMasterImagingTests/PreviewPortableHalfFITTests.swift)

## 应用内耗时与交付范围

封存 Release 的同一编辑服务对两张照片依次运行关闭、开启、开启、关闭四轮。每轮每张照片包含 37 个操作、各两个状态，并分别请求交互和定稿，共 1,184 帧。所有交互与定稿的像素摘要和近似标记跨轮相同，592 次定稿另外核对了原归档。实验路径在符合资格的 64 次定稿全部命中。其它请求沿各自的原路径执行。[逐状态、逐轮回执](evidence/portable-frozen-mask-half.json)

| 完整 2400×1600 定稿含显示读回 | 关闭 P50 | 开启 P50 | 关闭 P95 | 开启 P95 |
| --- | ---: | ---: | ---: | ---: |
| 9504×6336 原片，八控件 | 49.97 ms | 60.15 ms | 79.74 ms | 85.96 ms |
| 8640×5760 原片，八控件 | 51.44 ms | 55.72 ms | 85.02 ms | 78.41 ms |

每个表格单元采用同一照片、同一开关下的 32 次目标定稿。另一项去雾实验随同开关，其命中的是单独的去雾配方。冻结覆盖、生成半幅并等待 GPU 完成这一段，主、次片的中位分别为 42.11 和 36.96 ms。两张照片的定稿中位均升高，功能保留作默认关闭的 Metal 接入验证。更换为 Batch 29 和 Batch 19b 旧运行库后，同一 Swift 程序在两个库上各输出四张正确的色相及曝光定稿，并保留原有限值检查。[运行库指纹与回退结果](evidence/portable-frozen-mask-half.json)
