# 033 · 资料库前三阶段技术实施方案

2026-11-22 · 经确认的技术方案。以 **Rust 目录内核、SQLite 本地事务、可重建的搜索索引** 为主线。Swift 保留原生界面，既有成像管线继续提供像素和渲染。先用现有库跑通迁移、分页和恢复，再接入 Lightroom、分组制作与智能查找。Server 后续单独立项。本轮已执行的研究和原型列在[验证记录](validation.md)，接入产品的完成情况见[任务清单](tasks.md)和[交付验收](delivery-validation.md)。

## 一 · 目录与导入基础

1. **从实际网格换读路径。** 当前刷新读取整库快照，选片与浏览仍使用 Swift 内存对象。先从同一份已提交的目录快照建立可删除的 `search.sqlite`，对新旧查询逐页比较有序 ID、数量和分项，再让资料库网格、项目和集合通过同一个分页接口取卡片。首批 60 项，只按可见范围装载缩略图。批量操作冻结查询修订、明确选中范围，执行时复核资格。v7 先在固定快照上对读。待新增、改分、移出、删除等写入都有可重放的事务序号，且分页、滚动、反向排序、多选全部通过对账，再把在线网格切到新读路径。[实际读取](../../Sources/RAWMaster/LibrarySnapshot.swift) · [现有过滤](../../Sources/RAWMasterCore/AssetSearchEngine.swift) · [实测](validation.md)
2. **迁移写入所有权。** Rust 经窄 C ABI 提供只读查询，先在副本中影子对读。然后随正式 schema 升级将一次业务命令的全部写入交给一个事务所有者。现有 Swift `LibraryStore` 先作适配层，逐项接入。任一时点每个写入域只有一个入口。正式切换前核对已有配对、项目纳入、成员顺序、编辑、外置盘定位和操作历史。升级中断可使用迁移前快照和操作记录恢复。[升级契约](data-model.md) · [现有升级校验](../../Sources/RAWMasterCore/DatabaseSchema.swift)
3. **完成一次导入。** 探测来源、逐文件核验，再做候选配对，将同拍的 RAW 与机内 JPEG 折叠后判序列。相机身份、子秒或帧号相冲突的候选进入复核。晚到的伴随文件可在新会话补配。人工拆配、改序或锁组随修订保存。暂停／崩溃可续接，完成事务一次写入逐文件结果及归档资格，随后只读。同一命令重试取回原收据，二次导入创建新会话。导入排除原件不进入完整备份，仍排除的必要帧只显示缺口。[封存与五文件算例](spec.md#每个导入原件的归档资格) · [初筛工作流](../006-import-triage-workflow/spec.md)
4. **搬动资料库和原件。** 默认由应用创建并命名资料库。用户可选搬迁为库包，外置卷以卷与根的身份及相对位置重连。目录与编辑资料先取一致快照，完整备份再按该代有效逐文件清单复制并校验。恢复先在新位置打开，显示只恢复了目录的条目和实际可用的原件。目标完成核验后再切换当前库。同名、跨卷、唯一副本、已排除配对成员和断点重启分别验收。

**阶段出口。** 用当前 v7 目录副本比较全部查询 ID 和已迁实体关系，在挂载、离线、重连三种状态打开当前照片。用现有六张 RAW 重跑导入并在写入期间操作网格，测从输入到首屏绘制的 P50/P95、首屏卡片数、峰值 RSS 及索引增长。温态常用结构化筛选可见首屏 P95 的目标为 300 ms。杀进程后复核封存、索引续建、备份恢复和命令幂等。本轮已测 SQL、单独读取快照及四轮实拍导入期间的同库查询。分页接入后在真实窗口补测输入到绘制。[测量口径](validation.md)

## 二 · 日常管理与 Lightroom 单向迁入

| 交付单元 | 实施顺序与验收 |
| --- | --- |
| 文件、作品与集合 | 先建立卷、文件夹、作品版本与原件的关系，再实现批量重连、受管文件和旁车的移动／改名、普通集合、集合组、手动排序及规则集合。堆栈记录文件夹或集合的作用域、顺序与封面。虚拟副本可单独入集合、评分和保存外观。卷离线时仍可浏览元数据，移动部分失败可按操作清单恢复。[文件模型](data-model.md) |
| 元数据和检查器 | 在网格、单张与 Survey 共用的检查器中显示 EXIF、来源明确的 RGB 直方图、IPTC、多选共有／混合值。相机 AF 点需有机型、坐标系和方向依据，往返旋转／裁切后对准同一主体。连拍先用相同倍率的 AF／主体区域比较局部清晰度，保存亮度、纹理和运动模糊的证据。证据不足时返回未知。人工纠正独立保存，失焦照可正常纳入。六张现有 ARW 可提供 Sony AF 字段。判断准确度需经人工标注的连拍验证。[检查器和清晰度验收](search.md) |
| 常规检索 | 文件名子串、IPTC、关键词与文字标签使用文本索引，日期、星级、机身、镜头、状态等用类型化谓词。作用域、复合条件、分项计数和智能集合共享同一规则树。展开一个 RAW+JPEG 拍摄时，应显示具体命中的文件。保存规则后修改一张照片的评分并重开，结果应反映本次修改。[查询语义](data-model.md) |
| Lightroom 迁移 | 用只读的 `.lrcat` 一致副本预检 schema。盘点 `.lrcat-data`、XMP／ACR、预览和离线卷。按源目录身份、源对象和类型建立账本。先建文件、主片与虚拟副本，再落集合、堆栈、关键词、元数据及每个版本的外观。保留智能集合原规则，说明其在源目录中能否取得成员快照。专有显影载荷和依赖逐字节封存并校验摘要。重复导入和中途重启必须保持目标关系唯一，已有人工编辑单独继承。[单向迁移契约](lightroom-migration.md) · [五份目录实测](validation.md) |

**阶段出口。** 五份现有 Lightroom 目录逐个输出组织关系、元数据、历史外观三张对账表。一个虚拟副本即一行独立的外观结论。缓存候选、可解码、可绑定源修订和缺失分别统计。源记录缺失或不支持的规则保留原值和理由。源盘断开后核对封存字节、渲染外观、任务恢复和两份虚拟副本的独立编辑。

## 三 · 分组制作与智能检索

**制作顺序为延时、星轨、多曝光 HDR、全景。** 在现有编辑视图增加分组状态，默认列出当时的全部拍摄，继承已明确停用的成员。提交时冻结顺序、每个实际输入文件和内容版本、替代 JPEG 或缺帧的处置。先接现有延时渲染器，将成功读回的 MP4 登记作可检索的派生作品。随后引入其余三种算子。对每种输出保存源组修订和有序输入，从作品可回到源帧，从源组可看到各次结果。取消、崩溃续作与重试不得重复登记。单张与分组共用作品关系和任务记录，独立保存各自配方。[制作专项与实拍探针](group-processing-research.md) · [现有分组规格](../015-group-editing/spec.md)

| 检索能力 | 首个可交付版本 | 接入条件 |
| --- | --- | --- |
| GPS 围栏 | WGS84 原值与修订保存在权威目录。R-tree 选包围盒候选，圆按球面距离、多边形按约定的边与边界规则精判。跨 180° 拆候选窗。空坐标可独立筛出。保存的围栏与其他过滤共用候选范围 | 最大 Lightroom 样本的 10,960 个有效坐标上，索引结果与穷举逐 ID 相等。进入产品前补跨经线、极区、凹多边形、边界及人工改坐标的回归。[空间基线](validation.md) |
| 中文按画面找图 | 先用 SigLIP2 B/16 多语模型与精确余弦排序，以 Chinese-CLIP B/16 作对照。索引记录照片／作品、输入版本、像素来源、模型与预处理版本。先限定作用域，再对有向量的候选打分并报告覆盖。任务在本机可暂停或重建 | 实验量化模型与可分发原权重的转换结果需对照。在不同拍摄组留出集评中文复杂描述、无关查询及负例，再定默认模型和分数策略。当前 1,265 个代理的实测支持先用精确检索。[模型选型与证据](retrieval-research.md) |
| 人物 | 库所有者开启后检测、五点对齐、编码。保守聚类作为待确认建议。命名、合并、拆分、拒绝误配为人工记录。过滤“已确认人物”只读取实际确认的对应关系。关停扫描可单独清除机器特征 | YuNet、SFace 已在现有照片跑通。提高检测分辨率的收益需与算力、误框一起复测。跨相机、跨日以及易混淆人物需独立标注。将误并数、漏检及未知分别报告。[人物实验](retrieval-research.md) |

**阶段出口。** 回库的成片保留全部实际输入，移走外部导出件后仍能打开或明确报告受管内容缺项。组合查询“围栏内、已确认人物、四星以上，再按画面描述排序”须逐个通过硬条件。过期向量、被移出范围的照片、导入历史均不能出现在当前结果。重新分析后维持人工命名和纠错。[智能检索验收](search.md)

## 需审阅的取舍

- SQLite 继续承担桌面目录事务。Rust 先接只读查询再接单写入口，C++ 通过 C ABI 接成像算子。现有 Swift 代码和已存数据按调用路径迁移，便于逐段核对。[语言与存储依据](research.md)
- 文本检索、中文文搜图和人脸使用三种索引。建议第一版以精确向量排序作为可核查的参照。默认权重、阈值及人脸自动聚类的开放范围须以独立标注和可分发制品决定。[检索与人脸实验](retrieval-research.md)
- 阶段一至三只固定跨平台数据身份、版本、幂等操作及本地作业描述。后续可用同一份资料库数据验证 Linux 执行器和新旧客户端兼容。服务端数据库、网络协议、部署与调度留给阶段四。[本地兼容设计](data-model.md)
