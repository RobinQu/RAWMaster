2026-11-22 · 前三阶段的本地持久化和内核接口提案。表中的名称表示逻辑实体，正式迁移时再确定物理表名与 schema 编号。[产品约束](spec.md) · [实施方案](plan.md)

## 权威记录

| 对象 | 稳定键与关系 | 不变量 |
| --- | --- | --- |
| 资料库、挂载根、文件夹及位置 | 库有独立 `libraryID`。卷／根、文件夹及副本各有 ID。副本记录内容版本、受管／引用、卷、相对路径、最后核验时间与状态。macOS 书签保存在本设备 | 换盘和移动库包仍能解析同一业务身份。离线卷不等于照片删除。一次不完整扫描不能将其余文件判缺失。重定位先列候选，再查完整长度和摘要 |
| 拍摄、文件、内容版本 | `captureID` 表达一次快门。逻辑文件 `fileID` 承载 RAW、机内 JPEG 等角色，`contentVersionID` 固定某次内容及摘要算法、完整哈希、长度。文件可以有多个位置。保留配对证据、来源和人工锁定 | 改名或路径变化保持文件身份。相同字节可复用已核验内容，各次出现、拍摄归属、项目选择和作品引用均可追溯。JPEG 代理在独立的派生记录中标明其输入和渲染方式 |
| 导入出现、处置与项目纳入 | `sessionID + occurrenceID` 记录某批发现的文件、来源根、当次核验及封存处置。项目和文件通过多对多纳入事件连接。角色含普通与明确选择的仅序列用途。恢复纳入另带来源和核验记录 | 同一文件第二次导入可有新项目和新出现。已封存的决定保持只读，恢复追加事件。按有效纳入逐文件生成归档引用。最终排除项仅保留历史。相同内容另有有效引用时，按有效引用计一次对象覆盖 |
| 拍摄组与有序成员 | `groupID + revision` 对应一份成员顺序。成员引用拍摄、位置、参与状态，保留各文件参与例外、推断证据和用户覆盖 | 同一拍摄可参加多个组。RAW+JPEG 在一个制作任务里只计一帧。可追溯历史次序、同拍文件选择和缺帧。重新推断先发布建议，人工拆配／锁组和已冻结作业继续有效 |
| 作品、版本、集合与堆栈 | `workID + versionID` 表达照片、虚拟副本或派生照片／视频。版本引用源拍摄或输入和配方。集合成员指向相应作品／版本，集合组保存树。堆栈单独保存文件夹或集合范围和位置 | 虚拟副本共享原件，独立保留名称、集合、编辑与历史外观。相同照片在不同集合的堆栈顺序可不同。Adobe 的已有堆栈和按拍摄证据识别的序列可并存 |
| 外部来源映射、元数据与历史外观 | 以源目录稳定身份、对象类型、源对象 ID 定位，另记快照摘要、版本与迁移批次。元数据保留原值、单位、提取器、人工修订和有效值。外观绑定源图像／虚拟副本、修订依据、分辨率及内容摘要。Adobe 载荷以原始字节或原容器关联 | 同一目录的新快照可增量对账，同名图片和复制的目录都要显式核实归属。重复迁入同一源对象与修订不重复生成关系。无法证明外观对应修订时保留其来源和不确定性。依赖目录、侧车及必要外观可逐对象校验 |
| 人物与机器观察 | 检测框使用定向原始坐标与输入版本。机器候选记录模型、五点和置信度。人物 ID、命名、确认、拒配、合并、拆分和人工清晰度结论作为用户记录 | 向量重建或照片换代理时可重新检测。用内容、区域与旧观察对齐，出现歧义待复核。人工纠错、人物 ID 和作品历史不随索引重建消失 |

## 从 v7 安全切换

1. 当前的 `assets` 内含会话和项目，`project_admissions` 用 `asset_id` 作键，组成员用文件 ID。读取 v7 前先走现有只读结构验证。该验证有表、列和索引清单并拒绝未知视图／触发器。研究版投影单独建库。正式上线时扩展正式迁移器及支持版本，再添加权威记录。[现有 schema 校验](../../Sources/RAWMasterCore/DatabaseSchema.swift) · [既有纳入模型](../../Sources/RAWMasterCore/TriageModels.swift) · [既有资产与成员](../../Sources/RAWMasterCore/Models.swift)
2. 在已提交事务的一致切面制作备份，保存 schema、操作水位和清单摘要并做完整性检查。在私有副本升级，导入旧文件 ID 映射、会话、来源路径、可核验的摘要、项目纳入、配对和成员。尚未配对的文件先有单文件拍摄。已确认配对映射至同一拍摄。保存组内首现顺序、旧文件级参与例外及冲突。离线文件保留待核验状态，升级可在外置盘未挂载时完成。
3. 旧版的序列保护可能自动纳入仍为排除的文件。保留其编辑及组关系，将已有逐文件终态用于判定归档，缺乏明确纳入依据时标注待对账。以现有档案清单和五文件场景复核。迁移报告逐域统计数量、差异和无法无损处理的记录。校验后经短暂写入屏障切换至新库，重新打开并核对。不覆盖迁移前备份。
4. 写入切换前可回到旧库。切换后如已有新写入，先保全新版快照和操作日志。仅在验证过的回放或导出能保留新操作时回退。旧客户端先校验格式／最低写入版本，遇到更高版本须安全退出或进入受支持的只读路径。数据库版本、交换载荷版本、索引代次和模型版本各自演进。[SQLite 一致备份](https://www.sqlite.org/backup.html)

## 查询、后台索引与范围

- 查询描述包含库和范围、对象层级、已纳入可见性、带单位及缺值语义的谓词树、排序、分页大小和修订。按文件求交 RAW/JPEG 的两项文件属性，再按拍摄或作品折叠。普通整理范围与导入历史入口分别取数。多库可分别执行、按全局稳定键合并，返回库和模型覆盖。
- 游标包含作用域和查询指纹、只读快照／逻辑修订、缺值位、排序值及稳定对象 ID。相等日期和空日期都有确定顺序。UI 翻页保持快照，若修订已清理则显式刷新并恢复锚点。分项计数、全选操作及权限复核读取同一规则。写命令提交前重新验证选中的版本。实验以旧路径给出的固定顺序打平，同生产环境跨重建的稳定 ID 由新内核维护。
- 在同一权威事务内保存业务修改和可重放的变更序号。索引器以已提交序号去重。初建从快照水位 `s` 开始，分批生成新代，补齐 `s` 以后的修改及删除，校验计数、版本与抽样 ID 后原子切换。正在读取的索引代保留到读者退出。分页采用短读事务及可过期游标，避免长时间浏览阻碍 WAL checkpoint。失败可从检查点继续或删除该代重建。索引滞后时，评分、成员资格与删除须从权威数据补差／复核。向量缺失或过期单列覆盖。新增的排除决定立即影响查询和归档。
- 空间树返回经纬度包围盒命中，精判读取双精度原值。圆以经纬度和米定义，基线采用平均地球半径的球面距离。第一版多边形按相邻顶点最短经度差展开，在同一经纬平面作奇偶判定，边或顶点计入。声明可保存的几何类型和适用范围。对自交、绕极或涵盖半球而当前语义无法唯一解释的多边形提前提示处理。跨日界线拆包围盒查询后去重，近极点的圆可能覆盖全部经度。原始缺值与合法的零坐标独立。
- 结构化投影、FTS、空间和模型索引分别带格式、覆盖水位和重建状态。向量还记录模型／权重／tokenizer／预处理指纹、维度与元素编码、内容／作品版本及输入代理。只有同一共享特征空间的向量可比较。更改图片、方向或所采用编辑时使对应结果失效。更换启用模型时先建新代，保留人工数据。[检索专项](retrieval-research.md)

## 可移植内核与作业边界

接口以版本化 C ABI 暴露打开／关闭句柄、读页（卡片及续页游标）、提交命令取收据、取消和取作业状态、打开一致快照及释放结果。使用固定宽度整数、长度明确的 UTF-8／字节缓冲、错误码和显式释放函数。借用内存限一次调用，分配和释放由同一模块负责。不得跨 ABI 抛异常或展开 panic。连接在线程内持有，有界读池和单写队列。主线程只订阅增量结果。文件访问由宿主提供可在本机解析的定位符，原生书签、文件描述符及绝对路径不进入跨设备身份。只读计数探针验证了这一接口方向的本机可行性。[Rust／Swift／C++ 探针](../../experiments/library-lifecycle/ffi-probe/include/catalog_probe.h)

| 本地持久化内容 | 后续兼容作用 |
| --- | --- |
| 操作载荷 | 包含库、操作 ID、实体、基准修订、结果修订、动作、载荷版本及设备身份。同操作 ID 同内容返回同一收据。同 ID 不同内容报冲突。独立的新字段可保留或跳过，涉及读写语义的未知版本须拒绝修改。可凭固定序列化样本检查跨语言读写 |
| 作业与输入 | 含作业 ID、冻结的组／成员修订、按序的拍摄／文件／内容版本、画质与替代决定、配方和资源摘要、引擎／模型及所需能力。只记录本地执行状态与检查点。输入离线、未纳入或版本已变时按输入逐项报告。未来可复用描述决定执行位置 |
| 发布与恢复 | 渲染先写受管暂存，校验长度、摘要和可读性，再用作业 ID 的唯一约束登记作品及来源。文件发布与目录提交间若崩溃，按暂存清单核对已有对象并补登记。相同作业重试只产生一个结果。组重排后新任务另建修订。外部导出文件和资料库持有的母版分别记位置 |
| 原件与可用性 | 内容摘要、字节数、已核验的副本、归档资格及来源各自保存。本地热 RAW、代理、原件离线均可独立显示。以后启用 Server 时可附加新的位置和独立备份凭据。旧本机副本先核验再接入，换设备时重新解析卷／根 |

前三阶段以本机两种语言调用同一内核、相同样本跨版本解码、未知版本拒绝危险写入、重放不增记录作为兼容验收。网络传输、服务端权威目录与远程作业调度在后续 Server 专项决定。
