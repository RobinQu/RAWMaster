# Lightroom Classic 目录迁移

2026-11-22 · 阶段二，单向迁入。首版以**组织关系、元数据、可获得的历史外观**三项验收。Adobe 专有显影参数及可取得的依赖原样封存。迁移完成后可从任一虚拟副本开启独立的 RAWMaster 编辑版本。[资料库规格](spec.md)

五份源目录的实际迁入与差异数见[逐库验收](evidence/lightroom-release-validation.json)。主片、虚拟副本及独立还原后的本地编辑可按[宿主验证](lightroom-native-edit-validation.md)复测。

## 迁入对象与落点

| 来源 | 迁移行为与核对单位 |
| --- | --- |
| 目录、文件与存储卷 | 从一致、可读的目录副本开始，盘点目录版本、相关的 `.lrcat-data`、原件、已有 XMP／ACR 及预览。按源目录身份和源对象身份记录映射，保留多卷文件夹树、相对路径、缺失占位及文件类型。整卷重定位后按内容核验。无法核验的原件标为待找回 |
| 普通集合、集合组、智能集合 | 保留层级、各自成员及原有手动顺序，一张照片可属于多个集合。智能集合保存原规则和迁移时成员快照。支持的规则在目标库重新求值并对账，不能等价执行的规则可查看快照和差异原因 |
| 堆栈与虚拟副本 | 保留堆栈所属文件夹或集合、封面与顺序。每个虚拟副本拥有独立名称、版本、集合归属和外观引用，多份副本可共享同一个物理原件。原有整理堆栈与 RAWMaster 的连拍／延时组按各自来源保存 |
| 元数据 | 保留源中可取得的旗标、星级、颜色标签原值、分层关键词、标题、说明、作者、版权、IPTC、EXIF 与 GPS。记录字段来源和缺失值，颜色文字等无法映射的原值列入报告。Lightroom 的拒绝旗标作为原目录选片数据迁入，本次迁入明确跳过的文件另计 |
| 历史外观 | 将可定位到相应主片或虚拟副本的 Adobe 预览、渲染成片连同来源、分辨率及可验证的版本信息保存。来源不足、版本无法对应或外观缺失时逐项标明。用户可同时查看历史外观并打开新的 RAWMaster 编辑版本 |
| Adobe 专有显影参数 | 保存在一致目录副本或对应原始数据／伴随文件中，保留可取得的原始载荷、版本和依赖，建立到相应照片或副本的索引。以原始载荷或源文件的哈希核验封存。原生参数等价转换和像素重现属于今后单独验证的能力 |

目录搬迁涉及主目录及相关数据。集合、堆栈作用域和伴随文件按 Lightroom Classic 的数据含义核对。[Adobe 目录管理](https://helpx.adobe.com/lightroom-classic/desktop/manage-catalogs-and-files/create-catalogs.html) · [Adobe 集合](https://helpx.adobe.com/lightroom-classic/desktop/organize-photos-in-lightroom-classic/photo-collections.html) · [Adobe 堆栈](https://helpx.adobe.com/lightroom-classic/desktop/organize-photos-in-lightroom-classic/grouping-photos-stacks.html) · [Adobe XMP 与 ACR](https://helpx.adobe.com/lightroom-classic/desktop/organize-photos-in-lightroom-classic/create-xmp-acr-files.html)

## 文件操作与迁移报告

资料库支持按卷浏览、移动或重命名文件及相关伴随文件，操作前展示实际范围，完成后校验并更新位置。中断时按逐项记录恢复。将照片移出集合、从库中移除、删除受管文件是可辨认的不同操作。移动外置盘的文件夹或改挂载点后，提供整树重连。迁移读取源目录和原件时保持只读。

每次导入记录源快照、已处理的源对象与目标映射。重复执行同一快照可补齐缺失项，目标库后续人工修改与新版本保留。原目录出现新修订时列出差异。报告按对象类型给出源数量、迁入数量、缺失、仅封存、未支持及理由，并单列成员、顺序、作用域和版本关系的差异。断开原目录后，已封存的参数和外观仍可从资料库备份还原。

本轮盘点的五份目录中，三份有可关联的预览索引。已读回独立 JPEG 层级和旧版打包 `.lrprev` 中的 JPEG。实施时先按源图像 ID 查索引，再按 UUID 与 digest 对应实际预览，并记录能证明的修订、层级及内容哈希。可解码的预览仍需核对与源作品版本的关系。源目录在读取期间有更改时须重新取得一致的配套文件，不能把各自时点的文件宣告为已核验的一套外观。[现有目录对账](validation.md) · [Adobe 预览提取说明](https://helpx.adobe.com/lightroom-classic/desktop/kb/extract-previews-for-lost-images-lightroom.html)

## 首版验收

1. 使用有多卷文件夹、嵌套集合组、跨集合成员、堆栈及两个虚拟副本的真实目录副本。逐项核对对象、顺序和关系。同一 RAW 可共享内容，两份副本各自对应正确的已知外观与参数。检查原目录及原件字节。
2. 纳入带自定义色标、分层关键词、GPS、拒绝旗标、缺失外观及无法执行规则的样本。按三项验收范围分别出结果，能从报告定位到具体照片、集合或字段。断开一个卷，先浏览已迁元数据和可用外观，重连后只将能核验的原件登记为可用。
3. 中途停止后重新执行，再重复迁入同一快照。已迁对象与关系的重复数为零。抽取专有配方、XMP／ACR 或其原始容器做字节校验。在 RAWMaster 中编辑其中一份副本后再还原备份，两份副本原有的历史外观及封存参数仍可分别取得。
