## 存储与备份

服务端通过对象存储保存不可变的原件、编辑依赖和照片／视频成片。事务型目录按稳定身份记录对象的内容版本、位置、校验结果和对它的业务引用。客户端使用各自的本地目录，通过服务接口交换带版本的变更和清单。单机模式可独立完成导入与整理。

| 用户看到的状态 | 登记依据 |
| --- | --- |
| 待归档／传输中 | 对完成清单中符合资格的每个文件建立传输记录。可断点续传，传输失败可逐项重试 |
| 服务器原件可用 | 接收方已核对完整长度和哈希，并提交该文件的归档引用。重复发送同一请求只登记一次 |
| 独立备份已覆盖 | 独立于主存故障的目标已校验该代清单及对象，可按版本恢复。主存对象、临时上传或同存储池快照各有自己的状态 |
| 无归档原件／待找回 | 初筛排除的文件只同步必要的历史元数据。缺失原件列出现有来源、查找入口及可恢复范围 |

归档程序从有效纳入清单枚举原件，不能靠遍历整个来源目录、资料库包或组内文件来扩大范围。若用户选用服务端作为接入暂存位置，暂存内容与长期归档、独立备份清单隔离。封存后只提升有资格的文件，排除项按暂存生命周期处理。远程作业的输入也要核对有效纳入，不能借组引用给排除原件建立归档。用户源文件及其他合法引用始终独立管理。

同一代备份包含目录快照、引用的原件、机内 JPEG、编辑配方及其必要资源、成片和来源关系。服务器可重建预览和机器索引，人工命名、纠错、采用及历史外观随目录或受管对象备份。周期校验报告缺失或损坏的具体对象，独立备份可用于修复。用户显式删除受管内容时记录删除意图与回收期限。

## 客户端冷热数据与离线协同

- 本地常驻可检索的目录，近期使用的完整原件按容量缓存。冷照片以 JPEG 代理浏览，代理与机内 JPEG 分别标记。代理可按容量预取、按需获取或离线固定，界面分别显示目录可查、代理可看、原件可用、需联网和独立备份状态。
- 可按照片、整组或项目固定离线级别。用户请求原始细节、全质量导出或本地 RAW 处理时，先取回并核验需要的内容。离线时说明当前可用级别，下载中断后继续。在线服务器已持有原件时，远程处理可直接执行。
- 自动释放只适用于未固定、已确认可从服务端取回且独立备份已覆盖的本地受管副本。离线固定、未上传的唯一副本、尚未持久化的编辑和用户引用的外置盘不进入缓存回收范围。
- 同步操作携带操作 ID、实体、基准修订与载荷版本，可离线排队、重放去重。独立字段可合并，同一人工决定冲突时保留双方来源，配方分支可选择。迟到的分析或任务结果绑定原输入版本，人工决定与当前采用版本由用户控制。

## 将计算委托给服务器

本地与远端使用同一份任务描述。描述包含操作 ID、目标库和项目、按顺序选定的拍摄与具体文件内容版本、配方及外部资源版本、引擎／模型、输出类型。提交前显示执行位置和需要补传的输入。按任务所需的 CPU、GPU、内存与引擎能力选择执行端，缺少依赖时列明缺项。

任务可排队、查看进度、取消和重试。客户端失联后凭原操作 ID 查询服务端结果。输出先私有暂存并核验，再登记作品版本或派生照片／视频及全部来源关系。重复回调只产生一次有效登记。任务期间发生重排、换配方或用户采用另一版本时，已完成的旧结果可回看，当前版本由显式采用决定。

## 服务端验收场景

1. 对[五文件导入样本](spec.md#每个导入原件的归档资格)执行归档、独立备份和异机恢复，逐对象对比三份清单及哈希。仅含初筛排除的另一批次产生零条原件归档引用，导入历史仍可还原。预暂存、重复导入及同哈希另有合法引用分别复测。
2. 服务器已归档但备份尚未验证时尝试自动释放，再完成独立备份后重试。已固定原件与引用盘始终可核对。冷片从代理切换到完整 RAW，中断后恢复下载，最终哈希与归档清单一致。
3. 主存一份对象损坏，恢复到另一台机器。核对原件、组顺序、人工标签、历史外观、编辑依赖与派生成片。用没有备份原件的排除记录走历史恢复，如实显示需要可校验的来源。
4. 两台设备离线修改不同字段及同一评分，随后重连，分别验证合并与冲突保留。将已归档的一组委托处理，在回报前断网、修改组并重试原请求。只产生一个绑定原输入的结果，取消或失败的未发布临时产物可清理。
