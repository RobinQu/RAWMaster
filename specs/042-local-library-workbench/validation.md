# 042 · 本地资料库与任务验证

2026-11-28 · 摄影工作台使用仓库样片走查交互。原生测试使用临时资料库、独立卷和本机模型，分别核对文稿、任务及实际输出。[规格](spec.md) · [实施计划](plan.md)

## 浏览器走查

在仓库根目录运行 `python3 scripts/check-ui-prototype.py --local-library-only`。脚本使用独立 Chrome 会话，无需 Server 评审状态。

| 操作 | 已核对的反馈 |
| --- | --- |
| [开始页](../../docs/ui/prototype/index.html#welcome) → 新建 → 取消 → 重开 → 选择示例卷 | 菜单只显示本地建库及打开动作。无效位置留在表单，成功后进入空库。编辑、导出不可用，制作任务显示空状态 |
| 顶栏资料库菜单 → 最近库 → 选择 `DSC_0712.ARW` → 切库 → [Finder 示例](../../docs/ui/prototype/index.html#tools/package) | 移动后弹出卷，打开失败时当前库保持。接回并双击后，同一库 ID 和原选片恢复 |
| 多选 → 更多 → 批量工作流 → 提交 → 切到空库 → 重开原库 → [制作任务](../../docs/ui/prototype/index.html#jobs) | 任务只出现在原库。导入会话可以回查。批次可从暂停点继续，已完成项沿用原候选。撤销后回原选片 |

| 提交较大批次 → 重开工作台 → 制作任务 → 取消待处理项 | 列表显示「已暂停」。取消余项后，已完成候选及原版本 ID 保持 |
| 1280×800 桌面、390×844 浅／深、Tab／Return／Escape | 菜单内容在窄窗内可见，打开后焦点进入菜单，退出后回到按钮 |

## 切库确认与标题栏路径

在[资料库与备份](../../docs/ui/prototype/index.html?batchNativeReview=1#tools/package)新建第二个库，回原库后选两张照片，打开批量工作流并提交。通过「资料库菜单 → 最近打开」选择另一库，在弹窗查看两库名称和目标路径。选择等待，核对任务继续执行且当前库仍打开。取消等待后重试，分别验证等待自然完成和暂停后再回原库继续。打开离线库先提示接回卷。重复打开同一库保留当前上下文。

切库后，在标题栏库名上右键检查路径和上级目录。以 390 px 浅色和深色外观用 Enter 打开路径、用 Escape 关闭，确认焦点返回库名。带确认、取消、等待、暂停和路径的浏览器专项共 15 个场景通过。

签名构建 4209 在浅色与深色外观下通过原生走查。用 Launch Services 打开临时包 Alpha 和 Beta，重复打开 Alpha 时仍只有一个工作台。打开 Beta 出现确认，取消后仍是 Alpha，再确认后在同一进程打开 Beta。两库均通过真实右键检查左侧库名、包和上级目录，菜单中有「拷贝资料库路径」。用 Escape 关闭菜单后可重新操作标题。辅助功能读取的库名随切换更新。[原生标题](../../Sources/RAWMaster/WorkbenchLibraryTitle.swift) · [切库入口](../../Sources/RAWMaster/ApplicationLibrarySession.swift)

原生会话测试在成片交付等待期间检查两库的锁和旧库连接。取消等待后任务继续，目标库仍可取得锁。再次等待至任务完成后，才释放旧库并打开目标库。另有覆盖最近库确认、取消及恢复原选片的用例。[会话回归](../../Tests/RAWMasterUITests/ApplicationLibrarySessionTests.swift)

本轮浏览器全量 60 个场景和 Server 评审入口 8 个场景通过。原生回归分两轮共 18 个不同用例通过，含本机 Flux 切库后重试、真实 RAW 的 20／200 张批次、批次交付成片及原件队列恢复。[任务用例](../../Tests/RAWMasterUITests/LocalLibraryTaskTests.swift) · [批次用例](../../Tests/RAWMasterUITests/SceneWorkflowBatchTests.swift)

## 原生验收记录

macOS 27.0.1，Apple Silicon。临时验证包采用独立的偏好设置域。资料库、输出目录和故障注入均使用临时夹具。

| 用例 | 核对结果 |
| --- | --- |
| 签名包文稿打开 | `scripts/build-app.sh debug` 构建 4203 通过签名核验。`.rawmasterlibrary` 的 UTType 为 `io.robinqu.rawmaster.library`，系统识别为 package。用 Launch Services 启动指定签名 app 打开 A，冷启动先处理文稿事件。重复打开 A 聚焦同一主工作台。向同一进程发送 B 后，移动已经关闭的 A，再打开保持库身份。拷贝已关闭的 A，通过原生确认按钮打开副本，核对原库身份和副本新身份。[应用入口](../../Sources/RAWMaster/RAWMasterApp.swift) |
