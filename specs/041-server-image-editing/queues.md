## 1. 执行位置

| 阶段 | 本机 | Server |
| --- | --- | --- |
| 040 归档与同步 | 冻结封存资格与上传清单，读源卷、续传和取回，保存校验、同步水位与本地回执 | 核验对象并登记引用。负责服务端快照、元数据备份、校验、隔离恢复。使用 040 的命令／传输 ID，基础闭环无需图像作业或 GPU |
| Q3 首个计算闭环 | 显式选择「RAWMaster Server」，提交一张已归档照片。取回后校验，再登记代理或候选 | 先验收已验证的显示代理与兼容 SDR 子集。冻结输入、能力和版本，返回输出收据 |
| Q4／Q5 扩展 | 场景批次写回原头和原批次。032 只在字节成功写入已授权目标后签发交付回执。Flux 回到原照片／版本的候选 | 通过独立门槛后执行场景图／HDR、确定性模型前缀、明确选用的 Flux。分组渲染、全规格 032 服务端渲染另验收 |

普通导入、原地引用、原片定位、最终交付写盘、编辑与版本采用始终由持有库和文件授权的客户端完成。适合委派的工作使用明确授权、可冻结的输入，有可验证的处理契约及版本，且输出可在客户端幂等登记。用户主动选择执行位置，同一工作项一次只委派给一个执行方。换执行位置要先核对旧尝试，再明确生成新请求。

## 2. 客户端的远端任务

本机任务、资源分配、切库和交付回执按 [042](../042-local-library-workbench/spec.md#5-制作任务) 实施。队列在此基础上增加以下阶段。

| 客户端阶段 | 动作与结果 |
| --- | --- |
| 提交意图 | 持久化所属库、业务项、冻结请求与原作业 ID。网络或能力未就绪时显示等待原因，满足条件后继续 |
| 拉取与核对 | 保留服务端状态和事件游标。提交结果不明时先查原任务 ID。显式取消已接收作业时传播取消意图并等待回执 |
| 结果可取回 | 输出由 Server 发布后进入本机下载和校验。失败时重试取回。登记候选、代理或交付输入后保存本地收据 |
| 切库与重开 | 042 关闭旧库前保存意图及游标。已接收的作业继续在 Server 执行。重开所属库后更新，处理事件时核对所属库 |

代理取回或生成按源内容、代理契约、解码器／引擎、画质与输出状态去重。用户当前所需的取回优先于预取，后台网络与计算各自受预算约束。场景批次保留 042 的业务状态，逐项关联远端作业、原版本和目标 head。现有第三方生成任务仍按各自原服务状态核对。

## 3. Server 作业和准入

| 能力与作业 | 准入与产物 |
| --- | --- |
| `library_core` | 040 的命令、传输、归档、取回和备份。资源独立预留，受图片或模型压力时仍可用 |
| `image_proxy` · `proxy.generate` | 显示代理和已验证的 SDR 编辑代理。输出绑定源、方向、几何及代理契约 |
| `image_sdr_batch` · `legacy.render.final` | 通过对照的旧 SDR 子集。其余配方显示具体能力缺口 |
| `image_scene_batch` · `scene.proxy`、`scene.render.final`、`scene.render.batch` | Linux scene executor、色彩和输出契约逐项通过。HDR AVIF 与 SDR JPEG／PNG16 独立。借用 SDR JPEG 浏览无法解除场景执行资格 |
| `model.prefix` | 显式批处理的确定性前缀，绑定模型身份及顺序，验证几何、覆盖和预算 |
| `generative` · Flux | CUDA、模型版本、许可、显存和功能开关独立验证。返回候选 |

保持 041 已定的 NVIDIA GPU 图像模块准入，影像路径用 Vulkan，生成式用 CUDA。容量按库公平分配并设置上限。分块或逐项可让出资源时优先用户所需代理和短任务。生成式共享物理 GPU 时统一核算显存、显卡并发和驻留模型。控制、归档和备份留有可测容量。队列满返回原因和退避建议，能力缺失在提交前可见。

PostgreSQL 作业聚合以 `(library_id, job_id)` 为键，包含冻结请求、输入、尝试、输出、幂等控制命令及事件。请求记录包含版本化的规范序列化与摘要、源 `contentID`／文件 ID／原始版本、有序输入、父和目标 head、场景图或兼容配方、输出状态、模型前缀、模板／批次项、引擎／解码器／模型／种子、目标与资源请求。字段随作业类型适用。Server 计算并核验摘要。同 ID 不同摘要返回冲突。回执回带上述请求摘要、产物哈希、长度、ICC／CICP、位深、目标和格式。场景收据另有 backend、tiles、cache hits、dispatches、budget、peak bytes 和 CPU time。原件来自同库已核验归档。生成所需的蒙版或其他选定输入单独预检并经用户确认，放在限时作业输入域。这些引用不能赋予原片归档资格。

状态按 `queued → running → staged → published` 演进，分别记录等待、取消、失败及恢复后的待核对。Claim 创建 attempt 和租约，心跳续租。超时或换代令旧 token 失效。Worker 可重复尝试，成功只可见一次。先每 attempt 写独立暂存并校验 S3，再用 PostgreSQL 条件事务核对当前 lease、授权代次、取消状态与请求，唯一登记作业输出和同一事务内的事件。失败或过期暂存按业务引用和回收策略清理，提交成功的输出按保留期独立管理。暂存没有客户端候选或 032 收据。

## 4. 双端协同

1. **准备和提交。** 客户端用稳定 `jobID`、`requestHash` 和库／业务映射持久记录提交意图。发送前核对绑定、能力、同库对象、当前网络和显式授权。Server 在事务提交作业及初始事件后才确认接收。客户端保存投影和事件游标。一项逻辑作业不为观察、下载各生成一行用户任务。
2. **观察和补差。** PostgreSQL 是远端执行状态权威，SQLite 是本地任务、网络意图及采用的权威。gRPC 按每个作业单调事件序号追赶。投影和游标同事务提交。重复/乱序事件不倒退。发现缺口、事件已过期或换恢复代次时，先取权威快照和新游标，再续订。凭证和 presigned URL 不进入日志、可复制库包或冻结载荷。
3. **未知结果。** 提交超时标「结果待核对」，按原 ID 取得作业或确定的未接收回执。仅在同一权威代次能确认未接收时才重送原意图，复用同 ID。去重收据保留期覆盖承诺的离线重试窗口。收据超出保留期，或 Server 从旧备份恢复后查不到 ID 时，用原收据、已验证对象和审计记录核对。无法证明时保留未知供处理。第三方恢复还遵循各自的计费与查询语义。
4. **取消和重试。** 未发送的意图本地取消。发送后用独立 `commandID` 幂等发送取消。离线时显示「取消待确认」。Server 的取消与发布在同一作业记录上竞争，先提交取消则阻止发布，先发布则返回已有收据及「已发布」。可做续跑的失败／已取消作业在同 ID 下新开 attempt，冻结请求保持。重试命令复用自己的 ID。结果已发布则重试下载或登记，查回原收据。
5. **取回及采用。** 下载走 040 S3 Direct／Relay。校验哈希、长度、请求、执行契约、输出范围及格式后，按 `(libraryID, jobID, outputID)` 幂等登记。客户端对当前目标 head、原片、版本和业务规则做条件写入。原输入仍有效时记录候选。目标已变时提示旧结果并保留来源，现有采用版本保持。代理入缓存。032 复用原批次、逐项收据和目的路径验证。撤销候选需检查是否已采用或交付。
6. **权属变化。** 切库只改变客户端会话。所有权转移或隔离恢复切换后，旧写绑定和旧 worker attempt 被 fencing。已发布结果继续可查询。尚在运行且未发布的作业进入核对，只有当前授权方显式接续原请求才重新执行或登记可确认结果。新持有者可查询原任务。核对流程遵循 [040 恢复契约](../040-server/metadata-backup.md#63-客户端对账)。

## 5. 可见性与验收

顶栏「制作任务」沿用现有入口。一个库内看到本机和 Server 的工作。设备任务明确标出。范围、冻结版本、执行位置、当前阶段、阻塞原因和下一步在详情中。后台预取默认收起。返回恢复此库的选片／编辑／导出上下文。尚未联网、缺能力或无已归档原片时，提交页说明原因并保留本机入口。界面以实际进度、阶段、待处理项表达。只在 Server 可以给出准确信息时显示队列位置。

| 必验 | 判据 |
| --- | --- |
| 042 本机回归 | 验证现有恢复契约仍可用，并检查远端准备或失败时本机任务仍可继续。[042 验证](../042-local-library-workbench/validation.md) |
| 重试与取消竞态 | 同 ID 同请求幂等，不同请求冲突。取消与发布的两种次序各测试一次。旧租约无权发布 |
| 断线／恢复旧库 | 提交回执丢失、重复／缺口事件、旧数据库恢复、所有权换代。新库绝不接收旧库输出 |
| 取回及版本冲突 | 错误哈希或格式拒绝登记。重复取回只记一份。候选或回执保留在冻结版本。候选采用、交付写盘均单独核验 |
| 能力与资源 | 无 GPU 仍归档和恢复。能力禁用有理由。前台拖动保响应。大批作业期间短任务和资料库获得资源 |
| 媒体真实性 | 用真实 S3／PostgreSQL、真实 RAW、冻结的 HDR／SDR 输出和模型验证。样片和浏览器仅走查交互 |
