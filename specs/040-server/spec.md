# 040 · RAWMaster Server 1.0

2026-11-27 · **设计修订中。** Server 基于 [042 客户端](../042-local-library-workbench/spec.md) 的资料库包，可以托管多个独立库，每库一次授权一个可写副本。控制面使用 gRPC over HTTP/2/TLS，内容面使用 S3 兼容 API，元数据使用 PostgreSQL。服务器本地磁盘保留日志、临时文件和有限中转缓冲。[Server 接入](local-library.md) · [工作台走查](validation.md#server-资料库接入走查)

PostgreSQL 与 S3 的高可用和存储可靠性由基础设施负责；RAWMaster 仍负责**自身元数据的一致性校验、逻辑备份、恢复**，以及证书、令牌等服务端身份资料的安全备份。[部署与架构](plan.md) · [存储](storage.md) · [元数据备份](metadata-backup.md) · [安全与证书](security.md) · [数据模型](data-model.md) · [gRPC／S3 协议](protocol.md) · [交互](ux.md) · [任务](tasks.md) · [现有基础](evidence.md)

## 1. 结论

1. **Server 单写者。** 每个库绑定一个设备上获授权的 `replicaID` 和 `ownershipEpoch`。其他副本经授权可只读或显式转移所有权。连接后可新建 Server 库或同步到选定的 `.rawmasterlibrary` 包。
2. **gRPC 负责事务性控制。** 库所有权、操作日志、上传意图、收据、事件流、元数据备份管理通过 gRPC；事务边界在 PostgreSQL，不在 gRPC。
3. **S3 负责对象字节。** RAW、JPEG、资源、成片使用 S3 兼容 API；默认客户端用 presigned URL 直传，失败自动切换服务器中转 Relay。S3 ETag 不作为内容哈希。
4. **PostgreSQL 负责服务端元数据。** 客户端不直连 PostgreSQL；客户端本地 SQLite 仍是离线工作副本。服务端不需要重建完整客户端目录逻辑，只保存操作日志、对象索引、归档引用、快照索引和业务状态。
5. **元数据备份是 Server 业务逻辑。** 使用 PostgreSQL 一致快照 + 对象清单 + 校验和，恢复到隔离数据库并逐项验证；不依赖 PostgreSQL HA 代替逻辑恢复。
6. **自签名证书是正式方案。** 自建服务使用私有 CA 或自签名证书，客户端固定服务器身份；证书、设备令牌哈希、令牌密钥／pepper 纳入服务端备份范围。私钥和密钥材料进入单独加密的 secret bundle，不进入普通元数据 dump。
7. **存储可靠性外部化。** RAWMaster 不实现 RAID、纠删码、跨站点复制或 S3/ZFS 可靠性；现有 TrueNAS 冷备承担介质与灾难恢复。RAWMaster 只保证逻辑清单、哈希、引用和恢复路径。
8. **按职责交付队列。** 040 首先闭合归档、取回、同步与备份。041 规划可委派的代理与渲染、场景批处理和生成式任务。032 继续负责本地目标授权和交付回执。[双端队列](../041-server-image-editing/queues.md)
9. **037／038／039 对齐。** 资料库必须能保存和恢复新版场景图配方（`DevelopmentRecipe` schema 4 / `DevelopmentSceneGraphV1`）、输出状态、模型前缀、场景工作流模板与批量候选身份；旧 SDR 兼容配方与新场景配方分开，不能静默迁移。HDR AVIF 10 位 PQ 与 SDR JPEG/PNG16 成片作为不同交付资源登记。Server 本身不执行交互编辑；场景图批处理属于 041。

## 2. 用户与问题

**目标用户。** 一位摄影师或一个家庭，使用一台主机 Mac 和一台移动 Mac；每台 Mac 可以有自己的独立资料库，也可以在不同时间切换打开不同库。服务器是长期归档和跨地点访问节点，不是共享协作平台。

| 当前问题 | Server 1.0 的回答 |
| --- | --- |
| 哪些原片真的在服务器上 | 逐文件归档引用、S3 对象校验和状态 |
| 服务器是什么、证书是否可信 | 自签名 CA／服务器证书指纹，客户端固定并显示变化 |
| 哪台设备拥有这个库 | 库所有者、所有权 epoch、显式转移 |
| 笔记本空间不足 | 代理浏览、按需取回、固定离线、受控释放 |
| 服务器元数据坏了怎么办 | 一致快照、对象清单、隔离恢复、`metadata doctor` |
| 证书或令牌丢失后还能不能恢复 | 证书／令牌纳入备份；私钥和密钥材料进入加密 secret bundle |
| 上传中断或 S3 不可达 | Direct 直传 + 自动 Relay 回退；断点、幂等、校验 |
| 旧备份恢复后会不会覆盖新状态 | `ownershipEpoch`、修订对账、客户端补交操作 |

## 3. 交付边界

### 3.1 Server 1.0 必须交付

- Server 建库、同步已有库及下载快照。客户端复用 042 的选址、包打开与切换入口。
- 自签名 CA／服务器证书、客户端固定、设备登记、令牌、库所有权与转移。
- 一个服务器托管多个独立库；每库独立配额、对象前缀、归档引用和元数据。
- 归档资格、归档清单、S3 Direct 上传、自动 Relay 回退、内容校验和去重。
- 冷热数据、JPEG 代理、按需取回、照片／组／项目固定、受控释放和过期策略。
- 单客户端操作日志、离线队列、重连对账、库快照。
- PostgreSQL 元数据一致性校验、逻辑备份、备份验证、恢复、对象清单核对。
- 证书、令牌哈希、私钥／密钥材料的备份与恢复。
- 健康、配额、归档／备份状态、日志和版本兼容。
- 远程作业只保留接口和身份预留；场景图／HDR／批处理的 Server 执行见 [041](../041-server-image-editing/spec.md)，不在 040 内实现。

### 3.2 Server 1.0 明确不做

- 共享库多设备写、团队权限、评论、发布、Web 客户端。
- Server 跨库查询、去重或事务。本机 033 显式选择的只读联合检索仍可用。
- RAWMaster 自己管理 RAID、纠删码、S3/ZFS 复制或异地容灾。
- 远端交互编辑和服务端直接写入本机交付路径。通过验收的远端渲染归 [041](../041-server-image-editing/spec.md)。
- 自动删除用户源文件或把排除项“顺手”归档。
- 把 PostgreSQL 当客户端共享数据库，或让客户端直连数据库。

### 3.3 与 033 的关系

033 定义资料库生命周期与逐文件归档资格；本规格把阶段四落地为 Server 1.0。若冲突，以 033 的归档资格和五文件样本为准。033 中原“RAWMaster 管理独立备份”的表述，在本架构下调整为：**存储可靠性由外部 TrueNAS 冷备承担；RAWMaster 负责逻辑元数据备份、对象清单和恢复验证**。该差异需在 Server 发布验收中明确记录。

## 5. 用户故事

### US0 · 从 Server 在本机打开资料库（P0）

摄影师在启用 Server 功能的客户端核对证书和设备登记，然后选位置新建库，或把已有 Server 库同步到一个本机包。

**独立验收。** 建库失败可按原命令续接，已有库先验证快照和必要资源再打开。取消或失败时回到原工作区或开始页。同一已绑定库的独立拷贝保留照片和版本，原写授权留在原包实例。

### US1 · 确认原片归档（P0）

摄影师完成导入，打开 Server 面板，看到本次纳入、明确仅序列、排除、失败和待找回；开始归档后可以关闭窗口。稍后看到每张照片的 S3 对象、归档引用、校验时间和待处理项。排除项不进入归档。

**独立验收。** 五文件样本的归档清单恰为 A.JPG、B.RAW；A.RAW 排除、C.RAW 必要帧但排除、D.RAW 失败均不产生对象引用；恢复 A.RAW 只增加一份引用。

### US2 · 笔记本浏览冷照片（P0）

摄影师在只有代理的笔记本上筛选冷照片；需要 1:1 或本地 RAW 时取回完整原件并校验。可按照片、组、项目固定离线；释放本地副本前显示完整检查表。

**独立验收。** 代理与机内 JPEG 分标，取回中断可续，最终 SHA-256 一致。已固定、未校验、有未同步修改、冷备保护不足或只剩唯一副本时阻止释放。

### US3 · 恢复 Server 元数据（P0）

服务器 PostgreSQL 发生逻辑损坏、错误迁移或误删。管理员选择最近一次已验证的元数据备份，恢复到隔离数据库，运行 `metadata doctor`，核对 S3 对象清单，切换服务。客户端重连后补交未同步操作。

**独立验收。** 恢复到空 PostgreSQL 后，库、所有权、操作日志、归档引用、快照和配额完整；S3 对象缺失逐项列出；客户端修订对账无静默丢失；未验证备份不能作为恢复来源。

### US4 · 证书与令牌恢复（P0）

服务器主机损坏，管理员从备份恢复自签名 CA、服务器证书、令牌哈希和密钥材料。客户端重新连接时仍能验证服务器身份，已登记设备令牌继续有效；如果私钥／pepper 丢失，则必须重新登记并明确提示。

**独立验收。** 同一 CA／密钥恢复后客户端无需重新固定；单证书方案恢复后指纹一致；证书过期、指纹变化、令牌撤销和错误令牌均被拒绝；secret bundle 缺失时不能假装身份已恢复。

### US5 · 单客户端所有权与重连（P0）

同一库被第二台 Mac 打开时，服务器拒绝写入并显示当前所有者。用户显式转移所有权后，旧客户端被 fencing token 拒绝，新客户端获得新 epoch。客户端离线修改后重连，按操作 ID 补交。

**独立验收。** 第二客户端无法写；转移后旧客户端不能写；离线操作补交去重；服务器恢复到旧修订后，客户端可补交其后的操作。

### US6 · 提交远程作业（P1，Server 1.1）

摄影师把已归档组交给服务器，冻结输入、配方、引擎和模型；可查询、取消、重试；断线后按作业 ID 核对结果。结果先暂存，用户采用后才成为作品版本。

**独立验收。** 回报前断网、改组并重试原请求只产生一个绑定原输入的结果；旧结果不自动覆盖当前版本。

## 6. 功能要求

### 6.1 身份、证书与所有权

- **SRV-R01 · 服务器身份。** 自建服务使用私有 CA 或自签名证书；客户端首次连接显示证书链和 SPKI 指纹，确认后固定。指纹变化、证书过期、主机名不匹配必须阻止写入。
- **SRV-R02 · 设备登记。** 一次性登记码绑定设备；服务器签发随机不透明令牌，数据库只保存哈希；令牌存客户端钥匙串。撤销设备后不能继续同步或上传。
- **SRV-R03 · 库所有权。** 每个库记录 `ownerDeviceID`、已授权 `replicaID` 和 `ownershipEpoch`。设备令牌与写授权分开，副本只读需显式授权。
- **SRV-R04 · 所有权转移。** 显式转移生成新 epoch；旧客户端被 fencing token 拒绝。恢复或换机后可通过恢复码转移。
- **SRV-R05 · 离线优先。** 连接失败不阻塞本地打开、导入、选片、整理和已有编辑；界面区分本地可用、需服务器、状态未知。
- **SRV-R06 · 多库。** Server 托管多个独立库。本机显式切换库。Server 绑定见[资料库接入](local-library.md#已同步库的移动与拷贝)。

### 6.2 归档与 S3 对象

- **SRV-R07 · 归档资格。** 只接受封存会话的有效纳入、明确仅序列纳入或显式恢复纳入。来源扫描、组关系、项目星级、S3 扫描和远程作业不能新增资格。
- **SRV-R08 · 排除项。** 最终导入排除的原件只保留来源、内容身份和处置历史；不创建归档引用，不进入对象前缀，不因配对、缺帧或组引用被带入。
- **SRV-R09 · 归档清单。** 每次计划列出库、项目、会话、文件、拍摄、内容哈希、字节数、文件名、角色、纳入依据和缺项；重复执行返回同一收据。
- **SRV-R10 · Direct 上传。** 默认由 Server 创建上传意图和 S3 multipart，客户端用 presigned URL 直传。对象 key 内容寻址，不允许覆盖不同内容。
- **SRV-R11 · Relay 回退。** Direct 遇到 DNS／TCP／TLS／5xx／超时等传输失败，自动向 Server 请求 Relay；Direct 和 Relay 使用同一 upload ID、part 号和 S3 multipart，不重启整个文件。
- **SRV-R12 · 校验。** 服务端取得完整对象 SHA-256 的可信校验证据并核对长度和 key。multipart 的合成校验或 ETag 不满足整对象要求。服务端必要时读取暂存对象流式计算。通过后才登记对象和归档引用。
- **SRV-R13 · 幂等与断点。** 同一 `uploadID`／`commandID` 重复提交只生效一次；未完成 multipart 有到期清理；Direct 已上传 part 可被 Relay 跳过。
- **SRV-R14 · 状态分离。** 上传暂存、S3 对象可用、归档引用、外部冷备、客户端本地副本分别记录，不能用一个“已同步”概括。
- **SRV-R15 · 内容去重。** 同一库内相同 `sha256 + byte_count` 只存一个对象，可有多个文件／项目／恢复引用；跨库不去重。删除一个引用不删除仍被使用的对象。

### 6.3 冷热、代理与过期

- **SRV-R16 · 常驻目录。** 客户端本地 SQLite 持续保存可检索元数据、关系、人工决定和版本；服务器离线时仍可浏览已缓存范围。
- **SRV-R17 · 代理。** 冷照片使用 JPEG 代理浏览；代理与机内 JPEG 分标来源、尺寸和生成版本；代理可重建，不进入原件归档引用。
- **SRV-R18 · 按需取回。** 1:1、全质量导出或本地 RAW 处理前取回完整原件；支持 Range、断点、取消、重试和 SHA-256 核对。
- **SRV-R19 · 固定离线。** 可按照片、组或项目固定；固定后不被缓存回收；固定状态属于设备，不上传为共享业务事实。
- **SRV-R20 · 受控释放。** 仅释放未固定、S3 对象已校验、符合已配置的外部冷备策略、无未同步编辑且有其他副本的本地受管文件。外部覆盖未知且没有明确的外部保护配置时保留本地文件。
- **SRV-R21 · 过期策略。** 本地原件缓存、代理、垃圾桶、草稿、版本、备份代次、上传暂存、同步墓碑分别配置；默认不自动删除唯一归档对象或最后已验证元数据备份。
- **SRV-R22 · 垃圾桶。** 用户删除先进垃圾桶，保留期可恢复；到期后由 Server 业务逻辑回收，S3 生命周期只作兜底。
- **SRV-R23 · S3 生命周期边界。** `objects/` 前缀不得配置自动过期；只对 `staging/`、`orphan/` 等临时前缀使用生命周期。

### 6.4 元数据一致性、备份与恢复

- **SRV-R24 · 一致性不变量。** 归档引用必须指向同库对象；对象 key／哈希／字节自洽；操作修订单调；每库一个所有者；无跨库引用；配额与对象汇总一致。
- **SRV-R25 · `metadata doctor`。** 在备份、恢复、迁移、升级后检查 schema、约束、操作缺口、收据、所有权、对象、引用、配额、上传意图、作业、快照、orphan 和 outbox。
- **SRV-R26 · 一致快照。** 使用 PostgreSQL `REPEATABLE READ` + 导出快照，`pg_dump --snapshot` 和对象清单在同一时点生成；备份记录 schema、WAL LSN 和格式版本。
- **SRV-R27 · 全量逻辑备份。** 默认备份整个 Server 元数据；包含库、设备、所有权、令牌哈希、操作、对象、引用、历史作业、快照索引和审计。上传意图、租约、未发送 outbox 不备份。
- **SRV-R28 · 备份验证。** 在临时 PostgreSQL 恢复 dump，运行迁移和 `metadata doctor`，对比计数与校验和；抽样 HEAD S3 对象；未验证代次不能用于恢复。
- **SRV-R29 · 隔离恢复。** 先恢复到隔离数据库；验证对象清单；重置瞬态数据；切换连接。部分成功不得标“完整恢复”。
- **SRV-R30 · 对象缺失。** 元数据恢复成功但 S3 对象缺失时标 `missing`，列出来源和冷备查找入口；不能显示“原件可用”。
- **SRV-R31 · 存储重绑定。** 换 bucket／endpoint 时更新对象位置并重新 HEAD 校验；不重写内容哈希。
- **SRV-R32 · 客户端重连。** 恢复后先验证授权代次和共同修订，客户端按已有收据补交，Server 领先时补拉。修订歧义或已提交效果无法确认时转待核对。
- **SRV-R33 · 库快照。** 客户端目录快照存 S3，索引在 PostgreSQL；恢复客户端时取最新快照并补操作日志。快照修订不得超前。
- **SRV-R34 · 证书／令牌备份。** 公有证书链、SPKI 指纹、令牌哈希、设备记录进元数据备份；私钥、令牌 pepper／签名密钥、S3 凭据进单独加密 secret bundle。
- **SRV-R35 · 备份加密。** TLS 只保护传输；备份在 S3 和 secret bundle 中必须静态加密；密钥离线或由管理员保管，不与备份同址。

### 6.5 运维、安全与版本

- **SRV-R36 · 自签名 TLS。** gRPC 和 S3 直传均支持私有 CA 或自签名证书；客户端固定 CA／SPKI；RustFS 证书不被信任时自动 Relay 回退。
- **SRV-R37 · 日志与审计。** 记录操作、上传、备份、恢复、证书／令牌事件；不记录令牌、私钥、S3 密钥；日志可导出但不泄露内容。
- **SRV-R38 · 配额与容量。** 每库配额、已用字节、对象数；超限拒绝写入但不删除已有归档；提供容量和失败报告。
- **SRV-R39 · 版本兼容。** gRPC API、proto、PostgreSQL schema、备份格式、S3 provider profile 分别版本化；未知写版本拒绝，旧客户端只读或安全退出。
- **SRV-R40 · 升级前备份。** 数据库迁移、证书轮换、Server 升级前创建并验证元数据备份；失败可回到隔离恢复。
- **SRV-R41 · 恢复演练。** 至少每季度从元数据备份 + S3 对象恢复到隔离环境，核对库、引用、客户端快照和对象哈希；记录回执。
- **SRV-R42 · 远程作业（1.1）。** 作业描述、冻结输入、能力、队列、取消、重试、结果登记按 [041](../041-server-image-editing/spec.md) 执行；必须支持 scene graph、输出状态、模型前缀和 HDR／SDR 交付目标。未通过验证的引擎不开放。

## 8. 关键流程

### 8.1 归档 Direct → Relay

1. 客户端 gRPC `CreateUpload`，Server 校验资格和配额，写 PostgreSQL `upload_intent`，创建指向暂存 key 的 S3 multipart，返回 presigned part URL。
2. 客户端直传 S3，失败或不可达时按 part 请求 `RelayUpload`。
3. Server 用同一个 S3 multipart 上传缺失 part，跳过已完成 part。
4. 客户端 `CompleteUpload`，Server 完成 multipart，校验整对象 SHA-256，发布到不可变 key，再以 PostgreSQL 事务登记对象和归档引用。
5. 失败 abort／过期清理；对象 key 内容寻址，重试幂等。

### 8.2 冷片取回

1. 客户端显示代理和“需联网”。
2. 请求原件；Server 返回 presigned GET 或 Relay。
3. 客户端 Range 下载、断点、SHA-256 校验；成功后标原件已缓存。
4. 释放前检查固定、对象可用、外部冷备、未同步编辑和唯一副本。

### 8.3 元数据恢复

1. 选择已验证代次，校验 dump／清单／checksums。
2. 恢复到隔离 PostgreSQL，运行迁移和 `metadata doctor`。
3. 按对象清单 HEAD S3；缺失／损坏分类。
4. 重置上传意图、租约、运行作业和 outbox。
5. 只读启动；客户端重连、补交操作；通过后切生产。
6. 记录恢复回执；未完成项保留。

### 8.4 证书／令牌恢复

1. 恢复元数据中的公有证书链、SPKI、设备记录和令牌哈希。
2. 恢复加密 secret bundle 中的 CA 私钥、服务器私钥、令牌 pepper／签名密钥、S3 凭据。
3. 安装证书和密钥；启动 Server；客户端用原固定身份连接。
4. secret bundle 缺失时，明确要求重新登记／重新固定，不假装身份恢复。
5. 证书过期或主机名变化时，用同一 CA 签发新 leaf；单证书方案需重新固定。

### 8.5 所有权转移

1. 第二客户端申请只读或转移。
2. 所有者确认转移；Server 递增 `ownershipEpoch`，签发新 fencing token。
3. 旧客户端写入被拒绝；新客户端拉取最新修订后继续。
4. 恢复或换机走同一流程，不共享旧令牌。

## 9. 验收场景

1. **五文件归档。** A.RAW 排除、A.JPG 纳入、B.RAW 仅序列、C.RAW 必要帧排除、D.RAW 失败；S3 对象和归档引用恰为 A.JPG、B.RAW；C 组提示缺帧；D 保留失败记录；恢复 A.RAW 只增一份引用。
2. **Direct／Relay。** Direct 中断网或 RustFS 不可达，自动 Relay 缺失 part；最终 SHA-256 与清单一致；重复提交不产生第二个对象；Direct 已完成 part 不被重传。
3. **元数据备份恢复。** 全量备份恢复到空 PostgreSQL；`metadata doctor` 通过；库、所有权、令牌哈希、操作、对象引用、快照和配额完整；S3 缺失对象逐项列出。
4. **备份验证。** 损坏 dump、清单校验和不符、对象 key 不符、跨库引用、操作缺口、配额不一致均被拒绝；未验证备份不能用于恢复。
5. **证书／令牌。** 同一 CA／密钥恢复后客户端无需重新固定；错误指纹、过期证书、撤销令牌、错误令牌被拒；secret bundle 缺失时明确要求重新登记。
6. **单客户端所有权。** 第二客户端不能写；转移后旧客户端被 fencing 拒绝；新客户端获得新 epoch；离线操作补交去重。
7. **冷热与释放。** 冷片代理切完整 RAW。中断续传。最终哈希一致。已固定、未校验、冷备保护不足、有未同步改动或唯一副本阻止释放。
8. **对象缺失／重绑定。** S3 对象缺失时状态为 `missing`；从冷备恢复后重新校验转 `available`；换 bucket／endpoint 后重绑定并重新 HEAD。
9. **过期。** 垃圾桶、草稿、墓碑、暂存和备份代次按策略过期；`objects/` 不被 S3 生命周期自动删除；最后已验证元数据备份不被自动删除。
10. **规模。** 10TB 级库、约 20 万对象、10GbE + jumbo frame 记录首传、增量、恢复、`pg_dump`、`metadata doctor` 和 S3 HEAD 时长；未测 100TB 不标通过。
11. **安全。** 自签名证书固定、私钥备份加密、备份静态加密、日志不含令牌／密钥、公开暴露需 TLS 和显式配置。
12. **版本。** 未知 gRPC／proto／schema／备份格式拒绝写入；旧客户端只读或安全退出；升级前备份可回退。
13. **037／038／039 资源。** 保存并恢复含 `sceneGraph`、输出状态、模型前缀的场景版本；HDR AVIF 10 位 PQ 与 SDR JPEG/PNG16 成片分别登记；旧 SDR 兼容配方不被静默迁移；场景模板与批量候选身份可追溯；Server 不执行交互编辑，批处理按 041 验收。

14. **Server 接入。** 验证建库、已有库快照、显式接续和独立拷贝的绑定隔离。[接入验证](validation.md#server-资料库接入走查)

## 10. 成功标准

- **归档正确。** 有效纳入与 S3 归档引用逐文件一致；排除项零引用；对象 SHA-256 可核对。
- **Direct／Relay 可靠。** 两种路径结果一致；中断续传不重复；Relay 不依赖本地大磁盘。
- **元数据可恢复。** 全量备份能恢复到空 PostgreSQL；`metadata doctor`、对象清单、客户端重连均通过；缺项明确。
- **身份可恢复。** 证书、令牌哈希、私钥／pepper 的备份边界清楚；同 CA 恢复后客户端无需重新固定；secret 缺失时安全失败。
- **单写者安全。** 第二客户端不能写；转移有 fencing；服务器恢复后旧 epoch 不能倒带。
- **可控释放。** 仅允许释放未固定、已校验、满足冷备保护、已同步且有其他副本的本机受管文件。
- **存储可靠性外置。** 不把 S3/ZFS 复制、RAID、纠删码算作 RAWMaster 功能；但逻辑备份和恢复必须通过。
- **新资源可追溯。** 场景图、输出状态、模型前缀、模板、批量候选和 HDR／SDR 交付资源在元数据、对象清单和恢复中都保留身份；旧 SDR 兼容路径不被静默改写。
- **性能基线。** 10GbE／jumbo、10TB 库、Direct／Relay、`pg_dump`、恢复和 S3 HEAD 在固定环境测量后冻结；不以未测数字承诺。

## 11. 假设、非目标与待决

### 假设

- 单用户、多库、一库一客户端；客户端为 Apple Silicon Mac。
- PostgreSQL 和 S3 是外部高可用服务；Server 本地磁盘只放日志、临时文件和有界中转缓冲。
- S3 通过 RustFS（TrueNAS 25.04 App）、MinIO 或云 S3 提供；Direct 默认，Relay 回退。
- 存储可靠性、RAID、纠删码、跨站点复制由 TrueNAS／S3 和现有冷备负责。
- 编辑云端见 041；本轮只保留场景图、输出状态、模型前缀、模板和批量候选等身份，不执行交互编辑或场景图批处理。
- 037／038／039 的新场景图、HDR、DAG 和 Rust scene executor 已进入 main；Server 场景图／HDR 批处理仍受 041 的后端与色彩门约束。
