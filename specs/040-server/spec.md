# 040 · RAWMaster Server 1.0

2026-11-26 · **功能设计，待评审；未开始实现。** 本规格把 [033 阶段四](../033-library-lifecycle/server.md)的产品要求展开为可交付的 Server 1.0：先完成全量归档、独立备份、冷热数据和多设备同步，再开放远程 AI／批处理。桌面客户端仍然是完整离线可用的主工作区；Server 是可选的长期保管与协同节点，不是把应用改成联网客户端。

## 1. 结论

1. **先保管，再计算。** Server 1.0 只承诺三件事：每个有资格的原件都能说明是否已归档、是否被独立备份覆盖；冷照片可代理浏览、按需取回原件；多设备离线修改可核对、可合并或显式保留冲突。远程计算在独立验收后开放。
2. **不把“有服务器”变成新的单点。** 客户端继续保存可检索目录并独立完成导入、选片、整理和本地编辑；没有服务器、断网或服务器故障时，已有本地能力不降级。服务器不可用时不能暗示“已搜索全库”或“已备份”。
3. **原片资格不扩张。** 归档清单逐文件取自封存会话的有效纳入及后来的显式恢复纳入；来源扫描、组关系、项目星级、备份扫描和远程作业都不能把最终排除项带入归档。同一内容被多个有效引用时只存一份对象，但每个引用和每个导入来源都保留。
4. **服务器副本与独立备份分开显示。** 主存对象可用、暂存上传、同存储池快照和独立备份各有不同状态。自动释放本地受管副本前必须同时满足：未被固定、服务器原件可回取、独立备份已核验覆盖、没有未同步编辑。
5. **同步是业务操作，不共享活动数据库。** 客户端通过带操作 ID、设备身份、基准修订和载荷版本的命令交换变化；重复提交只生效一次，独立字段可合并，同一人工决定冲突时保留双方来源，配方冲突保留分支。服务器不接收或回传活动 SQLite 文件。
6. **远程作业只运行已验证的可移植引擎。** 作业描述、冻结输入、引擎／模型版本和结果登记与本地共用；服务端缺少引擎、模型或输入时明确禁用并列出缺项。不能把 Mac 专用显影链路的未验证结果称为跨端一致。

## 2. 用户与问题

**目标用户。** 一位摄影师或一个家庭，使用一台主机 Mac 和第二台 Mac（家用或移动），另有外置盘和 NAS。现有资料库已经可以本地导入、初筛、精编、编辑和导出；用户真正缺少的是长期保管与跨设备连续性。首版客户端仍只支持 Mac，不包含 iOS／Web 客户端。

| 当前问题 | Server 1.0 的回答 |
| --- | --- |
| 不知道哪些原片真的在服务器上、哪些只有目录记录 | 逐文件归档状态，来源可追到导入会话与纳入范围 |
| 服务器有了，但不知道是否还有一份独立备份 | 主存、临时上传、同池快照、独立备份分别显示并各自校验 |
| 笔记本空间不足，冷照片打不开 | 常驻目录可检索；冷片用 JPEG 代理浏览，需要时按需取回完整 RAW |
| 换机或服务器损坏后，关系和编辑能不能恢复 | 按代恢复目录快照、引用的原件、编辑资源、成片和来源关系，逐对象核对哈希 |
| 两台设备离线改同一批评分、标签或组 | 操作可离线排队；不同字段合并，同一决定保留冲突供选择，组与配方保留分支 |
| 长任务只能在 Mac 上跑，关机就中断 | 冻结输入的远程作业可排队、查询、取消、重试；断线重连只登记一份结果 |

**不解决的问题。** Server 1.0 不是多人共享图库、团队权限、对外发布、Web 编辑器或云 SaaS。也不把“服务器在线”当成“原片已安全”，更不自动删除用户源文件。

## 3. 交付边界

### 3.1 Server 1.0 必须交付

- 连接、设备登记、证书／身份校验、离线与版本不兼容状态。
- 资料库绑定；一个服务器可保管多个资料库；首版客户端至少支持连接一个服务器和其中的多个库，多服务器连接后置。
- 逐文件归档资格、归档清单、断点上传、内容校验、内容去重和归档引用。
- 同代目录快照＋引用对象＋编辑资源＋成片的独立备份、周期校验、异机恢复。
- 本地目录常驻、JPEG 代理、完整原件按需取回、照片／组／项目离线固定、受控释放。
- 业务操作同步、离线队列、变更拉取、字段合并、冲突记录与显式解决。
- 服务端存储、备份目标、队列、对象校验、设备与日志管理；升级前备份和版本拒绝。
- 仅在引擎、模型、输入和许可都具备时开放远程作业；否则明确本地执行或禁用。

### 3.2 Server 1.0 明确不做

- 团队／多租户权限、共享编辑、评论、发布和 Web 客户端。
- 跨服务器主动复制、全球 CDN、对象存储多区域编排。
- 自动删除用户源文件、自动格式化存储卡、把排除项“顺手”归档。
- 未验证引擎的跨端像素一致性、未授权模型上传、第三方云中转。
- 100 TB／200 万文件的容量验收。Server 1.0 先以现有资料库和受控放大样本验证，容量专项另立。
- 全自动冲突裁决。冲突必须可见、可追溯，不能按到达时间静默覆盖人工决定。

### 3.3 与 033 的关系

033 定义资料库生命周期与逐文件归档资格；本规格只把阶段四展开成 Server 1.0 的功能、状态、协议和交付顺序。若两份文档冲突，以 033 的归档资格与验收场景为准；本规格新增的能力必须回写并接受 033 的跨功能对账样本。

## 4. 交付阶段

| 阶段 | 范围 | 可独立验收的结果 |
| --- | --- | --- |
| S1 · 连接与服务器目录 | 安装、初始化、TLS、设备登记、资料库绑定、服务端目录与操作日志、健康检查 | 新服务器可被一台 Mac 连接；错误指纹／过期登记码被拒绝；服务器离线不影响本地资料库 |
| S2 · 归档、备份与恢复 | 逐文件归档清单、断点上传、内容校验、去重、独立备份、异机恢复 | 五文件样本归档清单精确；中断续传不重复；独立备份恢复到新机后逐对象哈希一致 |
| S3 · 冷热与同步 | 代理、固定离线、按需取回、缓存释放、操作同步、冲突解决 | 冷片从代理切到完整 RAW；断网修改后重连不丢决定；同字段冲突可见并可选 |
| S4 · 远程作业 | 能力登记、输入解析、排队、进度、取消、重试、结果登记 | 同一作业断线重试只登记一份结果；缺引擎／模型／输入时明确禁用；旧结果不覆盖当前版本 |
| S5 · 容量与运维 | 百万级目录、100 TB 参照、监控、保留策略、升级与演练 | 容量测量、故障矩阵和恢复演练通过；不以未测规模宣称达标 |

**发布口径。** Server 1.0 = S1 + S2 + S3；S4 作为 1.1；S5 是独立容量与运维专项。任何阶段都不得用“接口已定义”替代真实服务器、真实网络和真实对象校验。

## 5. 用户故事

### US1 · 确认哪些原片真的被保管（P0）

摄影师完成一次导入并关闭会话，打开 Server 面板，看到本次纳入的原片、已排除项和待补项。开始归档后可以关闭窗口；稍后回来看到每张照片的服务器副本与独立备份状态。若某张原片丢失，界面说明它是否曾取得归档资格、现在缺什么、可以从哪里找回。

**独立验收。** 用 033 的五文件样本执行归档、备份、恢复，逐对象核对清单、引用和哈希；仅含排除项的另一批产生零条原件归档引用，导入历史仍可还原。

### US2 · 在笔记本上浏览冷照片并取回原件（P0）

摄影师在只有代理的笔记本上筛选、比较和标记冷照片；需要 1:1 检查或本地 RAW 处理时，明确取回完整原件并看到进度、校验和可用级别。也可以把某张照片、某个组或某个项目固定为离线可用。

**独立验收。** 断开服务器后仍能看代理和本地已缓存原件；取回中断后继续，最终哈希与归档清单一致；未固定、未备份完成的本地副本不能被自动释放。

### US3 · 换机或服务器故障后恢复（P0）

摄影师从独立备份恢复到一台新机器，先看到恢复范围和不完整项，再打开资料库核对原件、组顺序、人工标签、历史外观、编辑依赖和派生成片。

**独立验收。** 主存一份对象损坏，使用独立备份恢复到另一台机器；逐对象校验通过，缺失项明确列出；仅排除记录不伪装成可恢复原件。

### US4 · 两台设备离线修改后重连（P0）

摄影师在 Mac A 修改评分和标签，在 Mac B 修改组顺序和编辑配方。两台设备离线工作后重连，独立字段合并，同一评分冲突保留双方来源，组和配方保留分支，任何一方都没有静默丢失。

**独立验收。** 覆盖不同字段、同字段、组成员、配方、删除意图和迟到分析结果的故障矩阵；重复发送、乱序、超时重试均只产生一次有效结果。

### US5 · 把长任务交给服务器（P1）

摄影师选择一组已归档原片，提交一个冻结输入、配方、引擎和模型版本的作业。提交前看到执行位置、需要补传的输入和缺失能力；运行中可以取消、重试或关闭客户端，稍后按作业身份核对结果。

**独立验收。** 回报前断网、修改组并重试原请求，只产生一个绑定原输入的结果；取消或失败的未发布暂存产物可清理；旧结果不被当前版本自动采用。

## 6. 功能要求

### 6.1 连接、身份与设备

- **SRV-R01 · 服务器身份。** 首次连接必须显示服务器地址、版本和 TLS 证书指纹；用户确认指纹后才保存。指纹变化、证书过期或不支持的 API 版本必须阻止写入并说明原因。
- **SRV-R02 · 设备登记。** 使用一次性登记码把设备绑定到服务器；服务器签发按设备区分的长期令牌，令牌只存 macOS 钥匙串。撤销设备后，该设备只能读取本地数据，不能继续同步或上传。
- **SRV-R03 · 单用户、多设备。** 首版只有一个所有者角色；所有已登记设备默认可访问该所有者的资料库。团队角色、访客和细粒度权限不在首版。
- **SRV-R04 · 离线优先。** 连接失败不得阻塞本地打开、导入、选片、整理或已有编辑。界面必须区分“本地可用”“需要服务器”“服务器状态未知”。
- **SRV-R05 · 资料库绑定。** 客户端把已有 `libraryID` 绑定到服务器；服务器不得改写本地业务身份。重复绑定同一库幂等；不同库使用同一 ID 或同一库出现不同来源时拒绝并报告。
- **SRV-R06 · 多库。** 一个服务器可保管多个资料库；客户端可按库查看归档、备份和同步状态。跨库检索在客户端完成或显式请求，不能把未同步库当作已搜索。

### 6.2 归档资格与清单

- **SRV-R07 · 资格来源。** 服务端只接受由封存会话的有效纳入、明确仅序列纳入或后来的显式恢复纳入产生的逐文件归档引用。来源目录遍历、项目星级、组关系、缓存扫描和远程作业都不能新增资格。
- **SRV-R08 · 排除项。** 最终导入排除的原件只同步来源、已有内容身份、处置和历史关系；不创建原件引用，不进入独立备份，不因配对、缺帧提示或组引用被带入。后来显式恢复并核验可读原件后，才追加新的归档引用。
- **SRV-R09 · 归档清单。** 每次归档计划列出资料库、项目、会话、文件、逻辑拍摄、内容哈希、字节数、文件名、角色、纳入依据和缺项。清单可按会话、项目或全库生成，但逐文件结果必须一致；同一命令重复执行返回同一收据。
- **SRV-R10 · 内容去重。** 以 `sha256 + byte_count` 作为内容身份。相同内容只保存一个对象，可有多个文件、会话、项目和恢复来源引用；删除一个引用不得删除仍被其他有效引用或备份代次使用的对象。
- **SRV-R11 · 待找回。** 已有归档资格但当前没有可校验原件时，状态为“待找回”，列出现有来源、查找入口和可恢复范围；不能用旧哈希或代理冒充完整原件。
- **SRV-R12 · 历史范围。** 初筛完成前的失败项、未核验项和封存后未恢复的排除项不进入全量归档；导入历史仍可读取其来源与处置。

### 6.3 传输、校验与主存

- **SRV-R13 · 断点传输。** 大文件分块上传，记录已接收区间；断网、退出或服务器重启后可继续。未完成上传只能存在于隔离暂存区，不能出现在归档清单或备份代次中。
- **SRV-R14 · 校验后再登记。** 服务端收到完整长度后重新计算 SHA-256；只有长度、哈希、可读性和引用全部匹配才登记“服务器原件可用”。校验失败保留失败原因和可重试状态，不产生半成品对象。
- **SRV-R15 · 幂等。** 同一上传／归档命令重复提交只登记一次；同 ID 不同内容返回冲突。服务端已持有同一内容时可跳过字节传输，但仍核对声明的内容身份和引用。
- **SRV-R16 · 主存状态。** 主存对象、暂存上传、同存储池快照、独立备份和客户端本地副本分别记录；界面不得把任一状态概括为“已同步”或“已备份”。

### 6.4 独立备份与恢复

- **SRV-R17 · 同代清单。** 每代备份包含同一时点的目录快照、归档原件、机内 JPEG、编辑配方及必要资源、成片和来源关系；代理、缩略图和可重建索引可不入备份，但必须能从原件重建。
- **SRV-R18 · 独立故障域。** 独立备份目标不能与主存共用同一块盘、同一存储池或同一 NAS 快照。只复制到同池目录、只做 RAID 或只做同机快照，都不能标记“独立备份已覆盖”。
- **SRV-R19 · 校验与周期检查。** 备份完成后逐对象校验并记录代次收据；周期检查报告缺失、损坏、不可读和引用不一致的具体对象。修复只补缺项，不重写已核验对象。
- **SRV-R20 · 异机恢复。** 恢复先列出代次范围、目录版本、对象数量、缺项和所需空间；先恢复目录与关系，再按哈希核验对象。部分成功可续跑，只有实际可读且校验通过的内容才计入恢复结果。
- **SRV-R21 · 恢复后的身份。** 恢复到新服务器或新设备时生成新的设备身份和访问令牌，不复用旧令牌；资料库业务身份保持不变。恢复完成后旧设备令牌可按需撤销。
- **SRV-R22 · 保留与回收。** 默认不自动删除唯一原件或唯一备份代次。回收只作用于无任何有效引用、未被保留代次引用且超过保留期的对象；删除意图与回收期限可审计。

### 6.5 冷热数据、代理与离线固定

- **SRV-R23 · 常驻目录。** 客户端本地目录持续保存可检索元数据、关系、人工决定和编辑版本；服务器离线时仍可浏览已缓存范围，并明确标注未覆盖范围。
- **SRV-R24 · 代理。** 冷照片使用 JPEG 代理浏览，代理与机内 JPEG 分别标记来源、尺寸和生成版本；代理不进入原件归档清单，也不冒充 RAW 细节或最终输出。
- **SRV-R25 · 按需取回。** 用户请求 1:1 检查、全质量导出或本地 RAW 处理时，客户端先取回并校验需要的完整原件；支持断点、取消、重试和哈希核对。
- **SRV-R26 · 离线固定。** 可按照片、组或项目固定离线级别；固定后不得被缓存回收。固定状态属于设备，不上传为共享业务事实；服务器可接收预取意图以优化带宽。
- **SRV-R27 · 受控释放。** 自动释放只适用于应用托管、未固定、服务器原件可回取、独立备份已核验覆盖、没有未同步编辑的本地副本。引用盘、唯一副本、未上传内容和用户明确固定的内容不进入回收。
- **SRV-R28 · 可用级别。** 界面至少区分：仅目录可查、代理可看、原件已缓存、需联网取回、取回中、已固定、可释放、释放受阻。不能用单一“离线可用”覆盖不同能力。

### 6.6 多设备同步与冲突

- **SRV-R29 · 操作交换。** 客户端以操作 ID、设备 ID、资料库 ID、实体、基准修订、载荷版本、动作和载荷提交变化；服务器按资料库分配单调服务器修订并返回收据。客户端不共享活动数据库文件。
- **SRV-R30 · 离线队列。** 客户端持久保存待发送操作；断网、重启、超时和乱序后可按原操作 ID 重放。服务器按操作 ID 去重；同 ID 不同载荷拒绝。
- **SRV-R31 · 变更拉取。** 客户端凭游标增量拉取已应用操作、冲突和解决结果；重复或回声操作不得再次生成上传。新设备可先取分页快照，再按游标追平。
- **SRV-R32 · 字段合并。** 不同字段的修改可合并；同一人工决定字段的并发修改保留双方值与来源，等待显式选择，不按到达时间覆盖。
- **SRV-R33 · 组与配方。** 组成员、顺序、参与和编辑配方按版本保存；并发修改产生分支，不静默丢帧或覆盖版本。采用哪个版本由用户明确操作。
- **SRV-R34 · 删除与恢复。** 删除是带版本和来源的意图，不因同步冲突自动触发物理删除；一端排除、另一端恢复时保留冲突或人工选择，原件副本与业务决定分开处理。
- **SRV-R35 · 迟到机器结果。** 分析、AI 或远程作业结果绑定提交时的输入版本；输入已变时保留为过期结果，不覆盖当前人工决定或当前采用版本。
- **SRV-R36 · 设备私有状态。** 本机路径、卷挂载、窗口位置、缓存状态、离线固定和预览偏好不进入共享业务同步；必要时按设备单独登记。

### 6.7 远程计算

- **SRV-R37 · 同一作业描述。** 本地与远端共用操作 ID、资料库、项目、按序输入、内容版本、配方、引擎／模型、输出类型和所需能力。提交前显示执行位置和需补传输入。
- **SRV-R38 · 能力匹配。** 服务端按 CPU、GPU、内存、存储、引擎、模型和许可登记执行能力；缺少依赖时列出缺项并禁用，不能静默换引擎或降级画质后仍宣称同一结果。
- **SRV-R39 · 冻结输入。** 作业开始时冻结组修订、成员顺序、文件内容版本、替代 JPEG 或缺帧处置；输入离线、未归档或版本变化时逐项报告。
- **SRV-R40 · 队列与生命周期。** 作业可排队、查看进度、取消、重试；客户端失联后按原作业 ID 查询。取消或失败的未发布暂存产物可清理，不产生作品版本。
- **SRV-R41 · 输出发布。** 输出先私有暂存并校验长度、摘要和可读性，再以作业 ID 唯一约束登记派生照片／视频、作品版本和全部来源关系；重复回调只产生一次有效登记。
- **SRV-R42 · 版本不覆盖。** 作业完成期间发生重排、换配方或用户采用另一版本时，旧结果可回看但不自动成为当前版本；当前版本由显式采用决定。

### 6.8 运维、安全与兼容

- **SRV-R43 · 访问保护。** 远程访问使用 TLS；登记令牌、备份目标凭据和云服务密钥不进入普通日志、导出包或错误回显。默认只监听局域网，公开暴露需显式配置并提示风险。
- **SRV-R44 · 可观察性。** 提供健康、存储容量、归档／备份覆盖率、同步队列、冲突数、作业队列和最近错误；日志带请求／操作 ID，便于对账但不泄露内容。
- **SRV-R45 · 升级与回退。** 服务端与客户端分别携带 API、载荷、目录 schema、索引、引擎和模型版本。未知写版本拒绝修改；升级前生成一致备份；回退只能在使用已验证的回放或导出保留新操作时进行。
- **SRV-R46 · 灾备演练。** 提供可重复的恢复演练入口：从独立备份恢复到隔离机器，核对对象、目录、人工决定、组顺序、编辑依赖和成片来源；演练结果可作为发布证据。

## 7. 客户端入口与状态词汇

完整交互见 [ux.md](ux.md)。首版固定三个入口：

1. **设置 → Server。** 连接地址、证书指纹、设备登记、资料库绑定、归档策略、备份目标和诊断。
2. **资料库工具 → Server。** 归档覆盖率、独立备份、冷热缓存、冲突、作业和恢复入口。
3. **照片／组／项目上下文。** 查看归档状态、固定离线、取回原件、释放本地副本；不把服务器动作塞进编辑参数面板。

状态必须成组显示，不能用“已同步”同时表示目录、原片、备份和作业。最低词汇：

| 维度 | 状态 |
| --- | --- |
| 连接 | 未配置、连接中、在线、离线、需重新认证、版本不兼容、降级 |
| 归档 | 未取得资格、待传输、传输中、校验中、服务器原件可用、独立备份已覆盖、待找回、缺失或损坏、仅保留历史 |
| 本地可用 | 仅目录、代理可看、原件已缓存、取回中、已固定、可释放、已释放、释放受阻 |
| 同步 | 已同步、待同步、同步中、有冲突、暂停、失败 |
| 作业 | 草稿、缺输入、排队、运行、等待、已暂存、已登记、失败、已取消、待核对 |

## 8. 关键流程

### 8.1 首次连接

设置 → Server → 输入地址 → 显示证书指纹和服务器版本 → 输入一次性登记码 → 选择设备名 → 选择要绑定的资料库 → 测试上传／下载 → 完成。任何一步失败都停留在当前表单，保留已填内容；未确认指纹前不得发送资料库内容。绑定后先显示“只同步目录”状态，归档与备份必须由用户明确开启或确认计划。

### 8.2 归档

会话封存后，客户端按逐文件处置生成候选清单；Server 面板显示纳入、明确仅序列、排除、失败和待找回数量。用户确认后开始传输；服务端暂存、校验、登记引用。客户端可关闭窗口，稍后从同一清单继续。主存完成后仍显示“独立备份未覆盖”，直到备份代次校验通过。

### 8.3 冷片取回

冷照片先显示代理和“需联网取回”。用户请求 1:1 或本地 RAW 处理时，客户端取回完整原件并校验；可取消、重试、固定。释放本地副本前核对固定状态、服务器可回取、独立备份覆盖和未同步编辑；任何一项不满足都显示原因而不是灰掉按钮。

### 8.4 离线同步

客户端离线时继续写入本地目录，并把可同步操作放入持久队列。重连后按顺序推送；服务器返回收据、服务器修订和冲突。独立字段直接合并；同一决定冲突进入“待解决”，组／配方冲突保留分支。客户端拉取远端变化后更新本地，但不重复上传自己的操作。

### 8.5 远程作业

用户选择组或照片 → 制作 → 选择执行位置 → 查看冻结输入、需补传文件和能力 → 提交。客户端可关闭；重新打开时按作业 ID 查询。结果先暂存、预览、校验，再由用户采用或登记为派生作品；旧结果不自动替换当前版本。

### 8.6 异机恢复

从备份代次选择恢复 → 预览目录、对象、资源和缺项 → 选择新服务器／新设备位置 → 恢复目录与关系 → 批量校验对象 → 打开资料库核对 → 列出仍缺失或需重连的内容。恢复完成前不显示“完整恢复”。

## 9. 验收场景

1. **五文件归档对账。** A.RAW 排除、A.JPG 纳入，B.RAW 仅序列纳入，C.RAW 是必要帧但排除，D.RAW 核验失败。归档及独立备份清单恰有 A.JPG、B.RAW；C 所在组提示缺帧；D 保留失败记录。重启或重试结果相同。后来从可读来源恢复 A.RAW，只增加这一份归档引用。把配对两成员处置互换，按同一规则复测。
2. **全排除批次。** 仅含最终排除项的批次产生零条原件归档引用，导入历史、来源和处置仍可恢复；组、备份扫描或远程作业不能把原件带入归档。
3. **断点上传。** 大文件传输中断网、退出客户端、重启服务器；继续后只完成缺块，最终哈希与清单一致；重复提交同一上传不产生第二个对象或第二条归档引用。注入哈希不符、长度不符、磁盘满和权限错误，均不得登记完整。
4. **独立备份门槛。** 主存完成但独立备份未验证时，尝试释放本地受管副本必须被阻止并说明原因；完成独立备份后重试成功；固定原件、引用盘和未同步编辑始终不被释放。
5. **冷片切换。** 冷片从代理切到完整 RAW，下载中断后继续；最终哈希与归档清单一致。服务器离线时显示代理可看、原件需联网，不把代理标成 RAW 可用。
6. **双设备合并。** 两台设备离线修改不同字段后重连，字段合并；同一评分冲突保留双方值和设备来源，用户选择后产生新修订；组顺序和编辑配方冲突保留分支，不丢帧、不覆盖版本。
7. **重复与乱序。** 同一操作重复发送、超时重试、乱序到达和重连后重放，都只产生一次有效结果；回声操作不再次上传；未知载荷版本拒绝写入。
8. **远程作业重连。** 作业提交后断网，修改组并重试原请求；只产生一个绑定原输入的结果。取消、失败、服务器重启和迟到回调分别可清理或标记过期，不自动采用。
9. **异机恢复。** 主存一份对象损坏，从独立备份恢复到另一台机器；核对原件、组顺序、人工标签、历史外观、编辑依赖和派生成片，逐对象哈希一致。用没有备份原件的排除记录走历史恢复，如实显示需要可校验来源。
10. **安全与版本。** 错误指纹、过期登记码、撤销设备、错误令牌和重放请求被拒绝；日志不含令牌或备份凭据。旧客户端遇到更高写版本进入只读或安全退出，不写入未知 schema。
11. **多库与去重。** 同一内容在两个库、两个项目或两个文件角色中出现时只存一个对象但保留全部引用；删除一个引用不删除仍被使用的对象。跨库查询明确显示哪些库已同步、哪些仅本地可查。
12. **容量记录。** 用现有资料库和受控放大的目录记录文件数、拍摄数、关系数、版本数、元数据查询时延、归档吞吐、恢复时长和存储占用；未测的 100 TB／200 万文件不标为通过。

## 10. 成功标准

- **正确性优先。** 归档清单与有效纳入逐文件一致；排除项归档引用为零；恢复对象哈希 100% 核对；没有“显示成功但对象不可读”。
- **不丢操作。** 同步故障矩阵中无静默丢失；重复、乱序、超时和重连结果可解释；同一人工决定冲突可见。
- **不误释放。** 未固定、未备份覆盖、未同步或有唯一副本的本地内容不被自动回收；释放前可解释。
- **单一结果。** 同一作业重试只登记一个结果；旧结果不自动覆盖当前版本；取消和失败可清理。
- **可恢复。** 从独立备份恢复到隔离机器后，目录、关系、决定、编辑依赖和成片来源可核对；缺项明确。
- **可运维。** 升级前有备份，未知版本拒绝写入，健康与容量可观察，日志不含秘密。
- **性能基线。** 归档吞吐、冷片首屏、取回时延、同步批次和作业排队在固定硬件、网络和样本上测量后冻结；不以未测数字承诺。Server 1.0 不把 100 TB 压测作为前置，但数据模型和分页不得假设全库常驻内存。

## 11. 假设、非目标与待决

### 假设

- 单用户、多设备、自托管；服务器为 Linux x86_64，客户端为 Apple Silicon Mac。
- 客户端保留完整本地目录和离线工作能力；服务器不是每次打开应用的必需条件。
- 服务器只保管有归档资格的原件、必要资源和成片；用户源文件仍由用户管理。
- 备份目标与主存独立；独立备份的部署形式和频率在实施时确定。
- 远程计算只在可移植引擎、模型和输入都通过独立验收后开放。

### 待决

| 编号 | 问题 | 当前建议 | 决策时点 |
| --- | --- | --- | --- |
| D-SRV-01 | 服务端目录引擎 | V1 每库 SQLite（复用目录内核、单写队列、快照简单）；并发或规模测量不足时迁移 PostgreSQL，API 不暴露引擎 | S1 冻结前 |
| D-SRV-02 | 独立备份实现 | 产品契约固定为“同代清单＋逐对象校验”；实现可在原生代次复制、restic／borg、ZFS send 间选择 | S2 计划前 |
| D-SRV-03 | 代理规格 | 先定长边 2048／2560、sRGB JPEG、质量与生成位置；用真实冷片测首屏和带宽后再冻结 | S3 计划前 |
| D-SRV-04 | 认证方式 | V1 使用 TLS＋一次性登记码＋按设备令牌＋指纹确认；mTLS 作为可选增强 | S1 冻结前 |
| D-SRV-05 | 冲突矩阵 | 先按本文第 6.6 节冻结字段级规则，再补 UI 与测试夹具；不做通用 CRDT | S3 计划前 |
| D-SRV-06 | 远程作业类型 | 只开放 Linux 可运行且已验证的引擎；Mac 专用 Metal 链路默认本地执行 | S4 计划前 |
| D-SRV-07 | 保留与回收 | V1 默认不自动删除；保留代次数、回收期限和删除意图需用户确认 | S2 计划前 |
| D-SRV-08 | 服务器管理界面 | V1 用配置文件＋CLI＋原生客户端设置；独立 Web 管理台不作为前置 | S1 冻结前 |
| D-SRV-09 | 静态加密 | V1 先依赖磁盘／卷加密和传输 TLS；应用层静态加密另立专项 | S5 前 |
